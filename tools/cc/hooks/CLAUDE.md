# tools/cc/hooks/

**Doing:** Claude Code hook scripts. Each script handles one event (PreToolUse, PostToolUse, SessionStart, etc.) and returns via the channel-XOR protocol.
**Don't break:** Zero `espalier` imports — hooks run standalone. Exit codes follow channel-XOR (0 + JSON OR 2 + stderr, never both). Path comparisons use `.replace("\\", "/")` for Windows. Derive shared constants and helpers from their `_hook_utils` single owners (`SOURCE_LANGUAGE_EXTENSIONS` and `PROJECT_MANIFEST_NAMES` are themselves projections of `tools/cc/_stack_table.py`, read behind a guarded import with a pinned copy; a stack is taught there, never in a hook), (`SOURCE_LANGUAGE_EXTENSIONS`, `EXEMPT_UNIVERSAL_PREFIXES`, `MCP_WRITE_VERB_SUBSTRINGS`, `PROJECT_MANIFEST_NAMES`, `has_active_plan`, and since 2026-09-30 `say_once`, `say_bad_stdin`, `read_toml_string_list` / `read_toml_table`, `adopter_protected_prefixes` / `protected_prefixes`, `split_command` / `resolve_program` / `spawn_checked`) — don't re-inline; the concept-overlap probe flags divergent copies. **Fail-open stays allowed below a blocking hook's umbrella; silent fail-open does not:** a new `except` that returns or assigns a falsy default must speak where it is seen (`say_once` in a blocking hook; `_hook_utils.advise` in a reporter that renders it into its one JSON object, or `say_once` where the event has no channel to Claude) or carry `# fail-open: ok <kind> <reason>`, because an exit-0 hook's stderr reaches the debug log only -- a bare `warn`, stderr print or stderr write pairs with a seen speaker in its block or carries `# voice: <kind> <reason>`; a new spawn routes through `spawn_checked` (a gate) or carries `# spawn: ok <reason>` (a reporter). `tests/test_failopen_voice.py` and `tests/test_spawn_chokepoint.py` derive both populations and are the gates (docs/CONVENTIONS.md "Fail-open with voice"). The `hook-authoring` skill is the source of truth for the authoring contract; `memory/hook-authoring.md` (read first, below) carries the accumulated patterns and gotchas.

## Before writing or editing in this folder:

1. Read [`memory/hook-authoring.md`](../../../memory/hook-authoring.md) — accumulated hook patterns and gotchas.
2. Confirm `docs/external/cc-hook-protocol.md` reflects the current Claude Code hook protocol (pinned external truth).
3. A new hook/detector WILL self-collide (deny-token data in a non-`_` hook, line-pins, state files) — run the sweep in `docs/SHARP_EDGES.md` "A new pattern-detector trips the harness's own defenses".
4. After edits, run `pytest tests/test_hooks.py tests/test_hook_protocol.py tests/test_failopen_voice.py tests/test_spawn_chokepoint.py` before any commit.
