| `DEF-4074` | tools/cc/mail.py::main (the send verb takes a non-ack whose text opens with the fix-forward head) | **`tools/cc/mail.py` sends a note, request, claim, release or assign whose text opens with the fix-forward head `gridlock: fix forward run <id>`, which only an ack can carry, so a ruling sent as the wrong type lands on the channel and rules nothing.** `RULING_HEAD` has one reader, `fix_forward_rulings` and `fix_forward_ruling`, over the dispatcher's acks alone: `ship.py open --base-red-ruled <id>` refuses a note by name (the id is no ack, or the ack does not open with the head) and the board's base line prints the revert. The send verb checks the text's length (`MAX_TEXT`), the guard's secret-path patterns and, for an assign, its shape, and nothing else: `send --type note --text "gridlock: fix forward run 1" --dry-run` printed the line it would send and exited 0 (driven 2026-10-31). #384's body left the send-time refusal to the dispatcher to rank, since it changes the driver's behaviour and needs its own oracle; until then the brief alone tells the dispatcher a fix-forward ruling is always an ack. Who is hurt: the held seat on a red `main`, which waits on a ruling the board never prints while the dispatcher reads its note as sent (every seat was held eleven hours on 2026-10-29 before a hand-opened pull request landed the fix, the case the head was built for); and the dispatcher, told nothing at the send. Fix shape: the send verb refuses a non-ack whose text opens with `RULING_HEAD`, naming the shape it should take (`--type ack --ack <the held seat's last message>`), on the live send and on `--dry-run` alike, pinned by a test over the five non-ack types and the ack that passes; a plain `gridlock:` note stays allowed (a ruling no request waits on).
