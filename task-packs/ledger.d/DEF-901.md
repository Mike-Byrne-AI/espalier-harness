| `DEF-901` | espalier/cli.py::_opening_paragraph (the fallback `::_build_asset_tables` renders into the CLAUDE.md Command table); espalier/render_surface.py::_skip_non_prose_block (via `::_read_body_description`, the same job for `cc/COMMANDS.md`); missing gate: no test compares the two readers on one fixture set | **The two readers that turn one command file into a Purpose cell disagree on three of four non-prose leaders, and the generated CLAUDE.md table takes the leaky one.** `espalier/cli.py::_opening_paragraph` -- the fallback `::_build_asset_tables` uses for a command with no frontmatter `description:` -- skips a leading markdown heading and nothing else, while `espalier/render_surface.py::_read_body_description` skips headings, blockquotes, HTML comments and fenced code blocks through `::_skip_non_prose_block` for the same job. Driven at HEAD on three synthetic bodies: the cli reader emits the blockquote line, the `<!-- espalier:managed -->` marker and the fence as the Purpose, where render_surface returns the prose; the two agree on all 17 packaged commands, so nothing is visibly broken today and the defect is trigger-gated (docs/FAILURE_MODES.md section 13.12). Who is hurt: the adopter reading a generated CLAUDE.md whose Purpose cell is a comment marker or a fence instead of a summary, on the day a maintainer authors a `.claude/commands/*.md` body opening that way and mirrors it; `cc/COMMANDS.md` shows the clean summary for the same command, nothing reds, and `_opening_paragraph`'s docstring records that they "drifted once, silently". Fix shape: have `_opening_paragraph` call `render_surface::_skip_non_prose_block` instead of its own leading-`#` test, and add the parametrized shared-fixture test (blockquote-, comment- and fence-leading bodies) that pins the two readers together. The probe keys on `_opening_paragraph`'s own leader vocabulary and on a call to the shared skipper under either spelling, so a fix that adds only the test, or that strips the leader further down the call chain, keeps the measured value and re-pins the row.
