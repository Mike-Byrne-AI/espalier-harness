| `DEF-2003` | tools/cc/hooks/session_start.py::_run_main (the catch-up, ::_sync_checkout, runs after the module-level sibling imports and before ::_load_mail loads tools/cc/mail.py by path); tools/cc/mail.py (imports record_merge, which takes run_bounded from _json_safe) | **A SessionStart that catches the checkout up across a commit changing a shared `tools/cc` helper runs its later blocks with that helper's old copy already imported, so a module it then loads by path from the moved tree can fail to import: the banner loses its `Mail:` line for that start, under a WARN that reads like a broken install.** `tools/cc/hooks/session_start.py` imports its siblings at module load (`_hook_utils`, `_json_safe` and the rest, the pre-catch-up bytes). `::_run_main` then runs the catch-up (`::_sync_checkout`, which moves `main` with `git switch -C`), and only after it builds the seat and mail lines, which load `tools/cc/mail.py` by path through `::_load_mail`, from the tree as it now is. Seen once on the Windows seat `win`, 2026-10-13 22:27Z: the start fast-forwarded `main` eight commits across #206, which added `run_bounded` to `tools/cc/_json_safe.py`. `mail.py` imports `record_merge`, whose new copy asks `_json_safe` for `run_bounded`, and `_json_safe` resolved to the old module already in `sys.modules`, so the banner printed `mail scan failed: ImportError: cannot import name 'run_bounded' from '_json_safe'`. A fresh process minutes later read every message (126). The import chain is read from the code (`session_start.py` line 49 imports `_json_safe`; `_sync_checkout` is called before `_mail_line` in `_run_main`; `mail.py` imports `record_merge`, which imports `run_bounded`); the failure was seen once and not driven. Any other block that loads a module by path after the catch-up has the same exposure (not enumerated). It heals at the next start. Who is hurt: the operator of any seat with the catch-up on whose start crosses a commit that adds a name to a helper several `tools/cc` modules share: that start's banner drops the unread-mail headlines, and the WARN names an ImportError, which reads as a broken install rather than a one-start ordering artefact. Fix shape (a shape, untested): run the catch-up before the hook imports anything the catch-up can move (in its own process, or as the hook's first act), or, when the catch-up moved `tools/cc/`, skip the by-path loads and say why on the `Checkout:` line instead of a WARN.
