| `DEF-3042` | tools/cc/hooks/_bash_patterns.py::iter_removed_or_relocated_operands (a dash word then a slashed wrapper name, repeated, read in quadratic time) | **A Bash command that repeats a dash word followed by a slashed path ending in a wrapper's name (`-exec /a/env`, `-path */bin/env`, `ls -l /a/env`, `gcc -I /usr/include/sudo`) is read in time quadratic in its length by the zone tier's removed-or-relocated reader, so a few kilobytes of it hold a harmless command for seconds, and by 8 KB the reader alone outruns the guard's judgment budget, which then refuses it.** `tools/cc/hooks/_bash_patterns.py::iter_removed_or_relocated_operands` runs every mutation arm on every Bash call. Measured 2026-11-07 here (Python 3.11, main at 8dd10c0, the walker's caches cleared before each call, the faster of two): `find build` then `-exec /a/env` repeated reads 372 ms at 2 KB and 1507 ms at 4 KB (ratio 4.05), and the ratio holds at 3.9 to 4.4 for `-name /a/env`, `-name /env`, `-name a/env`, `-name /a/bin/env`, `-o /a/env`, `-path */bin/env`, `-o -path ./bin/env`, `echo -x /a/env`, `ls -l /a/env`, `xargs -n /a/env`, `gcc -I /usr/include/sudo` and the names `nice`, `sudo` and `xargs` behind a slash; each linear twin reads about 2.0: no dash word before the path (`echo /a/env`), no slash (`-exec env`), a name that is no wrapper (`-name /a/rm`), one that only begins with one (`-name /a/envy`), or the path in double quotes (`-path "*/bin/env"`). The first drive on main (8488ae7, mail 7941cb) read 1.46 s at 4 KB, 6.2 s at 8 KB and 25.3 s at 16 KB, with no single compiled pattern slow alone (each under 80 ms at 4 KB, each about four times per doubling), so the cost is spread across the anchor-led patterns; which arm re-reads the slashed name is not measured (the `(?<=/)` wrapper arm is a guess). The head of the lane that reads the carriers' command-position grammar (C76, open as #506) reads the same (1.33 s at 3.2 KB). The walker scaling ratchet (`tests/test_redos.py::_WALKER_CONSUMERS`, `DEF-817`) judges this reader as `removed_or_relocated_operands`, but no flood in `tests/test_redos.py::_WALKER_FLOOD_MAKERS` carries the token, so CI is green. Neighbour, another defect: `DEF-4031` names the same reader for operands yielded without the verb's recursion. Graded as friction, not a fail-open: `tools/cc/hooks/write_guard.py::JUDGMENT_BUDGET_S` (3.5 s, the `DEF-1160` fix) refuses a judgment that outruns it, so the flood is denied, never let through (read from the code, not driven through the hook). Who is hurt: an operator whose agent passes a long generated command with many such pairs (a `find` with a run of `-path */bin/env` tests, a compile line of include directories), slowed by seconds a call or refused for a command with nothing in it (`docs/STANDING_PRINCIPLES.md` section 2). Fix shape: find the arm that re-reads the run from each slashed wrapper name and bound it, as the `_CMD_POS_WRAP_RUN` lookaheads bound the wrapper run, then add the shape to `_WALKER_FLOOD_MAKERS` so the ratchet that missed it holds it. The probe drives the flood through the ratchet's own `_walker_scaling_judgement` at a 2 KB window (the declared 32 KB cap costs minutes on a host without `SIGALRM`, which the probe stubs there) and prints 1 while it reads super-linear; its linear twin (`-exec /a/envy`) prints 0.
