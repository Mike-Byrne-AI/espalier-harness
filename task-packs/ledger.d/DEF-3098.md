| `DEF-3098` | tools/cc/seat.py::resolve, tools/cc/board.py, tools/cc/mail.py (three readers of which checkouts answer one seat name) | **Three readers of which checkouts answer one seat name answer it by three rules, so a twin the board flags is one the seat driver never sees.** `tools/cc/board.py` (the `seats:` line's checkout read) reads every worktree `git worktree list` gives, each by `mail.machine_setting` at git's effective scope, so a worktree with no name of its own answers its clone's; `tools/cc/seat.py::resolve` reads only the worktrees under `.claude/worktrees/`, a nameless one answering the name SessionStart would derive; `mail.name_this_worktree` reads every listed sibling's own `--worktree` name before it names a worktree. A worktree outside `.claude/worktrees/` that answers a seat's name (air's note 20261117T164638Z-air-cf1b9f: air-work's scratch worktree under a temp folder, no session in it, one mail ref with air-work) is a twin on the board and nothing to `seat.py`, which resolves the seat past it with no word; driven here on a fixture (a clone `box` with `.claude/worktrees/a` and a worktree outside the clone's folder, each answering `box-x` through per-worktree config): `resolve` returns `a`. Two more seams of the same reading: the clone's own name is read `--local` by `resolve` and by the board (`mail.clone_machine`), but at the effective scope by `seat.py::_this_checkout` and by the mail writer (`mail.send` reads `mail.machine_setting` with no scope), so a main checkout given a `--worktree` name answers one name to the resolver and writes its mail under another; and the board's naming remedy for a worktree is `mail.naming_steps(at=...)`'s two commands chained with `&&`, which Windows PowerShell 5.1 does not parse (the seat driver's twin refusal gives one command a line since DEF-3097's lane). Who is hurt: the operator or the dispatcher who reads a twin on the board and then runs `seat.py launch`, `brief` or `retire` on that seat, which acts as if the name had one checkout (a second writer launched beside the twin, or a retire releasing claims the twin's ref shares); and an operator on Windows PowerShell pasting the board's naming pair. Contract basis: a seat is one session in its own named checkout, one name on the mail channel (Core Rule 15), and these three are the channel's own readers of that. Fix shape (probable): one reader in `mail.py` of the checkouts answering a name (every listed worktree, each by the name it writes under, the clone's own included), called by the board, `seat.py::resolve` and `name_this_worktree`; `naming_steps(at=...)` gives one command a line. The probe prints the folder `resolve` picks (`a` while a twin outside `.claude/worktrees/` goes unseen; `refused` once it is read). | minor | LOGIC_BUG | OPERATOR |
