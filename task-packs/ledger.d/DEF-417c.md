| `DEF-417c` | espalier/release_pack.py::_is_pruned_from_walk | **The release walker's report-only prune does not match compiled Python, so every `__pycache__` entry on the walked tree becomes a line of the release report.** Driven: `_is_pruned_from_walk('pkg/__pycache__/x.pyc')` returns False; the predicate matches only a root `.git` component, a `venv`/`.venv` directory component and the `dist/final-release-matrix/` subtree, while its own docstring gives "pruning at walk time keeps the payload byte-identical and stops the report growing with local scratch" as the whole reason it exists. Who: a maintainer reading the release report to see what the archive rejected, who has to find the real entries among the compiled-file noise a developer tree always carries. Fix: add a `__pycache__` directory-component arm beside the `venv` one and keep it report-only -- `tests/test_release_pack.py::TestWalkPruning::test_pruned_paths_are_never_shippable` is the oracle that every pruned path is already contract-rejected, so the payload cannot move. | minor |
