| `DEF-5014` | espalier/_python_floor.py::interpreter_start_failure (a start probe that never answered read as cannot-start) | **On a slow host the engine's start-up probe reads a probe that never answered as an interpreter that cannot start, so `init` passes over a working Python and can wire a name that does not resolve, and `init` and `doctor` both say every guard fails open.** `espalier/_python_floor.py::interpreter_start_failure` runs `-I -c 'import sys'` with a 2 s timeout, retries a timeout once, and then returns "cannot start: the start-up probe timed out twice (2 s each)"; every engine caller reads that as the DEF-915 verdict. Driven on the Air (2026-10-16, the spawn stubbed to time out, every other spawn real, `tests/_interpreter_hosts.py` working stubs): on a host with only `python3`, the resolver skips it, warns that nothing validates and falls back to the literal `python`, which does not resolve there, so `init` wires it and says "Hooks are NOT yet active ... does not resolve on this host ... each guard fails OPEN"; with `python` and `python3` both present it wires `python` and says the interpreter "cannot start ... each guard fails OPEN" and that nothing on PATH answers as Python 3.10+, and `doctor` warns the same and prescribes putting a Python on PATH. Nothing is remembered between asks: `init` paid 80 start-probe spawns (160 s worst case) and `doctor` 32 (64 s), against 22 and 4 on a healthy host. The hook-side twin (`tools/cc/hooks/_hook_utils.py::interpreter_start_failure`) keeps the banner's verdict on two timeouts by design. Who is hurt: an adopter running `init` or `doctor` on a slow host (DEF-1130 measured 31 to 73 s per concurrent interpreter start on windows-latest; a loaded laptop), told a working interpreter cannot start, or left with hooks wired to a name that is not there. Fix shape (the shape DEF-2019 took): an unanswered start is its own verdict, distinct from cannot-start; a decision keeps the banner's verdict on it, and the claim surfaces (`init`'s enforcement claim, `doctor`'s floor check) say the start was not confirmed on a slow host, with a next step; the verdict is remembered per interpreter for the process, so its spawns are one bounded total; a pin on the spawn count with the spawn stubbed to miss.
