| `DEF-2075` | tools/cc/hooks/write_guard.py::_PS_GLUED_PAREN_RE (an array subexpression's command) | **A read inside a PowerShell array subexpression is not read by the secret-read leg, so `$a = @(Get-Content .env)` reads a dotenv on the PowerShell tool with no refusal, where `$a = (Get-Content .env)` is refused.** The leg treats a `(` glued to `@` as an argument's paren (`tools/cc/hooks/write_guard.py::_PS_GLUED_PAREN_RE`, which blanks it, written for `Get-Content @(".env")`), so the command inside `@( )` never sits at a statement start (probable cause, read not driven). Driven at the head of lane/a-powershell-comment-hides-no-command (ef0470) through the hook: `@(gc .env)`, `$a = @(Get-Content .env)` and `@(Get-Content -Path .env)` each allow, and Windows PowerShell 5.1 reads the file for the second (driven on a scratch file); `$(gc .env)` is refused. Found by that lane's failure-mode review, present at 9c47d43 too. Who is hurt: an operator whose agent loads a file's lines with `@(Get-Content ...)`, the common idiom for an array of lines, and reads a secret with no refusal. Contract basis: the secret-read leg, a program named directly with its operand literal, plain syntax. Fix shape (probable): `@(` after a blank, `=`, `\|` or a statement opener opens a statement as `$(` does, while `@(` glued to a verb stays an argument. The probe prints the read leg for the first two (`False False` while the defect stands). | major | LOGIC_BUG | ADOPTER |
