| `DEF-1103` | espalier/proofs.py::_walk_surface_findings; espalier/cli.py::_parse_yaml_frontmatter; espalier/render_surface.py::_read_frontmatter_description; tools/cc/hooks/post_write_check.py | **No Espalier surface checks that an adopter-authored agent, command or skill body has frontmatter Claude Code will actually load, and the generated roster lists a body that did not load as if it had.** Claude Code parses frontmatter strictly and, on failure, retries after a fallback that quotes values line by line with a regex that a trailing carriage return defeats. So frontmatter that is not strict YAML (typically an unquoted description containing `: `) still loads with LF line endings and fails with CRLF, as a Windows checkout with `core.autocrlf=true` and no `.gitattributes` rule produces. A project agent that fails to parse is not loaded at all; a skill or command loads with its fields dropped; nothing warns at normal verbosity. Espalier neither detects nor prevents it: `espalier/proofs.py::_walk_surface_findings` parses only managed `.toml` under `.claude`, `post_write_check.py` checks `.claude` bodies for placeholders only, and its own frontmatter readers (`cli._parse_yaml_frontmatter`, `render_surface._read_frontmatter_description`) are deliberately lenient line splitters, so `cc/LIVE_SURFACE.md` lists the unloaded agent with its full description. Found by the 2026-10-03 adoption audit (`espalier-issues/audits/2026-10-03-adoption/public_report.md`, C-9); re-checked at `08ab2db`: LIVE, trigger-gated: no shipped agent uses the failing YAML shape (all packaged bodies are strict-valid), so the user is an adopter authoring their own agent or command file; the root cause is Claude Code's loader, not Espalier. Who is hurt: a Windows adopter with `autocrlf` whose custom agent silently drops out after a re-checkout while the harness's own roster still shows it. Fix shape: a stdlib check (the runtime has no YAML dependency) that flags a top-level plain scalar containing `: ` or ` #`, or opening with a YAML indicator, in every `.claude` agent, command and skill body, reported by `audit` and `post_write_check` as `will not register`; a `doctor` recommendation (not an `init` write, since the host owns `.gitattributes`) for a `.claude/** text eol=lf` rule; and the roster renderer marking such bodies instead of listing them. | minor | LOGIC_BUG | ADOPTER |
