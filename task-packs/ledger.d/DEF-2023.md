| `DEF-2023` | tests/conftest.py::pytest_testnodedown (the went-down line's window shared with the first test's setup) | **The build report's went-down line cannot tell a worker whose tree build died from one whose first test's setup died: both reach the controller as a worker that finished collecting and sent no test report.**  DEF-2021's fix (`tests/conftest.py::pytest_testnodedown`) names such a worker `went down after collecting, before its first test report: in its build, or in that test's setup`. It must name both because a worker's build report rides `workeroutput`, which xdist delivers only when the worker finishes, so a crash loses it.  Who is hurt: an operator reading a crash run's tail on a slow host, where the first test's setup crossed the thread-method ceiling, who is told the build may be what died and chases it.  Fix shape: each worker writes its build report into its own basetemp as the build ends, and the controller reads that file for a worker that went down. The line then names the true outcome: the build failed, or it finished and the first test's setup is what died.  Oracle: a child run as in DEF-2021's pin (`tests/test_xdist_never_ran.py::TestACrashedWorkerIsNamedOnlyWhereItsBuildCanBe`, the row whose first test's setup crosses the ceiling), asserting the setup reading. No probe: see the why-not. | minor | HYGIENE | MAINTAINER |
