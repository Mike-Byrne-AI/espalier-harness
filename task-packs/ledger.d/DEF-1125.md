| `DEF-1125` | tools/cc/hooks/_bash_patterns.py::_below_a_scratch_root (the typed-string compare of the env root against the target) | **On a Windows host whose `TEMP` is presented in 8.3 form, the PowerShell scratch-root rung never fires: the env root is compared as typed, so a scratch tree spelled long (`C:\Users\someuser\AppData\Local\Temp\x`) is not "below" a root spelled short (`C:\Users\SOMEUS~1\AppData\Local\Temp`), and the forced recursive delete meets the wall the rung was built to relieve.** `tools/cc/hooks/_bash_patterns.py::_below_a_scratch_root` lowercases and separator-normalises the `TEMP`, `TMP` or `TMPDIR` value and the target and asks `startswith`; nothing expands a short component on either side, while the resolver the hard tier reads on Windows (`_posix`, `ntpath.realpath`) does expand one for a directory that exists. Fails closed: the wall, never an allow. Found by the failure-mode review of the scratch-root lane (2026-10-04) at the string level, where the compare is verified; that GitHub's windows-latest runners present `TEMP` with a `RUNNER~1` component is recalled from Actions logs and was not measured in this lane, so the host shape is plausible. `CLO-46` (8.3 names as an evasion of the protected zones) stays declined and `DEF-933` corrects that doc sentence; this row is the friction side, not an evasion. Who is hurt: a Windows adopter, or an agent on a Windows CI runner, whose `%TEMP%` carries a short component and who deletes a scratch tree under it spelled long: the rung's relief is silently absent and the delete is refused with no re-issue, the shape the lane set out to remove. Fix shape: read each env root in a second spelling too, `_posix(value)` (realpath expands a short name on Windows for a directory that exists, which a temp root does), and compare the target against both; a driven row needs a host with 8.3 generation on, so the test pins the two-spelling compare with a fake expander.
