| `DEF-3037` | tools/cc/ship.py::_handoff_push (the records-ref park tried only with no pull request open) | **A handoff onto an open pull request pushes its Session Log row even when the row is all the push carries, so the lane's running full tier is cancelled and starts again for a record.** `tools/cc/ship.py::_handoff_push` parks a handoff that carries rows alone on the seat's records ref (`tools/cc/ship.py::_park_the_row`, the `DEF-5007` path) only when no pull request is open for the branch; with one open it merges the base in, folds the parked rows (`::_fold_session_log`) and pushes, and the new head cancels the run in progress. The dispatcher's 11-04 run review read 56 of 196 pull-request test runs from 10-30 to 11-03 superseded by a later push: 29 catch-ups, 12 handoff rows pushed onto an open pull request, 4 folds of parked rows and 11 fixes, and put about 45 of them on the ship driver. The rows and folds are this row (16 runs); a catch-up cancels by design, since the board's `stale:` line asks for it so CI tests the combination, and a fix is the lane's own. Who is hurt: every seat whose lane is in CI when its handoff lands, whose merge waits another full tier (the full tier's cells take a median of 43 to 48 minutes, `DEF-3034`) for a commit no test reads, and the runners the restarted tier holds. Fix shape: in `::_handoff_push`, park the rows on the records ref when every commit the push would add is a Session Log row and the pull request is open, as the merged case already does, so the next push folds them; a handoff carrying code still pushes.
