| `DEF-2069` | espalier/cli.py::_ask_resolves_only_inside_a_virtualenv (asks whether the name resolves outside the venv, never whether that one clears the floor) | **Inside an activated virtualenv on a Python that clears the floor, init wires the venv's name when a Python below the floor answers to the same name outside the venv, so in a fresh shell every deny hook refuses every call.** `_ask_resolves_only_inside_a_virtualenv` asks only whether the name resolves anywhere once the venv is off PATH (`shutil.which(name, path=path_without(cand_prefix)) is None`), never whether what it resolves to clears the floor. So a venv shim that hides a below-floor system Python reads as host-wide, `_detect_python_command` returns it, and `_refuse_below_floor_wiring` passes. Driven 2026-11-11 (UTC; 2026-11-10 local) on the Windows box at lane head 88e2b091 (TP-706 follow-on 01afca): PATH = a 3.11.9 venv's Scripts, then uv's CPython 3.10.21, then System32, with VIRTUAL_ENV set. The resolver answered `python`, the refusal gate returned None, and in a fresh shell `python` found the 3.10.21. Who is hurt: TP-706's own adopter, stock Ubuntu 22.04 (python3 at 3.10.12) working in a uv or `python -m venv` environment on 3.11. Init reports success, and the next session started from another terminal, an IDE or the desktop app answers every tool call with the floor refusal. The failure-mode review of that lane drove a worse variant on Windows: where `python` outside the venv is the Store alias, not a Python at all, init wires `python` at rc 0 and doctor passes inside the venv, and from any other shell every hook exits outside {0, 2}, so every guard fails OPEN. The rewire leg reaches the same place: `--rewire-interpreter` run inside the venv rewrites a wired below-floor `python3` to `python`, and its minimal-PATH check (`rewire_interpreter_in_settings`, read against `os.defpath`, which names no system directory on Windows) never fires there. Fix shape, not built: the venv-only test asks whether the outside resolution clears the floor and starts, not only whether it resolves, and treats a name that resolves outside only to something that fails either as venv-only, the rewire's check reading the same, so the resolver moves to the next candidate or the floor refusal names it. Found by air's verifier reading the 01afca lane, filed on air's note aaa1bd. | major | LOGIC_BUG | ADOPTER |
