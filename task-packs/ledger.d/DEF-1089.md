| `DEF-1089` | espalier/managed_paths.py::STANDARD_MANAGED_TOOLS; tools/cc/read_summary.py::_project_dir; tools/cc/memory_sort_audit.py::_audit_duplicates | **The one tool that sorts machine-local auto memory against the repo's committed memory, `tools/cc/memory_sort_audit.py`, is never deployed by `init`, and it looks for the store only at Claude Code's default path.** `espalier/managed_paths.py::STANDARD_MANAGED_TOOLS` does not list it, and `espalier/cli.py::INIT_TOOL_SCRIPTS` is `list(STANDARD_MANAGED_TOOLS)`, the only source the init deploy loops use; no shipped command, skill, hook or workflow invokes it. `docs/MEMORY_SYSTEMS.md`, which holds the sorting rule and the pointer-marker grammar, is not in the wheel either; the seeded `memory/README.md` points at it with an honest "not deployed by `init`" caveat, while the `fuse` route overlays both. The audit takes its store from `tools/cc/read_summary.py::_project_dir`, which builds `~/.claude/projects/<per-character-encoded cwd>`; that is the right key for transcripts and the wrong one for auto memory, and nothing in the package reads Claude Code's `autoMemoryDirectory` setting (0 hits). A relocated store therefore prints "no machine-local store ... not audited" on stderr and exits 0, loud but with no hint about the setting; running from a linked worktree probably misses the store too (probable, not run). Found by the 2026-10-03 adoption audit (`espalier-issues/audits/2026-10-03-adoption/public_report.md`, A3-6); re-checked at `08ab2db`: LIVE. Measured on one adopter with a prior harness, which had auto memory to sort. Even deployed and pointed right, the audit is a drift detector, not an inventory: its docstring measures class-1 slug recall at about 26 percent on known twins, so deploying it alone does not do the fold; the missing step is an inventory of prior auto memory with a proposed home per note. Who is hurt: an adopter with months of auto-memory notes, or a non-default config directory or `autoMemoryDirectory`, who installs the harness and is given no way to sort those notes into committed homes. Fix shape: add `tools/cc/memory_sort_audit.py` to `STANDARD_MANAGED_TOOLS` with a short seeded section carrying the sorting rule (or fold the rule into the seeded `memory/README.md`); resolve the store from `autoMemoryDirectory` in local, project then user settings, falling back to the default; give the audit an inventory mode that lists each note with a proposed home for the operator to confirm. Edit the SoT, then run `scripts/sync_vendor_cc.py`; the EXPECTED_* counts follow. | minor | LOGIC_BUG | ADOPTER |
