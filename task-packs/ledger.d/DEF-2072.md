| `DEF-2072` | tools/cc/hooks/write_guard.py::_ps_secret_read_targets (a block comment in operand position) | **A block comment between a PowerShell read verb and its operand hides the operand from the secret-read leg, so `Get-Content <# c #> .env` reads a dotenv on the PowerShell tool with no refusal, where `Get-Content .env` is refused.** `tools/cc/hooks/write_guard.py::_ps_secret_read_targets` takes the words after the verb as typed and stops at the first that opens with `#`, so the comment's own words (`<#`, `c`) are read as the operand and `#>` ends the read before `.env`. Found by the code review of lane/a-powershell-comment-hides-no-command (ef0470) and driven at its head through the hook: `Get-Content <# c #> .env`, `gc -Raw <# c #> .env`, `Get-Content -Path <# c #> .env` and `Get-Content <# c #>.env` each allow; Windows PowerShell 5.1 reads the file for the first (driven on a scratch file). Already right: the protected-zone leg over-reads this shape (`Set-Content <# c #> tools/cc/hooks/x.py y` is refused). Who is hurt: an operator whose agent on the PowerShell tool annotates an argument with an inline comment and reads a secret with no refusal. Contract basis: the secret-read leg, a program named directly with its operand literal, plain syntax. Not DEF-2070's site (that is a statement start, this an operand slot in the reader) nor DEF-2071's (the re-parse lookback). Fix shape (probable): the reader skips a block comment between words, on the masked scan where the masker already reads the comment. The probe prints the read leg for the first two (`False False` while the defect stands). | minor | LOGIC_BUG | ADOPTER |
