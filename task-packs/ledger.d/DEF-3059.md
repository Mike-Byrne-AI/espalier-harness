| `DEF-3059` | tools/cc/hooks/_bash_patterns.py::_DIR_VERB_RE (current-shell cd spellings the tracker does not follow) | **The cd tracker misses current-shell `cd` spellings, so a relative write after one is judged from the wrong directory: `eval "cd tools/cc" && mv hooks/x.py /tmp/y` and `c\d tools/cc && mv hooks/x.py /tmp/y` are allowed, where bash moves `tools/cc/hooks/x.py` (the plain `cd tools/cc && mv hooks/x.py /tmp/y` is walled).** `tools/cc/hooks/_bash_patterns.py::_DIR_VERB_RE` reads `cd`, `pushd` and `popd` at the current shell's command position (`::_CMD_POS_IN_SHELL`, since the DEF-3043/3044/3053 lane's ruling 6344f9) as a bare word: a `cd` inside a quoted `eval` program, a backslash inside the word (`c\d`), a variable holding the verb (`C=cd; $C tools/cc`), positional parameters (`set -- cd x; "$@"`), a function or a sourced file that runs `cd` are not followed, nor, under zsh (the Bash tool's shell on macOS), a pipeline's last element (`echo \| cd tools/cc`), `noglob cd`, `nocorrect cd` and `repeat 1 cd`; nor a `cd` as an `if` or `while` test (`if cd tools/cc; then mv hooks/x.py /tmp/y; fi`), which re-bases nothing at base either: friction for that fixture, a false allow where a cd into a zone is followed by a relative delete (ack 1a9932 (5), note b94acf (4)). Fix shape: the tracker reads the verb as the shell resolves it (a quoted `eval` body as a program, backslash removal in the word, a literal binding inlined as the walls' readings already inline one), each spelling a wall row beside the bare twin; a function, `source` and the zsh forms may stay a declared limit.
