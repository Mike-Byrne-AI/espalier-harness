| `DEF-3081` | tools/cc/hooks/config_guard.py::_scan_payload (a user-settings change's path dropped as out of root) | **config_guard never judges a change to the user settings file: `disableAllHooks: true`, or an `env` map setting a variable that switches a gate (`ESPALIER_MAINTENANCE_MODE`, `ESPALIER_STOP_GATE`, `ESPALIER_STOP_GATE_TEST_CMD`), written to `~/.claude/settings.json` is let through, though the hook's docstring and CLAUDE.md's hook table say user settings are blocked.** Claude Code names that file in the payload by its absolute path (`source: user_settings`, documented), `_scan_payload` bounds the path to the repo root, drops it, and falls back to the two project files, so the change is never read; and no reader anywhere judges a settings `env` map, the project and local files included. Found by air's verifier on a8ce07's candidate 2 (operator call b375dc); queued as note 7ee56c, assigned 2065dd. Driven 2026-11-14 on Claude Code 2.1.319: an `env` map in a scratch project's settings reached the hook process at SessionStart and UserPromptSubmit (one nested headless run), and the settings reference says a user-settings `env` change is applied to the running session when it alters the merged `env`, so a gate variable written there loosens the session's own later hooks, not only the next one's. Precision, from the hooks and settings references: hook lists merge across user, project and local settings, so an emptied or no-op hook list in the user file removes no project hook (three of `_find_kill_switches`' four arms would be false findings there); `disableAllHooks` and each `env` variable take the value of the highest-precedence file (local, project, user). Who is hurt: an operator whose session, refused elsewhere, writes the switch into the user settings file; the running session applies it and later hooks start with the gate off, and nothing records it. Contract basis: the anti-self-disable floor (5cb6f0). Fix shape: config_guard reads the changed file wherever Claude Code names it, the user file identified by location (home or `CLAUDE_CONFIG_DIR`) or by source; it refuses an effective `disableAllHooks` the user file supplies, and a gate variable any settings file sets to a value that loosens its gate against the hook process's live value (so a value already in effect at the start refuses nothing); the refusal is recorded and told at the next PostToolUse, since ConfigChange has no channel.
