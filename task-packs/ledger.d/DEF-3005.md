| `DEF-3005` | tests/ (every per-node `ast.get_source_segment` call: ten files, named in the row) | **Ten test files call `ast.get_source_segment` once per node, and each call re-splits the whole source file, so a module that walks a large file per node can cross the 60 s per-test ceiling on the required `test (3.10)` cell, the slowest interpreter in the matrix, while every newer cell passes.** It has happened twice: `DEF-762`, and the reader census in `tests/test_ledger_fragments.py` on #207 (2026-10-14), fixed by splitting the file once. The cost per call is CPython's `ast._splitlines_no_ff`, a per-character loop over the whole source (read on 3.11.9, the same shape as 3.10's; timed here at 0.086 s for one call on the 820,196-character `tests/test_write_guard.py`, so about 700 per-node calls on that file fill the ceiling; not timed on 3.10). The oracle, every `get_source_segment` call under `tests/` read by AST on 2026-10-14, names 14 calls in ten files: `tests/test_adopter_verb_stand_down.py` (2), `tests/test_cli_deploy.py`, `tests/test_cognitive_blueprint.py`, `tests/test_config_fields_consumed.py` (2), `tests/test_contracts.py` (2), `tests/test_derived_population_census.py` (2), `tests/test_final_release_matrix.py`, `tests/test_maintenance_mode.py`, `tests/test_settings_reader_bom_contract.py` and `tests/test_write_guard.py`. Three of the 14 are the stdlib-equality pins for the split-once slicers (two in `tests/test_derived_population_census.py`, one in `tests/test_maintenance_mode.py`); they stay. Who is hurt: a maintainer whose required 3.10 cell times out, holding a pull request that changed nothing near the test, when one of these files or the file it walks grows, as the census did on #207.
