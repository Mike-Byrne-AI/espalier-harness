| `DEF-3055` | tools/cc/hooks/_bash_patterns.py::_ASSIGN_VALUE (its plain piece admits the separator characters: quadratic across start positions) | **The command-position anchor's assignment value admits the characters that open a command position, so on a run of assignments glued to separators each start reads to the end of the input and the anchor reads in time quadratic in the command's length.** `tools/cc/hooks/_bash_patterns.py::_ASSIGN_VALUE`'s plain piece (`[^\s;\|&'"$\\]`) admits `(`, `)`, `{`, `}` and the backtick, which `::_CMD_POS_SEP` opens a fresh start on, and `::_CMD_POS_ENV_ASSIGN` reads it under `::_CMD_POS_NO_VERB`'s star: driven in-process on Windows after the DEF-3043/3044/3053 lane, `re.compile(_CMD_POS + "zzz")` on `"A=(" * n` reads 78 and 320 ms at 4 and 8 KB, as do `"A=1("`, ``"A=`"`` and `"A=}"` (fourfold per doubling), where every other token run of the anchor now stops at a separator and reads the same floods in 1 to 3 ms. Left out of that lane on purpose: `_ASSIGN_VALUE` is also write_guard's environment-prefix reader's value (`tools/cc/hooks/write_guard.py::_BASH_ENV_PREFIX_TARGET_RE`), and a value keeps a substitution and a brace a separator-free run would lose (`PATH=${HOME}/bin rm -rf tools/cc` reads `rm` today only because the value spans the braces; `A=$(pwd)/x mv` the same), so the fix needs the lane's substitution piece and brace rule carried into the value with that reader's own rows. It also keeps the speed bump's narrowed inner fetch position (`tools/cc/hooks/_speedbump.py::_FETCH_INNER_POS`) from folding back into `_CMD_POS`. Who is hurt: an operator whose agent sends a long generated command dense with array assignments or substitutions (`arr=(a b c)` repeated, judged, never run here): past about 30 KB of such text the search nears Claude Code's 5 s hook timeout, the interpreter lock keeps write_guard's time budget from refusing it, and a cancelled hook lets the call through unjudged.
