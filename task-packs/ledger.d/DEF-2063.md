| `DEF-2063` | espalier/cli.py::_swap_interpreter_token (the quoted spaced head it writes into a shell-form hook) | **A shell-form hook command rewired to a spaced interpreter opens with a quoted word, which Windows PowerShell refuses.** `espalier/cli.py::_swap_interpreter_token` writes the target double-quoted when it holds whitespace (DEF-4094), and its docstring says such a hook runs in PowerShell where Git Bash is absent. PowerShell 5.1 reads a quoted first word as a string and refuses the line (driven for DEF-2060 on Windows 11). DEF-2060's fix, the forward-slash 8.3 short form, does not serve here: the command is persisted into `.claude/settings.json`, and a short name belongs to one volume. Who is hurt: a Windows adopter with no Git Bash whose only good Python has a space in its path, after `init --rewire-interpreter` writes that path into a shell-form hook; the hook fails to parse. Split from DEF-2060 at its strike, where this reach was named as read and not driven. Fix shape open: the call operator for a PowerShell-run command, or a launcher spelling that needs no quoting, driven on the host that runs the hook. Probe: `_swap_interpreter_token` given a spaced target returns a command that opens with a double quote. | minor | LOGIC_BUG | ADOPTER |
