| `DEF-1083` | .claude/commands/implement-pack.md (Stop conditions, folder mode); .claude/commands/handoff.md (push step); tools/cc/ship.py::marker_needed | **The shipped run-to-completion commands have no stop item for a step the repo's own rules make approval-required, and none says the repo's CLAUDE.md or the user's in-session instructions take precedence.** `/implement-pack` stops `ONLY when one of these fires` and that list is closed (test failure, release gate, audit errors, integrity drift, an unverifiable acceptance line, a refuting Task 0 oracle); it has no item for `the next command is approval-required by this repo and this session has not authorized it`, and it never reads a pack's own stop-conditions section (the only per-pack seam is four literal marker strings found nowhere else in the shipped assets). Folder mode adds `Do NOT ask "should I continue?" — that's exactly the friction the user wanted to remove`, the maintainer's preference arriving as if it were the adopter's own voice, in a slash-command body that is delivered as the user's turn and so competes with the repo's approval rules. `/handoff` commits with no approve-the-list step (which `/commit` has) and then runs `ship.py lane` and `ship.py open` or `git push` with no explicit-yes gate, so the push fires whenever `/handoff` is reached without the user typing it (the model invokes it from the skill listing, a delegating close command, or the RESUME line); `ship.py` binds the human-approval marker into the title itself when `marker_needed` reports hits, a deliberate maintainer choice that is a design conflict for install-ci adopters. The irreversible speed-bump tier is documented as a lever, not a wall, and clears when the agent re-issues the command. Found by the 2026-10-03 adoption audit (`espalier-issues/audits/2026-10-03-adoption/public_report.md`, A2-8); re-checked at `08ab2db`: LIVE at the instruction layer; behavioral magnitude unmeasured. No ledger row owns it (§C68 and DEC-39 are adjacent). Who is hurt: an adopter whose CLAUDE.md requires approval before commit or push, who runs a folder of packs or a `/handoff` and sees the push and merge arm without being asked. Fix shape: one consent seam, a numbered stop step in `implement-pack` before step 2a that stops on any command the repo's CLAUDE.md, the pack's stop section or a config key marks approval-required and reads the pack's own stop section; make the `Do NOT ask` line conditional on the launch having granted it; give `/handoff` the same explicit-yes gate as `/commit`; add a one-line precedence clause to every autonomy-granting body. | minor | LOGIC_BUG | ADOPTER |
