| `DEF-4112` | tests/conftest.py::_no_live_tree_writes (a fixture of module, class or session scope, or collection, writes outside every fingerprint) | **The live-tree watch fingerprints each test's own call alone, so a write into a watched directory made by a module-, class- or session-scoped fixture, or at collection, is seen by no fingerprint, and on a CI checkout a blueprint chain such a fixture starts is read by every later test with nothing naming its writer.** `tests/conftest.py::_no_live_tree_writes` is a function-scoped autouse fixture: pytest sets up the wider-scoped fixtures a test needs before it takes its first fingerprint, and tears them down after its teardown compares, so their writes fall outside every pair; no other function in `tests/conftest.py` calls `tests/conftest.py::_live_tree_fingerprint` (`pytest_sessionfinish` and `pytest_collection_finish` do not), and the block above `_LIVE_TREE_WATCH` declares the limit since #591. The shape the class has hit is this one moved a scope out: banner builds on REPO_ROOT that started a chain wherever none existed (the #573 ubuntu red, one test reading another test's new chain), moved to `self_host_tree_copy` in #591's lane; the same build in a module-scoped fixture would go unseen. Who is hurt: a maintainer who adds such a fixture, or a collection-time helper that roots a `tools/cc` script in REPO_ROOT, and whose CI cells then can red in a later test whose result depends on the chain, with no message naming the writer: the bisect the watch exists to replace. No sighting. Fix shape: an oracle of its own, a session-level check: fingerprint the watch before collection and at session finish, on the xdist controller where workers share one tree (a worker's pair would see its siblings' writes), excusing a live session's chain moves as `_attributed_moves` does, and red a net move no per-test fingerprint named, saying that a fixture or collection wrote it, since it cannot name which. Ruled a row by air (note 29bba8). The probe parses `tests/conftest.py` and prints whether `_no_live_tree_writes` is the only function that calls `_live_tree_fingerprint`: True while open. It reads code shape, not the defect: a new caller there flips it and a fix in another file leaves it True, so a strike rests on the fix's guard test. | minor |
