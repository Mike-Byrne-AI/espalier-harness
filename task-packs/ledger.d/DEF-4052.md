| `DEF-4052` | tools/cc/seat.py::brief_line | **The reset of a threshold handoff is a `/clear`, and the seat's next session is not re-briefed by it: the dispatcher's brief does not come back, a worker's `Orders:` line invites a second interval loop, and the old tick text persists.** The threshold handoff (`TP-704`: `tools/cc/hooks/task_router.py`, `handoff_context_tokens`, landed 2026-10-26) ends a session's work with a handoff and the operator's `/clear`, which the seat's interval `/loop` survives (measured 2026-10-15). After the clear, three things the failure-mode review of that lane named go wrong: (1) the dispatcher seat's brief (its duties, the assign authority, the figures rule) is a first message `seat.py launch` composes, and the SessionStart banner gives a dispatcher no `Orders:` line, so a cleared dispatcher orients from the banner alone; (2) on a worker holding live assigns the banner's `Orders:` line (`tools/cc/seat.py::brief_line`) ends "then start the worker loop (/loop 10m)" while the old loop is still running, which invites a second interval loop in the same window; (3) because the loop survives the clear, a seat keeps the tick text it was launched with until a relaunch, so a tick change (the threshold clause, 2026-10-26) reaches a seat only at its next launch.
