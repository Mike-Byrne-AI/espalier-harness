| `DEF-623` | `.gitignore` vs `espalier/cli.py::REQUIRED_GITIGNORE` | The harness prescribes `.espalier/` as a blanket directory ignore and its own repo enumerates individual files instead: `REQUIRED_GITIGNORE` carries `".espalier/"`, while this repo's `.gitignore` has no such line and lists seven `.espalier/` paths one at a time — so any NEW file under `.espalier/` is tracked by default here and ignored by default on an adopter tree, and the two shapes behave oppositely for the same path. They also disagree about a file that is already tracked here, `.espalier/freshness.json`. Who is hurt: the next maintainer who adds a runtime file under `.espalier/` on this repo and gets adopter-divergent behaviour with no warning — and because `.gitignore` doubles as the release-exclusion boundary, a new marker file rides into the release archive. Fix shape: decide which shape is canon and make the self-host `.gitignore` match what the harness prescribes, or record beside the entries why they must differ. | minor | HYGIENE | MAINTAINER |
