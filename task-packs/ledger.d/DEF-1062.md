| `DEF-1062` | espalier/cli.py::merge_hooks_into_settings (init's wire writes LF, ASCII-escaped); espalier/cli.py::repair_hook_wiring_in_settings (the merge-settings --repair write, same); espalier/cli.py::rewire_interpreter_in_settings (the init --rewire-interpreter write, LF, already ensure_ascii=False); espalier/cleanup.py::_unwire_espalier_hooks (the uninstall writes LF, ASCII-escaped); espalier/cli.py::_dominant_line_ending (the helper the .gitignore writers already use) | **On a Windows checkout with `core.autocrlf=true`, an install and uninstall round trip rewrites a tracked CRLF `.claude/settings.json` as LF, so `git status` reports it modified while `git diff` is empty; a non-ASCII rule comes back escaped on any OS.** `espalier/cli.py::merge_hooks_into_settings`, `::repair_hook_wiring_in_settings`, `::rewire_interpreter_in_settings` and `espalier/cleanup.py::_unwire_espalier_hooks` write `json.dumps(..., indent=2)` through `espalier/_atomic_io.py::atomic_write_text` (`newline=""`), so each lands as LF; all but the rewire also escape non-ASCII, a rewrite the rewire's own comment calls gratuitous. The .gitignore writers already follow the file via `espalier/cli.py::_dominant_line_ending` (the `DEF-940` precedent). Who is hurt: a Windows adopter who tracks their own settings.json (the `DEF-11` case), uninstalls, and finds ` M .claude/settings.json` with an empty diff; and one whose rules name a non-ASCII path, left a real diff. Nothing is lost: the JSON equals the committed file, and on the driven file (2-space indent, ASCII only) the bytes match apart from line endings. Found 2026-10-01 by the post-flip review on a Windows host and re-driven at HEAD. Out of scope, measured at the same writes: any other layout (4-space indent, a one-line array) comes back re-laid-out at 2 spaces; only a format-preserving JSON editor, absent from the stdlib, would close it. Fix shape: write all four through `_dominant_line_ending(settings_path)` with `ensure_ascii=False`, each pinned by a CRLF, non-ASCII round-trip test, since the probe reaches only the wire and the unwire. The probe seeds a CRLF settings.json naming a non-ASCII path in a temp repo, wires then uninstalls, and prints whether the wire kept CRLF and the character and whether the uninstall restored the bytes (`False False` today and under either change alone, `True True` under both). | nit | HYGIENE | ADOPTER |
