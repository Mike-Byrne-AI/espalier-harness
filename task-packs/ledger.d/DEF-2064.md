| `DEF-2064` | espalier/_text.py::program_word (an unspaced path left with backslashes); espalier/cli.py::_remedy_interpreter | **A remedy's unspaced Windows interpreter path keeps its backslashes, which Git Bash strips, so the pasted command is not found.** `espalier/_text.py::program_word` returns an unspaced path unchanged, and `espalier/cli.py::_remedy_interpreter` spells `sys.executable` through it when no PATH name clears the floor, so a per-user install such as `C:\Users\<name>\AppData\Local\Programs\Python\Python312\python.exe` reaches the reader with backslashes. In Git Bash an unquoted backslash is an escape, and the word arrives as `C:Users<name>AppData...`. PowerShell and cmd run it. Who is hurt: a Windows operator, or Claude Code's own Bash tool (Git Bash on this host), pasting a remedy on a host whose PATH `python` is a Store alias. DEF-2060 moved only the spaced case to forward slashes. Found by the DEF-2060 failure-mode review, which also noted that nothing pins the split between typed and persisted remedies (`_remedy_py(persisted=True)` at `espalier/cli.py::_file_onboarding_rows` is the one persisted site today): a fix here should add that census. Fix shape: forward slashes for any Windows program word, the persisted spelling left alone.
