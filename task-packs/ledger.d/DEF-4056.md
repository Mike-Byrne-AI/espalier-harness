| `DEF-4056` | tests/_box_lock.py::BoxLock._acquire | **The box lock's waiter has no exit: `BoxLock._acquire` polls `while True`, so a run that cannot take the lock waits for as long as the holder runs, and a run under a caller's own cap (an agent's Bash call, a mutant runner) reads its kill as the run's verdict.** `tests/_box_lock.py::BoxLock._acquire` loops on `try_lock_file` every `POLL_S` (0.25 s), prints the holder and the wait once per `REPORT_S` (30 s), and names the inspect and stop commands once the holder is past `WAIT_CEILING_MIN` (60 min), but returns only when the lock is taken or the record names a live ancestor; no variable bounds it and no exit says it waited. `TP-703c`'s Scope (out) names a bounded wait that exits distinctly, `ESPALIER_BOX_LOCK_WAIT_S`, as the review's proposal for a later lane, and its text (lines 176 to 180) leans on dispatches running their nodes serially so that no agent run takes the lock. Who is hurt: the maintainer whose agent runs a node id under `-n` beside a tier holding the lock (a `drive` or `mutants` dispatch that forgot the serial rule, or a `PYTEST_ADDOPTS=-n` inherited from the shell): the Bash call's cap (ten minutes at most) kills a run that never started, and a mutation run whose pytest never ran reads the mutant as a survivor; and the maintainer whose script wraps the tier in a timeout and reports the holder's wall clock as its own.
