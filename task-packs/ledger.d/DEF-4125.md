| `DEF-4125` | tools/cc/board.py::seat_rows (a session-less checkout listed first takes the bare row) | **The board's `seats:` line can give a live seat's name to a stale checkout that holds no session, and hand the live checkout the rename remedy.** `tools/cc/board.py::seat_rows` walks the checkouts in `git worktree list` order. A checkout with no session takes a name's bare row when that row so far came from mail alone, so a later checkout answering the same name with a live session reads as `held` and gets the `<name> [<checkout>]` row with the naming commands. On 2026-11-16 and 2026-11-17 a subagent worktree that air-work's process made on 2026-11-07 (clean, and locked by that process, so SessionStart's reaper kept it) answered air-work and was listed first: the board read "air-work: no live session" while the seat was live in `.claude/worktrees/work`, and named that live checkout to rename. The worktree was removed on 2026-11-17 at the operator's ruling (call 5733eb), which ends that instance, not the order. Who is hurt: the dispatcher, reading the seats line before an assign, who sees a live seat as dark; and any seat that pastes the remedy, which moves the live checkout off its mail ref, so its claims and jobs then read under a name nothing assigned. Fix shape: a checkout holding a session takes the bare row over one holding none, whatever the list order, and the session-less one then gets no row, as it gets today when it is listed second; a test pins both orders. | minor | LOGIC_BUG | OPERATOR |
