| `DEF-5098` | tools/cc/ledger_row.py::_base_tree (checkout-index through run_bounded) | **`ledger_row.py strike` checks out its base tree through a git whose bound kills git alone, so a smudge filter the checkout started keeps running at parent 1 when that bound fires.** `tools/cc/ledger_row.py::_base_tree` runs `git read-tree` and then `git checkout-index -a` at the probe runner's bound (`check_ledger_probes._TIMEOUT`, 30 s) through `run_bounded`, which on POSIX is `subprocess.run`, whose timeout kills the direct child only. `checkout-index` runs each path's configured smudge filter (`.gitattributes` `filter=` with a `filter.<name>.smudge` command, the shape git-lfs installs) as git's child. Driven in a code review on 2026-11-09 in a scratch repository: a smudge filter of `sleep 777; cat` and a 2 s bound left `/bin/sh -c sleep 777; cat` and `sleep 777` at parent 1 after the call returned (reaped by hand). `read-tree` with no `-u` runs no filter, and `_git_read`'s ref and object reads start no child (read, not driven). The strike guard's pytest takes the tree-ending spawn since the lane that filed this row; `tests/test_contracts.py::TestEveryTimedPytestEndsItsWholeTree` is keyed on pytest spawns and does not read this one. Who is hurt: an adopter whose clone configures a smudge filter (git-lfs) and whose strike's base checkout outruns the bound, for whom the filter's processes keep running beside the next work. Fix shape: `_base_tree` spawns through `_json_safe.run_tree_bounded`, its error handling unchanged; the guard is a scratch repository with a smudge filter that sleeps past a shortened bound and asserts no survivor after the call, reaped after. Probe: parses `ledger_row.py` and prints whether a timed call in `_base_tree` is a tree-ending call or a call to a function of the module that makes one: `False` while open. | minor | HYGIENE | ADOPTER |
