| `DEF-5117` | tools/cc/hooks/config_guard.py::_names_project_settings; tools/cc/hooks/config_guard.py::_changed_settings_label; tools/cc/hooks/config_guard.py::_settings_label_at | **config_guard decides which settings file a ConfigChange names by three rules, and two of its refusal records carry the payload's raw path.** `tools/cc/hooks/config_guard.py::_names_project_settings` and `tools/cc/hooks/config_guard.py::_changed_settings_label` match a payload path by location (the folder resolved, the name kept); `tools/cc/hooks/config_guard.py::_settings_label_at` matches the fully resolved path, then as the same file; and `tools/cc/hooks/config_guard.py::_scan_payload` bounds the payload path to the root before that third rule runs. So a `settings.local.json` symlinked out of the root is the local file to the gate-switch judgment and no file to the read: unparseable, it writes no `configchange_failed_open_settings_read` record, and the inventory scan reads it unvoiced. Separately, `configchange_blocked_kill_switch` (outside a gate switch) and `configchange_blocked_unwired` record the payload's `file_path` as given, so a skills change refused over a kill switch in `.claude/settings.json` writes the markdown file's absolute path, the home directory included, beside a finding about the settings file. Who is hurt: the operator reading a refusal's record, who sees a `.md` path named beside a `settings.json` finding; and one whose local settings file is a symlink out of the root and unparseable, who gets no record that its scan was skipped. Found by the failure-mode review of DEF-3092's lane (note 1dc4a5), ruled one class by air (assign 471785). Fix shape: one owner for which settings file a path is, read once a change, and every config_guard record's file field carries that owner's label or a fixed word, never payload text. The probe drives the hook on a skills change beside a kill switch and prints whether it blocked and whether the record names the payload's path. | minor |
