| `DEF-3099` | tools/cc/hooks/write_guard.py::check_secret_path_access (a read through an existing link to a secret) | **The secret read check judges a read target by the name it is read by, never by what an existing link resolves to, so a Read or a `cat` of a link to a dotenv file is allowed where a Read of the file is refused.** `tools/cc/hooks/write_guard.py::check_secret_path_access` hands each candidate (a content-surfacing tool's `file_path`, `notebook_path` or `path`; the Bash and PowerShell readers' read targets) to `::_secret_pattern_for`, a test of the spelled name alone. Driven on this box (2026-11-17, Windows 11, Python 3.11.9, a symbolic link made without privilege under developer mode): in a project holding a `.env` and a symbolic link `notes.txt` to it, the hook refuses a Read of `.env` and allows a Read of `notes.txt` and a `cat` of it by its full path. The creation side reads link makers one arm at a time: of `tools/cc/hooks/_bash_patterns.py::_SECRET_EFFECT_ARMS`'s seven arms, three make links (`ln -s`, `ln`, and `New-Item`'s link item types, DEF-5123), beside four that copy (`tar`, `zip`, `dd`, `Compress-Archive`). The link makers no arm reads are this row's cases, in effect words: `cmd /c mklink` (a symbolic link) and `mklink /H` (a hard link), `fsutil hardlink create`, the .NET `File.CreateSymbolicLink` and `CreateHardLink` methods called from PowerShell, `ln -s` run on the PowerShell tool, a script's `os.symlink`, and a link that existed before the session (an operator's, a dotfile manager's).
