| `DEF-1197` | tools/cc/hooks/_zone_watch.py::account: path 2 (content at HEAD) accounts for a commit made in the same call | **A bad edit committed in the same shell call is silent: the zone after-check accounts for any protected file that holds its content at `HEAD`, and a commit made in that call puts the edit there.** `tools/cc/hooks/_zone_watch.py::account` reads path 2 ("git: the file now holds its content at HEAD") as committed history that branch protection and CI judge, which holds for `main`, not for the working tree the session's hooks run from: `python fix.py && git commit -am wip`, or `git rm <hook> && git commit`, changes a running hook and reports nothing. Declared a limit by the operator on 2026-10-09 ("Document as a limit") and written into `docs/HOOKS.md` "The protected files after a shell call"; the commit still reaches `main` only through the pull request and CI. Who is hurt: the operator whose session's own hooks were rewritten by a slip that committed itself, until CI or a review sees the commit. Fix shape (untested): accept content at `HEAD` only when that commit was not made since the previous check (it is the baseline's stored HEAD, or reachable from a remote-tracking ref), and measure the false reports that rule brings (a switch between local branches, a merge whose result no ref holds) before adopting it. The probe builds a throwaway repository, takes a baseline, commits an edited hook in one step and prints what the check says: `silent` while open. Found by the failure-mode review of the A-1 lane (lane/a1-zone-after-check, 2026-10-09). | minor | LOGIC_BUG | ADOPTER |
