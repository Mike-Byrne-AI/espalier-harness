(1) `_upstream_gone` (965-967) is true only on `%(upstream:track)` = `[gone]`, and a lane pushed without `-u` keeps origin/main as its upstream, which is never gone; `catch_up` (1001-1010) then leaves it (`state=lane`), and the reason at 1008-1009 asks only whether `<branch>@{upstream}` resolves, so it says `its remote branch still exists` over a branch deleted on origin and pruned by the catch-up's own fetch (294-296). Driven: `lane/m` started from origin/main, one commit, `git push origin HEAD`, merged with a merge commit, the remote branch deleted: `state=lane reason='its remote branch still exists'`; the same lane pushed with `-u`: `would_catch_up`. (2) `_lane_not_on_origin` (1886-1909) reads the shared `lane_upstream`, whose fallback is `@{u}`; for a lane pushed with `-u`, merged and pruned, git reads the upstream as gone, `@{u}` does not resolve, and it answers `HEAD has no upstream: the lane was never pushed` (1901-1902), on which `arm` refuses (2094-2098). The catch-up runs at SessionStart on this repository and wherever `espalier.toml` sets `session_catch_up = true`.
