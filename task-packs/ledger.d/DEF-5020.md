| `DEF-5020` | tools/cc/hooks/_zone_watch.py::account (path 2 matches a small file's own bytes with its blob, and a big file's hash through the filters with its blob id: one form each) | **A protected file git calls clean reports when git brings it back, where its working copy differs from its committed form under the checkout's own filters: a file under 4 MiB stored through a clean filter (a git-lfs file, committed as its pointer), and a text file of 4 MiB or more committed with CRLF line endings in a checkout that sets `core.autocrlf`.** Path 2 of `tools/cc/hooks/_zone_watch.py::account` compares a small file's own bytes (line endings folded) with its blob, which for an LFS file is the pointer, and a big file's hash through the filters with its blob id, which under `core.autocrlf` is the hash of the LF form of a blob committed with CRLF (git's own status calls the file clean, by its safer-autocrlf rule). Found by DEF-5017/5018's failure-mode review (driven, with an emulated LFS filter, since git-lfs is not on the Air). Who is hurt: an adopter whose protected models are tracked by git-lfs, told to stop on every branch switch for the small ones, and an adopter on Windows (where `core.autocrlf` is the installer's default) with large CRLF text files. Named, not seen in an adopter. Fix shape, untested: on the report path only, have git hash a mismatched small file through the filters and a mismatched big one with `--no-filters`; a match either way is committed content.
