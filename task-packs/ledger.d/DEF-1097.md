Pinned by `tests/test_managed_markers.py::TestPackagedCommandsKeepTheirDescription` (contract, derived from the asset root): the deployed first non-blank line is `---`; the frontmatter parses under PyYAML to a description under 1,536 characters; it equals the body's opening paragraph (`audit-accuracy.md` exempt by name, its own description being the row `tests/test_command_surface_truth.py` tells the two sources apart by); a copy deployed before the fix (marker on line 1) is regenerated as `updated_managed`. Each row was seen red: main's `commit.md`, an unquoted `: ` in a plain scalar (PyYAML's "mapping values are not allowed"), and a one-sided edit of either copy. The probe reads 0. Not driven: Claude Code's loader on the folded form for a command (the agents load it on 2.1.290); `/read-summary`'s quoted phrase was reworded because no loading file proves a double quote inside a description, and `docs/SHARP_EDGES.md`'s plain-ASCII entry records what 2.1.290 does load.** PRIOR TEXT: **On every adopter tree, 17 of the 18 packaged slash commands deploy with the managed-marker HTML comment as their first line, so it is what Claude Code shows as their description.** Only `espalier/assets/claude/commands/audit-accuracy.md` opens with YAML frontmatter; the other seventeen open with a prose line that doubles as the description. `espalier/managed_markers.py::apply_marker_to_md` inserts the marker after the closing delimiter when frontmatter exists, but for a body with none it prepends `MARKER_HTML_COMMENT_RICH` as line 1, and a unit test pins that placement as intended. Claude Code takes the first non-blank line of a frontmatter-less command as its description, so `/commit`, `/handoff`, `/preflight`, `/recall`, `/status` and the rest all list as `<!-- espalier:managed - regenerated by ... -->` in the slash menu and the model's skill listing. They still run by name; what is lost is description-based discovery and auto-invocation, plus the always-on listing text spent on seventeen copies of one meaningless string. The maintainer cannot see it: the self-host copies carry no marker, the `CLAUDE.md` command table is built from the packaged source, and `render_surface._read_body_description` skips HTML comments on purpose, so the one renderer that learned about marker leakage never looked at the consumer that matters. Moving the marker to the end of the file is not a fix: `has_managed_marker` scans only the first 600 characters of a frontmatter-less body, so the next deploy would read the file as the adopter's and freeze it. Found by the 2026-10-03 adoption audit (`espalier-issues/audits/2026-10-03-adoption/public_report.md`, C-2); re-checked at `08ab2db`: LIVE (count of 16 of 17 re-verified at HEAD; the audit measured it on one adopter). Who is hurt: every adopter, opening the slash menu or relying on the model to pick a command by its description.
