| `DEF-2088` | tools/cc/hooks/_bash_patterns.py::_git_clean_operands (a glued `*>` on the Bash tool) | **On the Bash tool, `git clean -fdx *>/dev/null` reads `*>/dev/null` as one pathspec, so a clean of every entry in the checkout gets the CP-GITCLEAN bump, which a re-issue gets past, where `git clean -fdx *` gets the zone deny.** Bash splits `*>/dev/null` into the glob `*`, an operand, and the redirect `>/dev/null`; `tools/cc/hooks/_bash_patterns.py::_git_clean_operands` reads a token as a redirect only when it opens with a stream number or the operator (`tools/cc/hooks/_bash_patterns.py::_redirect_words`), so the glued token stays whole and names no zone. The PowerShell reading of the same token (that tool's `*` stream) is DEF-5108's. Found by the code review of DEF-5108's lane; driven through the wired hook on that lane's tree (the bump; `git clean -fdx *` and `git clean -fdx 2>/dev/null` each the zone deny). Who is hurt: an operator whose agent cleans the tree on the Bash tool with its output silenced, the harness's gitignored state under `cc/` among what the clean takes, behind one bump. Contract basis: the anti-self-disable floor (a delete of the harness's own state), plain syntax. Fix shape (probable): on Bash, read a token that opens with `*>` as the glob `*` and a redirect, in `_git_clean_operands` alone, off the per-call path of `tools/cc/hooks/_bash_patterns.py::_operands`; bash is its oracle.
