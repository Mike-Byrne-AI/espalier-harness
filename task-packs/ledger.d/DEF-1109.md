| `DEF-1109` | espalier/assets/claude/workflows/_fanout_audit.js (args prelude, Discover phase); espalier/assets/claude/workflows/_layered_review.js (SCOPE default); espalier/assets/claude/workflows/_convergence_review_template.js (args catch) | **`_fanout_audit.js` turns an argument it cannot use into the widest default run, a recursive whole-tree pack audit, without a dry run, confirmation or finder cap.** The args prelude maps an unparseable string to `A = {}` (`catch (e) { A = {} }`), and a valid JSON value that is not an object or an object with a misspelled key (`target` for `targets`) binds neither `finders` nor `targets`, so the Discover phase shells `find task-packs -name "TP-*.md"` (recursive, `Done/` included) and fans out one finder per hit, then one refuter per candidate, then a persist agent. The most likely trigger is a plain path string such as the path of one pack file; the sibling `_layered_review.js` accepts a plain string as its scope, and the fan-out workflow's description states no args shape. The scaffolds do log the resolved count or scope just before launching, so the defect is the missing gate, not missing logging: the host's approval prompt fires before targets resolve, and in auto, bypass and headless runs it does not ask again. Two secondary loci are low: the convergence template's catch falls back to the narrowest default (one smoke lens) and still appends a terminal row to `memory/CONVERGENCE_LEDGER.md`, and `_layered_review.js` now normalises an object arg (it reads `A.scope`), so only a misspelled key widens it to "the whole repository at rest", with a fixed finder count. Found by the 2026-10-03 adoption audit (`espalier-issues/audits/2026-10-03-adoption/public_report.md`, C-15); re-checked at `08ab2db`: LIVE for `_fanout_audit.js`; the layered-review object-arg claim does not hold at HEAD. Who is hurt: an adopter with many archived packs who passes args in the wrong shape and spends an N-agent, Opus-scale run, plus a corpus write to `reports/audit-findings.md`, on an invocation that read as a single-file request.
