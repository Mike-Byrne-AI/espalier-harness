| `DEF-2021` | tests/conftest.py::pytest_testnodedown (the went-down branch of the build report) | **In a run whose xdist workers crash, `tests/conftest.py`'s build report prints `xdist worker gwN FAILED: went down before it reported its build` for every crashed worker, whether its build failed, succeeded, or never ran.** `pytest_testnodedown`'s went-down branch fires on any worker that went down with an error and sent no build report. A worker's report rides `workeroutput`, which xdist delivers only when the worker finishes, so a worker the thread-method ceiling ends mid-run never reports a build that succeeded before its first test, and a run where no collected test asked for `initialized_repo_root` reports a build that never happened. DEF-2020's failure-mode review drove it on 2026-10-16: seven tests past a one-second thread-method ceiling at `-n 1 -q`, through the suite's own conftest, printed five such lines (gw0 to gw4) with no test asking for the tree. Who is hurt: an operator reading a Windows crash run's tail (a host check's `SUMMARY.md`, a seat's tier log) is told five times that the tree build failed, and chases the build instead of the ceiling crossings the `FAILED` lines name. Fix shape: the controller keeps, per worker, whether any test report arrived from it (xdist sets `report.node`), and prints the went-down line only for a worker that went down before its first report, the one case where the build can be what it died in; otherwise it says nothing, or that the worker's build report was lost with the crash. Pinned by a child run in which a ceiling crossing follows a passing test. No probe: see the row's why-not; the fix lane's child-run pin is the oracle. | minor | HYGIENE | MAINTAINER |
