| `DEF-5121` | tools/cc/hooks/_bash_patterns.py::_redirects_blanked (a redirect inside a here-string's quoted substitution) | **The tracked-tree wipe written as a loop fed by a here-string is allowed when the listing's double-quoted command substitution holds a redirect in git's option slot, where the same loop with the redirect last, or with none, meets the enumerator wall.** The redirect view (`tools/cc/hooks/_bash_patterns.py::_redirects_blanked`) blanks the redirects the token reader finds, and the token reader holds a double-quoted command substitution as one word, so a redirect inside it is never blanked and the loop readers (`tools/cc/hooks/_bash_patterns.py::iter_unnarrowed_loop_remove_roots` and the zone reader's loop arms) never read the listing's head. Found by DEF-2087's fix batch and driven through the wired hook at that lane's head: the redirect-inside spelling is allowed with no nudge; the plain and the redirect-last spellings wall. Who is hurt: an operator whose agent removes the tracked files one by one from a here-string listing with git's stderr silenced, an unusual spelling, and loses the checkout's tracked tree unrefused. Contract basis: a catastrophic delete (the tracked-tree wipe), plain syntax: the here-string, the double-quoted substitution and the redirect are ordinary syntax, and the hiding element sits inside the program text, not in a wrapper's argument slot (air's ruling a87b6c, on 5c1e1c and 40ec7f). Fix shape (probable): let the view read inside a double-quoted command substitution, blanking the redirects of the program it holds while a quoted mention outside a substitution stays data, with a row per loop carrier and the quoted-mention controls; its cost is measured against main with `scripts/guard_cost_census.py` before it lands, since that reading runs on every call that holds a quoted substitution.
