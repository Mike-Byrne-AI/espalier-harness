| `DEF-5106` | tools/cc/hooks/write_guard.py::_secret_read_targets_one (a command substitution's body) | **The Bash secret-read leg never reads a command substitution's body as a program, so a read inside `$(...)` or backticks draws no refusal at a statement's head (`$(cat .env)`) or among another verb's operands (`echo $(cat .env)`, `` echo `cat .env` ``, `echo "$(cat .env)"`), where `cat .env` is refused.** Bash runs the body first, and its output reaches the transcript through the outer command's output or, at a head, through the not-found error that names it. `tools/cc/hooks/write_guard.py::_secret_read_targets_one` cuts words at `(`, `)` and the backtick and reads one head per statement: a `$(` opener leaves `$` as the head, which is no read verb, and a body among operands is read as the outer verb's operands, which a verb off the roster never reads. The backtick form at a head is refused only because the cut leaves the body's verb first, and an assignment's value (`x=$(cat .env)`) is refused because the assignment word is skipped. Found by the code review of lane/an-empty-substitution-hides-no-secret-read (DEF-2074) and driven at the reader on that lane's head; filed apart from DEF-2074 on air's ruling (ack 202638): one class across both openers and both positions (Standing Principle 18), and its operand half needs a reader for substitution bodies. Who is hurt: an operator whose agent prints a secret through a substitution, `echo "$(cat .env)"` or a bare `$(cat .env)` line, with no refusal. Contract basis: the secret-read leg, plain syntax. Fix shape (probable): read each substitution body, both openers, as a statement of its own with the Bash roster (the PowerShell leg reads its `$(...)` subexpression that way), in place of the head-only read. The false-deny population it must run: the heredoc-in-substitution commit idiom (`git commit -m "$(cat <<'EOF' ... EOF)"`), whose heredoc body is data even when it quotes a read, and the commit messages and pull request bodies that name dotenv files.
