| `DEF-684` | scripts/derived_population_census.py::_source_bindings (the one-hop alias pass iterates `tree.body` only) | The derived-population census cannot see a function-local alias of a source container, so binding the population to a local inside a test retires its census row without adjudication. Driven through the census's own helpers on three synthetic sources: a direct `_hook_utils.X.items()` iteration yields one row, a module-level alias `X = _hook_utils.X` yields one row (the one-hop pass's stated purpose), and the same alias bound inside the test function yields zero, because that pass iterates `tree.body` rather than function bodies. Moving a binding one line into the function is therefore the cheapest way to clear a census red. Who: a maintainer whose derived-population gate silently loses coverage one local at a time. Fix: extend `_source_bindings` to walk `ast.FunctionDef` bodies for one-hop aliases of an already-bound root, and add a negative fixture -- a function-local alias that must produce a row -- beside the module-level one. | minor | LOGIC_BUG | MAINTAINER |
