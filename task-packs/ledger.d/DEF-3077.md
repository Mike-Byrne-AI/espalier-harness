| `DEF-3077` | tools/cc/hooks/_bash_patterns.py::_INTERP_PIPE_RE (an output redirect; the shell head's case and .exe) | **A program piped into a POSIX shell is not read when the shell carries an output redirect, or when its head is spelled in another case or with `.exe`, so a delete of the root echoed into it is a plain allow beside the walled bare pipe.** Found by win-2's #600 lane (residue candidates 1 and 2, 2026-11-12), ruled one row by air (413ebb) and filed in its fix lane (assign bae91f). Driven on Git Bash 5.2.37 with a harmless program: the shell ran the piped program behind stdout sent to a file, appended, clobbered or joined to stderr, behind `&>`, behind a quoted target, with the redirect glued to the head, and under an upper-case head, `bash.exe`, `Bash.EXE` and `sh.exe`; an input redirect on stdin made the file its program instead. Judged in process at origin/main 43d8879: the bare pipe walls, and the stderr-joined and the upper-case `.exe` forms allow. Cause: `_INTERP_PIPE_RE`'s trailing lookahead ends the statement only at a separator, so any redirect after the shell refuses the match, and group 2 reads the shell head bare and lower-case, where the `-c` reader reads it case-blind with `_EXE_SUFFIX` (DEF-1161's class). Who is hurt: an operator whose agent pipes generated text into a shell and silences or captures its output, or names Git's shell by its file name on Windows. Contract basis: catastrophic delete, one level of a literal launch wrapper (a program piped into a shell); nothing declares it a limit. Fix shape (probable): the lookahead takes a run of output redirects before the separator, an input redirect keeping the pipe as data, and the head reads as the `-c` reader's head does. The probe prints the wall's answer for the delete piped to a bare `bash`, to `bash` with stderr joined, and to `BASH.exe` (`True False False` while the defect stands). | major | LOGIC_BUG | ADOPTER |
