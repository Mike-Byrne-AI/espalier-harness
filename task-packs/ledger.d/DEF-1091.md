| `DEF-1091` | tools/cc/hooks/_hook_utils.py::_telemetry_enabled; tools/cc/hooks/_reinject.py::_log_recall_event; tools/cc/hooks/_recall.py; scripts/recall_eval.py | **Recall telemetry is hard-gated to the Espalier source repo with no opt-in, and the recall eval is not shipped, so an adopter who folds its own knowledge into the recall homes has no way to measure whether `/recall` finds it.** `tools/cc/hooks/_hook_utils.py::_telemetry_enabled` returns `is_self_host_repo(root)` outside a pytest run, and both writers depend on it: `_reinject._log_recall_event` on the push side and the `_recall` CLI shim on the pull side. `ESPALIER_TELEMETRY_UNDER_TEST` is not an opt-in of any kind; it only lifts the pytest suppression and the self-host test still applies, so an adopter has no path at all. The gate is a consent decision (the pull side records raw query text), so it should not be lifted by default. The larger gap is the instrument: `scripts/recall_eval.py` and its drift test are source-repo only (the shipped `implement-task.md` labels it so), `_recall.py`'s ranker table is calibrated on the live Espalier corpus, and the shipped `/recall` command quotes rates measured on that corpus, so an adopter runs a ranker tuned on someone else's corpus with no shipped way to pre-register queries with accept sets and re-check them after a fold. Found by the 2026-10-03 adoption audit (`espalier-issues/audits/2026-10-03-adoption/public_report.md`, A3-8); re-checked at `08ab2db`: LIVE. The audit's primary seam is the missing eval and the telemetry gate is secondary. Telemetry alone would not answer "did my fold work": the pull row's `matched` field is a nearest-neighbour flag, not a hit rate (the self-host log shows 814 of 820 queries matched), and nothing reads the log back. The reader and the effect measurement are `INV-3` and `INV-4`'s (open); this row is the adopter-side opt-in and the shipped eval. Who is hurt: an adopter who has moved their knowledge into `memory/` and `docs/SHARP_EDGES.md` and wants evidence that `/recall` returns it, and who cannot get raw queries recorded or a repo-owned eval run without editing the harness. Fix shape: an explicit, default-off, local-only `recall_telemetry` key in `espalier.toml`, read by `_telemetry_enabled` without any engine import (the default stays off, which keeps the consent posture); and a minimal shipped `recall-eval` command that reads a repo-owned query file (a query plus an accept set) and reports top-1 and top-3, so the check can be pre-registered and re-run after each fold. | nit | LOGIC_BUG | ADOPTER |
