| `DEF-5109` | tools/cc/hooks/session_start.py::_warn_if_nested_repo_litter (prescribes git worktree remove --force for a leftover worktree that holds changes) | **SessionStart's nested-repo warning tells the operator to remove a leftover agent worktree with `git worktree remove --force`, which drops the uncommitted work it holds.** `tools/cc/hooks/session_start.py::_warn_if_nested_repo_litter` names every untracked nested repo `_find_nested_repo_litter` finds and prescribes one remedy for all of them: `git worktree remove --force <path>` (after `git worktree unlock` if locked), or deleting the dir. It leaves out only the worktrees the catch-up's reaper already named (`covered`), so the warning reaches a worktree under `.claude/worktrees` whenever the reaper did not judge it: catch-up off (the adopter default, `session_catch_up` unset in `espalier.toml`), or a `resume` or `compact` start. Claude Code leaves an agent worktree behind only when it holds changes, and `init` does not gitignore `.claude/worktrees` on an adopter tree, so the worktree this line names is the one that holds work. Driven 2026-11-14 at origin/main 3548e80 in a temporary repository: a linked worktree at `.claude/worktrees/agent-x` holding one uncommitted file is named, and the line prescribes `--force` for it (the probe prints `True`). Who is hurt: an adopter with catch-up off, after a session that used the Agent tool's worktree isolation ends with an agent's changes unmerged, who follows the banner's remedy and loses those changes. Found by the failure-mode review of the DEF-4108 lane (note 9ca2a7); filed as its own row, not fixed there, by ack 4a3170. That lane widened the reach to the start-time lock form the Mac's Claude Code writes (a dead holder's lock in that form now reads as dead, so its worktree is no longer kept as a hand lock); the bare form reached it before. The fix shape is open: the remedy needs its own oracle (whether a named worktree holds changes, read without a new spawn per entry under SessionStart's wall), and the probe reads only whether `--force` is prescribed for a worktree holding an uncommitted file, so a fix that keeps the word with a caveat repins it. | major | LOGIC_BUG | ADOPTER |
