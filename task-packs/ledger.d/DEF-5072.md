| `DEF-5072` | tests/test_reinject_sync.py::TestMirrorCensusCoverage::_row_linked_parts (the positional link) | The identical-bytes mirror census links a group's members by position, as `espalier/mirror_registry.py::counterpart` does, so a curated row (`asset-docs` and `claude-asset`, both `kind=subset`) covers its whole source tree there: a hand copy of a file the row's sync never copies -- a `docs/x.json` beside `espalier/assets/docs/x.json`, or a `.claude/` file outside the four mirrored kinds beside its copy under `espalier/assets/claude/` -- reads as linked while nothing pins it. `tests/test_deploy_doc_parity.py::TestSourceAssetDocByteParity` reads `*.md` only (`:269`), and the census's own docstring defers such a pair to the curated rows' parity tests, which never read it. A maintainer who ships a non-markdown file by copying it into the asset tree gets a green census and two copies that drift, and the wheel ships the stale one. No live instance today: `git ls-files espalier/assets/docs` holds only `.md`. Fix shape: link a curated row's member only where the row's sync or pinning test reads it (the sync's own selection), or report a link that is positional only apart from one a test pins. The probe drives `_row_linked_parts` on that synthetic `.json` pair and prints 1 (one part, read as linked) while the census links by position alone. | nit |
