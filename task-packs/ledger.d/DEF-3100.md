| `DEF-3100` | tools/cc/mail.py::send (a send from a checkout whose seat name another checkout answers) | **The mail writer sends from a checkout whose seat name another checkout of the clone also answers, so a session in a seat's twin writes the seat's mail ref beside it and the dispatcher reads the two as one seat.** `tools/cc/mail.py::send` reads the name it writes under with `::machine_setting` in its own checkout and checks only that the message is from that name; the one twin refusal on the channel is `::assign_refusal`'s, for an `assign` from a linked worktree still answering its clone's name. Driven 2026-11-17 on this box, in a scratch clone `box` with two worktrees each given `box-x` through per-worktree config: `mail.py send --type note --text probe --dry-run` run in the first prints the message from `box-x` and exits 0. How twins arise, driven the same day on git 2.52.0: `git worktree add` run inside a named worktree copies its per-worktree config into the new one, so a scratch copy a seat adds from its own checkout answers that seat's name; two live instances in two days (air-work's `base711`, air's cf1b9f; win's `C:/tmp/wt2069`, air's 89d325). DEF-3098's lane makes the twin visible to the readers (`::checkout_names`: the board flags it while a session holds it, `tools/cc/seat.py::resolve` refuses the name, docs/SHARP_EDGES.md "The worktrees of one clone share its machine name" says how to avoid it); the writer is the one place the two sessions meet, and it still writes. Who is hurt: a seat whose scratch copy holds a session (a reviewer, a probe run inside it): both write one mail ref under one name, so a claim, a release or a stop from the copy reads as the seat's, and the dispatcher's assignments and `under two:` count fold them into one seat. Contract basis: one writer per shared state, isolated in the tool (Core Rule 14), and a seat is one session in its own named checkout (Core Rule 15). Fix shape (probable, at the writer, air's 89d325): before it writes, `send` reads the checkouts answering its name through `::checkout_names` and refuses where another one answers it, naming each with the rename (the seat driver's twin refusal, DEF-3097, is the model); whether a dormant twin refuses too, or only one a session holds, is the fix's call to price (a dormant one stops the live seat's mail until it is renamed; the board flags only a live one). Price, read before it is built, this box (28 listed checkouts, 12 present, 7 rounds, medians): `::checkout_names` 0.212 s (0.203 to 0.261) against the 0.015 s `::machine_setting` read `send` makes now, so about 0.2 s more a send here, one more git call per present checkout; the fix's own cost is unread until it is built.
