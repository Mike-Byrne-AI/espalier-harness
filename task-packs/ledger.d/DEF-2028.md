| `DEF-2028` | tests/test_box_lock.py::TestTwoRunsOnOneBox and ::TestTheInheritedPair (a Popen pid compared across the Windows venv redirector) | **Under a Windows venv, three `tests/test_box_lock.py` cases compare a spawned run's `Popen.pid` with the pid the run records, and the venv's `python.exe` is a redirector that starts the interpreter as its own child, so the two never match and the cases red against a lock that works.** `_spawn` and `TestTheInheritedPair._holder` launch through `sys.executable`; under a Windows venv that is `.venv\Scripts\python.exe`, which runs the base interpreter as a second process, so `Popen.pid` names the redirector while the lock record's `pid` is the interpreter's `os.getpid()` (`tests/_box_lock.py::build_record`). Measured on the win box at 273a0ea (a venv over CPython 3.11): `TestTwoRunsOnOneBox::test_the_second_run_waits_names_the_holder_and_runs_after_it` reds on `f"pid {first.pid}" in err` (the line named pid 25476, `first.pid` was 46408), `::test_every_wait_leaves_one_log_line_and_a_run_that_did_not_wait_leaves_none` on the wait log's holder pid (45432 against 50644), and `TestTheInheritedPair::test_a_child_of_the_live_holder_passes_through` on `holder.poll() is None`: the pair names the redirector's pid, which is no record's, so the child waits instead of passing through until the holder's own 40 s deadline frees it. The waiting line printed in time in each, so this is not `DEF-2027`'s class. These are the three `test_box_lock` names this box's full tier has carried as baseline (win-2's note bb9ae4, 2026-10-29; `#373`'s body); CI's windows-latest leg passes them because its interpreter is no venv. `tests/_interpreter_hosts.py::HOOK_PYTHON` (the base interpreter) is the suite's fix for a pid asserted across the redirector, but these children run `pytest -n 1` and the base interpreter does not see the venv's site-packages (no `xdist` there, read 2026-10-31).
