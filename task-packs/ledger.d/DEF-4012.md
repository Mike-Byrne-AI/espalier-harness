Found 2026-10-09 at the A-1 lane's CI fix; a prune was built and withdrawn in that lane because its two reviews found, in scratch trees, that planting a `.git` under a watched directory would leave it unwatched for every later session, that a directory becoming or ceasing to be a checkout reports its files as removed or added while they sit on disk, and that a protected top that is itself a checkout still reports its own git's moves. Who is hurt: an adopter who protects a directory holding a vendored clone or a submodule and updates it from a shell call, and is told to stop for a change their own command made on purpose -- the guard's one right response to a report is to stop, so a false report costs the operator a halt and teaches the agent to read the report as noise. No adopter has reported the case (named, not seen). Fix shape, two designs for its Task 0: (a) a prune below adopter prefixes only, with the pruned checkouts stored in the baseline so a directory entering or leaving the set restricts the comparison; (b) an accounting path that asks the nested checkout's own git for the blob at its `HEAD`, which needs no prune.
