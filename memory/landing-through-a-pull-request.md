Root `CLAUDE.md` Core Rule 10's whole text as of `97eb886f`, moved here when the
rule was cut to its imperative and a pointer (the root CLAUDE.md slim),
verbatim but for one retired clause: "so `/commit`'s branch-first and `gh pr

Self-host dev lands harness self-edits on `main` through a branch and a PR: the public repository's branch protection requires a PR with its required checks green and enforces it on admins (eight checks at the 2026-09-25 cut; thirteen since 2026-10-01, when the five `test-serial` cells joined the required set after the lane that added them merged; eleven since 2026-11-07, when the two `(3.10)` cells left with the floor's move to 3.11). Arm auto-merge with a merge commit (`gh pr merge --auto --merge`) and keep working; `/ship` runs that whole sequence through `tools/cc/ship.py` (the same on every device), with the marker bound at creation, so the branch is never typed and no title edit races the push -- and a session runs it once per lane, as `/handoff`'s last step, so the handoff's row rides the same push (eight handoff-only pull requests since the cut were the cost of the other order); and the turn that commits a lane's finished work runs `/handoff` itself, never leaving it for the operator to type (`stop_gate`'s Gate 5 holds the Stop once per commit while nothing is in flight and the lane holds commits origin does not, maintenance mode included: a lane finished at 05:13 and left that way sat unpushed, unrowed and claimed for eleven hours, 2026-10-24). The up-to-date rule was on from 2026-09-27 to 2026-10-09 and is off since: a PR merges on its own green CI, which tested it merged with `main` as of its last push; `.github/workflows/post-merge.yml` proves `main` after every merge (each push's run goes to the end, beside the next one, so a red run's suspects are the merges since the last green run before it -- one, unless a run between them is red, still going or ended with no verdict -- and `/inbox board` names them), and a red `main` is reverted before anything lands on it (Core Rule 15). Only `TP-479`'s pre-registered re-measure re-opens the rule, and the live setting is the banner's to print, never this sentence's. A PR that conflicts with `main` waits until the driver's `catch-up` verb merges `main` in and re-binds; the banner's `Open PRs:` line says so, and names the required red that holds a blocked one. The gate is the four `test (3.x)` cells and their four `test-serial (3.x)` twins, and each runs the tier the PR earns (`scripts/proof_tier.py --base`, the same rule as the local run): the contract slice for docs, tests and scripts; that plus the recall files for a corpus change; the full tier for engine, hook and workflow changes, its parallel leg in the `test` cells and its serial leg in the `test-serial` cells beside them, with `clean-checkout` alongside on the floor interpreter in its own workflow (the heavy end-to-end stages' one CI home; the per-pull-request tier left them out on 2026-09-30, when the stage-one smoke measured 848 s of a 992 s parallel leg in a cell). Measured on PR #3 before tiering: 19 minutes open-to-merged, cells 9 to 18 minutes on the not-slow slice. How long a full-tier cell takes is the bounds census's to print, never this sentence's (`python3 scripts/ci_job_bounds_census.py`: each job's worst and median green cell over its last 20 runs, beside its `timeout-minutes`); a cell is suspect past that worst, or when `gh run view <id> --json jobs` shows no step in progress. (Until the cut this rule said the opposite — commit straight to `main` — for the private archive tree, which had no protection.)
