# A hand-written count that moves on ordinary growth is tax

**Status:** active
**Linked from:** ESPALIER_MEMORY.md row "A hand-written count that moves on ordinary growth is tax"

A pinned number earns its place when it moves only because the thing it pins
changed. A number that moves because the repo *grew* -- a corpus of memory
notes, a bench corpus, a script inventory, a pattern tuple -- is a copy the
author re-types after every lane, and each copy is one more site a full-tier
red points at. Measured over 2026-09-01..09-09 on this tree: the bypass-class
count moved five times (four edits and a post-commit re-pin each), two
freshness fragments bound to constants were re-pinned twice at unchanged
values because every lane touched their file elsewhere, one added memory note
moved a pasted `too_short` cell from 20 to 22 under a 3% band and reddened
the tier, and a new script was one more literal to bump. Together they took
15 to 35 minutes of every lane.

## Sort the number first, then choose the fix

- **Derivable from its source** (a tuple's length, a glob's count, a roster's
  size): derive it (STANDING_PRINCIPLES §14). The doc sentence that states it
  is the consent gate -- it reds until a human edits it -- and a *deleted*
  source row reds the same sentence, so the deletion tripwire the literal gave
  is kept. Do not keep a second recorded copy that nothing reads: it was the
  fourth copy, and only a parity belt ever looked at it.
- **Provenance** (the corpus size a table was swept on, the arm it measured):
  band it wide -- the larger of five documents or a tenth of the pasted value
  -- so a re-paste is owed when the population has materially changed, not on
  every note.
- **The claim itself** (a rate, a peak, a cell that says "nothing is dropped
  here"): keep the band tight (three points; a tiny cell keeps half its
  value). A rate moves only when the mechanism moves.
- **The denominators of the claims** (an arm size) get a *share* of the
  population under the tight band, and coverage gets its own oracle (an
  on-disk listing per root against what the loader yielded). A wide count band
  alone hides a skipped root: corpus and arm shrink together, inside a tenth,
  while the rates hold.
- **A drift signal keyed on a file** when the claim is about a symbol: key it
  on the symbol's own lines (`git show HEAD:path` for the span, `git log -L`
  back through history). Two fragments re-pinned weekly at unchanged values
  read fresh the day this landed, and the three that read stale on file-level
  noise read fresh too.

## A literal shape ages like a literal count

A pin on the SHAPE of a curve -- `steps == [0, 2, 0]` over the slots of a
paraphrase sweep -- is a count in disguise: every step is a difference of two
counts that move on ordinary growth. The recall lane (2026-09-12) re-pinned
that literal for the fourth time (08-20, 09-03, 09-04, 09-12), and its own
comment had said on 08-20 that a third red for corpus drift means the pin is
measuring corpus size and wants re-deriving as a shape. Driven: of the 25 most
recently added memory notes, removing any one of four moves the steps, and the
recall tier now runs the test on every memory commit. Honour the escalation
rule the pin already wrote -- assert the property (never falls; six slots reach
further than two), keep the recorded curve as a dated record beside the
constant -- rather than adding a fifth prose paragraph under a fifth literal.
The tell is the pin's own history: three dated re-pins in a comment is the
third red.

## What to keep as a literal

A deletion tripwire on a population that grows *rarely and deliberately*
(hook helpers, agents) is a legitimate literal witness -- the test side is
independent of the producer, which a derived count can never be
(`tests/_surface_expected.py` marks these `# class: literal`). The test is
whether the population moves on ordinary work: scripts did (five in nine
days), so the count became `len(roster)` and the roster stayed the literal.
