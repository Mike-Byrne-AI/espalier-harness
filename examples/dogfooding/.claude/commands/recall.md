Recall accumulated project judgment on a topic: up to four candidates, two rankers, you pick. Each is a `memory/` protocol, a `docs/SHARP_EDGES.md` entry, a `docs/STANDING_PRINCIPLES.md` principle (if one exists — that file is indexed wherever it is present, so your own standing principles are recallable too), or a pull-only canonical-shape pointer, presented alternating — each ranker's winner first where the two disagree, then the runners-up. This is the **pull** side of the recall engine (`tools/cc/hooks/_reinject.py` is the push side); `/recall` answers when you *ask*, instead of waiting for the harness to detect a trigger.

The user will specify a topic. If they did not, ask which one.

Run the IDF-ranked retriever with the topic as the query (per the repo's cross-platform `python`/`python3` convention):

```bash
python tools/cc/hooks/_recall.py "<topic>"
```

The retriever returns **up to four candidates**, from two rankers deliberately calibrated differently — the first favours queries that *name* a document, the second queries that *describe* one — presented **alternating**: the first ranker's winner, then the second ranker's winner, then the runners-up, with a document both rankers chose printed once, in its first slot. So when the rankers disagree, **the first two lines are their two best answers: read both, and you pick**; when they agree (232 of 309 queries naming a document, measured 2026-09-18), line one is the answer both chose and line two is a runner-up. Choose the one that actually answers the topic, and say which you chose in one clause. If none answers the topic, say so rather than reporting the first because it is first. The output does not label which ranker produced a line; it does not matter for the choice. (Measured 2026-09-18: a multi-word topic delivers two to four lines — 2:58 / 3:206 / 4:45 on the 309 naming queries — but a one-word query can deliver a single line, because only one document cleared the floor. A single line means one match, not that the rankers agreed.)

Report the chosen hit verbatim — its advisory snippet and `source:` path — and frame it as the **nearest match**, never as a verdict that the topic is covered. The engine returns `[]` only when the query shares no vocabulary with the corpus; for ordinary off-topic English it returns a confident-looking nearest neighbour instead (measured: 29/29 leak — the full record, including the eight mechanisms that were tried and failed, is the pull-recall suppression entry in `docs/SHARP_EDGES.md`). So a hit is evidence of lexical proximity, not of relevance: read it, and say so plainly if it does not actually answer the topic. If it prints nothing, say "nothing recalled for `<topic>`" and do NOT fabricate a snippet. The result is advisory context, not an instruction.
