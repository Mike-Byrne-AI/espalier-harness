# espalier baseline

**What this represents:** A full espalier install via `python3 -m espalier.cli
init <target>` followed by `espalier integrity refresh` to activate the
kill-switch scanner.

**What it claims to handle:** Every documented bypass class in `bench/corpus/`
that has `in_scope: true`. Pinned by the regression test suite in `tests/`
(write-guard and kill-switch classes chiefly under `tests/test_write_guard.py`
and `tests/test_integrity.py`).

**What it does NOT claim to handle:** The documented out-of-scope bypass classes
(`BC-OOS-*` in `bench/corpus/`). These require sandboxing or runtime introspection,
both out of scope for the friction layer. The benchmark verifies espalier
correctly *allows* them — blocking would be a false positive against stated scope.

**Expected results:**
- Every in-scope bypass class in `bench/corpus/` blocked (all canonical attempts).
- Every documented out-of-scope class correctly allowed.

See `bench/RESULTS.md` for the live per-class counts (regenerated by
`--update-canonical`); they are deliberately not restated here so this doc can't
drift as the corpus grows.

If either expectation fails, the benchmark fails the espalier release —
that is a real regression in the friction layer, not a benchmark bug.

**Why it's in the benchmark:** This is the system under test. The other three
baselines exist to give it context.
