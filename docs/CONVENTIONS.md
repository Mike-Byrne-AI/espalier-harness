## Directory Layout

- `.claude/` — CC configuration: agents, commands, settings.json
- `tools/cc/` — Hook scripts and standalone tools. Zero espalier imports.
- `espalier/` — Harness engine. Imports only from espalier/.
- `espalier/scanners/` — stdlib-only scanner modules.
- `cc/` — Reference surface, governance docs, blueprints.
- `reports/` — Analysis outputs (repo_fingerprint.json, harness_config.json).
- `bench/` — Adversarial bypass benchmark (downstream consumer of espalier/ + tools/cc/; subprocess-only, no Python imports across the boundary).
- `tests/` — pytest test suite.
- `scripts/` — Release tooling. `scripts/build_release_archive.py` builds the deterministic `.zip` release artifact.

## Subsystem Pattern: Corpus + Runner + Canonical Output

`bench/` is the first subsystem to pair documented input data with a runner
and a regenerable canonical output file. If a future subsystem follows the
same shape, mirror the layout:

- `<sub>/corpus/` — one JSON file per class, each citing the source-of-truth
  test class via a `documented_in` field
- `<sub>/run_*.py` — stdlib-only runner that loads the corpus, exercises it
  against the comparison configurations, and emits results
- `<sub>/RESULTS.md` — committed canonical output, regenerated by the runner
  with an `--update-canonical` flag; the flag must reject partial runs
- `<sub>/baselines/<name>/{setup.sh, description.md}` — one directory per
  comparison configuration (in `bench/`: `no-governance`, `settings-deny-only`,
  `minimal-hooks`, `espalier`)
- `<sub>/results/` — timestamped runtime artifacts (gitignored)

Subsystems that live outside `espalier/` and need to invoke harness components
should do so via subprocess, not Python import — the `tools/cc/` isolation
discipline applies in spirit, not just to that directory.

## Code Style

- `from __future__ import annotations` at top of all `espalier/` files
- Type hints on all public functions: `def foo(x: int) -> str:`
- `_private` prefix on internal helpers
- Specific exception types only — never bare `except:`
- Advisory output: `print(..., file=sys.stderr)` — never to stdout (hooks only; CLI commands may write to stdout)
- Block output (hooks): JSON on stdout — never to stderr

## Agent Design Conventions

- Count follows function — add an agent when a domain needs dedicated context, remove
  when roles merge cleanly. Espalier-Harness currently runs 7 agents covering: architecture,
  code review + convention drift, docs, harness config, repo analysis, test generation,
  and internal-failure-mode finding (failure-mode-reviewer).
- Every agent gets: YAML frontmatter, role definition, working directory instruction,
  FACT/INFERENCE/SPECULATION requirement, numbered protocol phases, structured output.
- Model assignment: Opus for reasoning-heavy (design, diagnosis, interpretation).
  Sonnet for mechanical (review, scanning, test generation).
- Each agent has at least one executable bash block — not abstract instructions.
- **Dispatch spelling.** A body, a command or a gate message dispatches an agent
  by NAME — `subagent_type='<name>'` — and never names the tool (`Task`, renamed
  `Agent` in Claude Code 2.1.63: the parameter survives a rename, the tool name
  does not). The operator-typed form is the documented mention, `@agent-<name>`.
  Pinned by `tests/test_skill_delegation_parity.py::TestNoBodyNamesTheSubagentTool`
  (bodies) and `tests/test_denial_reason_actionability.py::TestAgentDispatchIsSpelledOneWay`
  (gate messages).
- **Agent isolation.** Spawn a mutate-capable agent (Write / Edit / `Bash(git *)`
  or any file-writing Bash) with `isolation: worktree` when it runs concurrently
  with other work or when its side-effects must not touch your live tree. Keep
  review/audit agents read-only (Explore, or Bash scoped to status/diff/log/show)
  — do NOT worktree-wrap them; worktrees cost ~200-500ms + disk each and read-only
  lanes need the live diff. After any git-capable agent returns, re-verify
  `git status` / `git diff --cached` and re-run the relevant gate before trusting
  a pre-agent green result. See `docs/FAILURE_MODES.md` §16.1.

## Command Design Conventions

- Count follows function — commands should map to real recurring tasks. Espalier-Harness
  currently has 17 always-loaded commands covering the full harness lifecycle, plus
  9 on-demand skills. The canonical counts live in `tests/_surface_expected.py`
  (`EXPECTED_COMMAND_COUNT` / `EXPECTED_SKILL_COUNT`).
  Remove commands when they duplicate sub-modes of another
  (e.g. `/godfiles` → `/scan godfiles`).
- Commands reference real paths in THIS repo, not placeholder paths.
- **A step an adopter cannot run is disclaimed with an INLINE PARENTHETICAL, on
  the line of the mention.** A shipped command body may name a path `espalier
  init` does not deploy — `scripts/*.py` most often — and the reader has to be
  told, because the body is instructions and Claude follows instructions.

  The form is load-bearing, not stylistic. `tests/test_adopter_pointer_resolution.py`
  exempts such a mention by recognising the prose itself
  (`_NOT_DEPLOYED_MARKERS`: `not deployed`, `self-host only`, `espalier source
  repo`, `source repo only`, `in the source tree`) within `_MARKER_WINDOW = 2`
  lines. That window models a parenthetical that lands on the mention's line, or
  the next when a sentence wraps.

  ⚠ **A disclaimer in the STEP HEADING is invisible to it.** Writing
  `## 7b. Snapshot the record *(self-host step — an adopter has no scripts/)*`
  is clearer to a human and unreadable to the gate: the mention sits 20-odd lines
  below. Three such annotations exist today and none is recognised. Prefer the
  parenthetical at the mention; a heading disclaimer is a bonus, never the only
  one. Tracked as `DEF-627`.

  ⚠ A mention inside a ``` fence is not seen at all — `strip_fenced_blocks` blanks
  fences before the scan — so the disclaiming prose must sit OUTSIDE the fence.
- **A command's description is cut twice before anyone reads it.**
  `cli._first_sentence` takes the first sentence or 100 characters for the
  generated `CLAUDE.md` table, and the slash-command menu cuts near 97 (observed
  at 97 characters of a 99-character sentence), so a correct body under a wrong
  or overlong first sentence is invisible to every session that loads the menu.
  Put the contract in a first sentence under 95 characters, and pin the
  *rendered* string through the renderer's own helpers (`cli._opening_paragraph`
  + `_first_sentence`) rather than a re-typed split, so the test cannot drift
  from the table it is asserting about —
  `tests/test_recall_eval.py::TestTheDeliveredShapeIsStatedAtEverySourceOfTruth::test_the_description_line_carries_the_shape_as_rendered`
  is the shape to copy.

## Hook Conventions

- Hook exit codes: 0 = the structured channel (decision JSON on stdout, or no output = "proceed"),
  2 = the simple channel (plain reason on stderr, no stdout JSON), 1 = script error (never intentional).
  Channel-XOR — see `docs/SHARP_EDGES.md`. Espalier-Harness hooks use exit 0 + JSON exclusively.
- Block JSON: `{"hookSpecificOutput": {"hookEventName": "...", ...}}` — see hooks for per-event format
<!-- espalier:fragment id=hook-count
     bound=espalier/harness_config.py::CANONICAL_HOOK_WIRING
     policy=numeric-contract -->
- All twelve standard hooks active: session_start, task_router, plan_guard, write_guard,
  config_guard, post_write_check, reflect_trigger, stop_gate, subagent_stop, post_compact,
  subagent_start, context_reinject_failure
- PreToolUse/PostToolUse matchers per hook (SoT: `harness_config.CANONICAL_HOOK_WIRING`):
  - `write_guard` (PreToolUse) and `reflect_trigger` (PostToolUse) use `"*"` matcher and filter
    internally against `MUTATION_TOOLS` (`{"Write", "Edit", "NotebookEdit", "Bash", "PowerShell"}` —
    plus `startswith("mcp__")` for MCP mutation tools)
  - `plan_guard` (PreToolUse) uses the narrow matcher `Write|Edit|NotebookEdit`
    (Bash and MCP writes are NOT plan-gated — `write_guard` still covers protected zones)
  - `post_write_check` (PostToolUse) uses the narrow matcher
    `Write|Edit|NotebookEdit|Bash|PowerShell|mcp__.*`
  - All other governance hooks use the matcher declared in `CANONICAL_HOOK_WIRING`
- Stop gate dispatches agents via the structured channel (exit 0 + `{"decision": "block", "reason": "..."}` JSON)
  — agent cannot stop until the gate is satisfied
- Hook-side scripts resolve repo root via `os.environ.get("CLAUDE_PROJECT_DIR", ".")` — `CLAUDE_PROJECT_DIR`
  is authoritative; `.` (cwd) is the fallback only when the var is absent (e.g., testing outside Claude Code).
  Standalone scripts under `tools/cc/` invoked by hooks or slash commands (e.g., `cognitive_blueprint.py`)
  follow the same `CLAUDE_PROJECT_DIR` → walk-up-for-markers → cwd order.
- **Env-isolation for harness-boundary subprocesses.**
  When a hook spawns a subprocess that itself reads `CLAUDE_PROJECT_DIR`
  (e.g., `cognitive_blueprint.py`, `reflect_protocol.py`), always
  pin the env explicitly:
  ```python
  env = {**os.environ, "CLAUDE_PROJECT_DIR": str(root)}
  subprocess.run([..., script, ...], cwd=str(root), env=env, ...)
  ```
  Without `env=`, the subprocess inherits the parent shell's
  `CLAUDE_PROJECT_DIR` — which under any Claude Code session points
  at the *operator's* repo, not the path the caller is targeting.
  Blueprint reads and writes silently route to the wrong repo.
  The footgun is documented in `docs/SHARP_EDGES.md` under
  "Subprocesses Inheriting CLAUDE_PROJECT_DIR"; this is the positive
  corollary. AST-scan contract:
  `tests/test_subprocess_env_isolation.py::TestHookSubprocessRoutingIsolation`.
- Flag files in `.espalier-state/` are ephemeral per-session state, cleaned by `session_start` on each new session:
  `session_started` (timestamp), `docs_refreshed` and `code_reviewed` (the relief records
  `subagent_stop` writes and the stop_gate hygiene gates read), `write_count`
- `ESPALIER_STOP_GATE` env var controls stop_gate mode: `light` (default, skips Gate 1 pytest) or `full` (runs pytest). Unknown values warn to stderr and fall back to `light`. Set per-shell or in `.claude/settings.json` under `env`.
- **Safe stdin reading (post-v0.6.6).** Every hook reads its JSON
  payload via `tools/cc/hooks/_hook_utils.read_stdin_safely()` —
  never via inline `json.load(sys.stdin)`. The helper decodes through
  `utf-8-sig` (silently strips a leading BOM, which is valid UTF-8
  but invalid JSON prefix) and returns `{}` on any decode / parse /
  EOF failure. This is the single SoT for stdin-tolerance behavior;
  the pre-v0.6.6 per-hook `try: json.load(sys.stdin) except (...)`
  pattern had divergent except tuples and missed BOM-prefixed JSON
  entirely (which would fail-open silently). A source-level contract test
  (`tests/test_hook_contracts.py::test_no_hook_uses_inline_json_load_stdin`)
  prevents the inline pattern from re-appearing in any canonical
  hook script.

## Testing Conventions

- Test files: `tests/test_{topic}.py` (topic is a module name or feature area — e.g. `test_hooks`, `test_edge_cases`)
- Test classes: `TestFeatureName` (PascalCase)
- Test functions: `test_{specific_behavior}` (no class prefix needed)
- Primary fixture: `tmp_path` from pytest; `monkeypatch` also accepted for env/attr patching
- `unittest.mock.patch` accepted for dependency injection (import inside test function to keep scope tight)
- Plain `assert` statements — not `self.assertEqual`, `self.assertTrue`
- Hook tests: run as subprocess, pipe JSON to stdin
- Scanner tests: call functions directly, no subprocess
- Marker taxonomy: eight markers — five **primary** (`unit` (default), `integration`, `contract`, `security`, `release`), exactly one per file, assigned by `_MARKER_RULES`; plus three **additive overlays** stacked on top of the primary marker — `slow` (via `_SLOW_FILES`), `heavy_e2e` (via `_HEAVY_E2E_TESTS`), and `full_tree` (via `_FULL_TREE_NODEIDS`). All eight are applied centrally in `tests/conftest.py::pytest_collection_modifyitems`; the overlays compose, so slices like `-m "slow and not heavy_e2e"` select against them. Files not matching any `_MARKER_RULES` pattern default to `unit`. Taxonomy declared in `pyproject.toml` with `--strict-markers`. The primary marker says what KIND of test a module holds; an overlay says what it COSTS, and the two are independent — a fast `integration` module stays in the `not slow` slice. The `unit` description is enforced in one half and self-declared in the other — not aspirational in either, but not symmetric: `tests/test_test_suite_contract.py::test_no_unit_module_spawns_a_child_process` reds if a `unit`-classified module shells out, and `tests/test_test_suite_contract.py::test_every_self_declared_slow_site_is_slow_or_exempt` reds if a site raises its own `pytest.mark.timeout` above the global ceiling without being marked `slow` at either granularity. Both derive their own populations and assert no wall-clock number.
- No hard-coded test counts in operator docs — enforced by `tests/test_test_suite_contract.py`. Use marker slices instead: `pytest -m security`, `pytest -m "not slow"`.
- **`ESPALIER_AUDIT_DIR` isolation pattern.** The autouse fixture in `tests/conftest.py::_isolate_audit_dir` redirects audit-log writes to `tmp_path/audit` for every test. Subprocess-based tests that construct their own `env` dict must `env.pop("ESPALIER_AUDIT_DIR", None)` (or override with their own value) before invoking the subprocess, otherwise the autouse value bleeds into the child process — rarely what the test intends. Live examples: `tests/test_security_regression.py`, `tests/test_kill_switch_blocking_surfaces.py`.
- **`# noqa: BLE001` is the deliberate-broad-except marker.** The project default is specific exception types only. When a broad `except Exception:` is genuinely needed (atomic-write cleanup that must re-raise; test fixture teardown; integrity scanner top-level "never crash on probe failure"), annotate the line with `# noqa: BLE001 — <one-line reason>`. Used 6+ times across `tools/cc/hooks/session_start.py` and elsewhere. Without the marker, the convention-drift audit flags the broad except as a finding.

### Live Self-Host Surface Tests Use the `initialized_repo_root` Fixture

Tests that exercise discovered self-host state — `surface_contract.discover_wired_hooks(...)`, `current_surface_report(..., mode="self_host")`, `espalier doctor .` via subprocess, `scripts/release_check.py` — depend on `.claude/settings.json` and `reports/*.json` being present on disk. Those are gitignored runtime artifacts produced by `espalier init`; a fresh clone (and CI) doesn't have them.

The pattern: use the **session-scoped `initialized_repo_root` fixture** in `tests/conftest.py`, not `REPO_ROOT`. The fixture mirrors the working tree into a tmp directory (sans gitignored runtime artifacts), runs `espalier init` against the copy, and prunes any profile-driven agent extras so the canonical 6-agent shape holds.

Reserve `REPO_ROOT` for tests whose intent really is *"this must hold of the source tree as committed"* — version-truth assertions, no-tracked-release-noise, exact count of committed `.md` files in `.claude/agents/` or `.claude/commands/`. Migrating those to the fixture would make the assertions tautological.

The companion SHARP_EDGES entry ("Tests Against the Live Self-Host Surface Need an Initialized Repo") documents the failure mode for each new test author.

## Single Source of Truth Patterns

These patterns concentrate "magic numbers" or repeated logic in one place so that bumps and future feature growth touch one file, not many.

### Surface cardinalities live in `tests/_surface_expected.py`

`EXPECTED_AGENT_COUNT_MIN`, `EXPECTED_UNIVERSAL_AGENTS`, `EXPECTED_COMMAND_COUNT`, `EXPECTED_SKILL_COUNT`, `EXPECTED_HOOK_COUNT`. Tests that assert cardinality must import from this module rather than hardcoding integers. Adding a new agent / command / hook means bumping the constant in one file. Per deploy-all semantics, agent assertions use `>= EXPECTED_AGENT_COUNT_MIN` (the universal floor) so profile-aware extras layered on top don't break the test.

### Hook-protocol assertions go through `tests/_hook_assertions.py`

Use `assert_hook_denied(result)` / `assert_hook_allowed(result)` for any hook regression test whose intent is "this must be blocked" or "this must be allowed." Asserting `result.returncode == 0` alone proves only that the hook didn't crash — it does not prove a deny payload was emitted. The helpers verify exit 0 + valid JSON + `hookSpecificOutput.permissionDecision == "deny"` (PreToolUse) or top-level `decision == "block"` (Stop / ConfigChange). Closes the false-pass class where a non-blocking hook is mistaken for a blocking one.

### Context-driven prefix policy via `tools/cc/hooks/_hook_utils.py`

The context-driven prefix helpers — `harness_protected_prefixes(root)`, `harness_exempt_prefixes(root)`, `harness_excluded_prefixes(root)` — return the universal harness prefix list with a self-host overlay (`espalier/` added) when `is_self_host_repo(root)` is true. Hooks that need to distinguish "this is the espalier-harness repo itself" from "this is a user repo using the harness" must call these helpers per request rather than read a module-level constant. The TOML name parser is strict (`[project]` / `[tool.poetry]` `name = "..."` only) so user repos that list `espalier-harness` as a dependency stay classified as user-repo — the safe default.

### Layout vs. content: `is_self_host_repo` is not a full-dev-tree proxy

`is_self_host_repo(root)` tests the code **layout** — `espalier/` + `tools/cc/` + `bench/` + the pyproject name + the `write_guard.py` hash. A *source release export* (`git archive` / GitHub "Download ZIP" / an extracted sdist) ships that whole layout, so `is_self_host_repo` returns **True for an export too** — even though the export **prunes** the tracked-but-`export-ignore`'d internal content (`ESPALIER_MEMORY.md`, the internal `docs/` ledgers, `.claude/workflows/`). Using `is_self_host_repo` as a stand-in for "the full dev tree is present" is therefore a category error: it makes a full-dev-tree check *run* against a pruned export and fail as a false negative.

When a check, tool, or gate must assert full-dev-tree invariants (committed-manifest completeness, `ESPALIER_MEMORY.md` anchors, workflow-schema parity), gate it on `surface_contract.is_release_export(root)` instead. That helper reads the `export-ignore` sentinels straight from `.gitattributes` — no hard-coded filename — and confirms an export *positively*: the layout is present **and** every tracked sentinel has been pruned. It is deliberately conservative (any uncertainty returns `False`, so callers keep running their dev-content checks — a loud failure on a real export beats a silent skip on a dev tree). `is_self_host_repo` stays correct for its own question — "is this the Espalier-Harness project?" — and is not being removed; it just must not be misused as a tree-completeness signal.

### Release archive classifier

`espalier.surface_contract.classify_release_path(rel)` is the SoT used
by every release-archive code path. Returns one of four labels:

- `"public"` — included in the release archive
- `"local_only"` — gitignored / per-session / experimental (e.g.
  `reports/`, `cc/blueprints/`, `settings.local.json`)
- `"internal"` — planning + internal docs (`TP-*.md` outside the two shipped
  pack locations, `task-packs/` root and `task-packs/Deferred/`, whose one home
  is `espalier/surface_contract.py::is_shipped_pack`; `BLUEPRINT*.md`,
  `docs/internal/`, `docs/session-archive.md`)
- `"transient"` — caches, build outputs, junk (`__pycache__/`,
  `.pytest_cache/`, `dist/`, `build/`, `.DS_Store`, `.venv/`)

Consumers:

- `espalier/release_pack.py::create_release_zip` — already routed via
  `is_internal_release_leak/is_transient/is_local_only`, plus one
  **report-only** pre-filter, `_is_pruned_from_walk`, that skips trees the
  report should not enumerate (the repo's own `.git`, virtualenvs, the
  release-matrix workspace). It runs *before* classification, so it is
  structurally a second exclusion authority — the shape that caused the v0.6.0
  leak recorded in `espalier/release_noise.py`. What keeps it safe is an
  invariant, not a convention: every path it prunes must also be rejected by
  the classifier, pinned by
  `tests/test_release_pack.py::TestWalkPruning::test_no_tracked_shippable_path_is_pruned`
  against every tracked file. If that test ever reds, the pre-filter has
  started removing payload and this bullet is no longer true.
- `scripts/build_release_archive.py::_classify` — delegates to
  `classify_release_path`
- `scripts/release_check.py::check_release_archive_builds_and_clean`
  — scans the built zip with the same classifier

`tests/test_release_archive_filtering.py` pins the classifier on every
known risky path and asserts build-vs-scan parity (the build script's
inclusion decisions and the scanner's offender check cannot disagree
because both call `classify_release_path`).

Wheel / sdist / release zip — three distributions, three policies
that overlap heavily but aren't identical:

- **wheel** — the Python package + asset resources (commands, skills,
  agents, hook scripts, harness-guard.yml). `pyproject.toml`
  `[tool.setuptools.package-data]` governs.
- **sdist** — source needed to rebuild the wheel. `MANIFEST.in` governs.
- **release zip** — clean public source snapshot. `classify_release_path`
  governs. Includes the harness package, scripts, docs, tests, bench/,
  CI workflows. Excludes everything labeled non-public.

### Local-only rolling logs — placement & the two-witness rule

A gitignored, local-only, append-only operator log (memory_candidate_log.jsonl,
reasoning_review_log.jsonl, finding_ledger.jsonl, born_weak_observations.jsonl)
lives in its emitting subsystem's directory. Two placement rules follow from
whether that directory also ships committed public files:

- **Mixed public/local dir** (`.espalier/` per BC-039; `cc/` per its public
  allowlist): the log MUST be enumerated by EXACT path in all three witnesses —
  `.gitignore`, `surface_contract._LOCAL_ONLY_PATHS`, and
  `release_denylist.DENIED_PATTERNS` — never a broad directory prefix, which
  would strip the committed public sibling (the BC-039 regression).
- **Pure-runtime dir** (`.espalier-state/`): a single whole-dir rule covers it.

Adding a new `.espalier/` or `cc/` runtime log means editing BOTH witnesses (and
the `GITIGNORED` parity test) in lockstep — omitting the second witness is the
classic sister-site miss: the first witness still prunes the archive, so the gap
stays invisible until an audit walks both witnesses against each other.

### Repo modes — `espalier doctor` semantics

`espalier doctor` classifies the repo into one of four modes and runs
mode-appropriate checks so a clean source checkout doesn't fail just
because gitignored runtime files haven't been generated:

- **`uninitialized`** — empty repo, no committed surface, no runtime
  artifacts. Doctor returns a friendly first-run guidance message
  ("run `espalier init .`").
- **`source_checkout`** — committed surface present (`cc/COMMANDS.md`,
  agents/, etc.) but no runtime artifacts (`.claude/settings.json`,
  `reports/*.json`, `.espalier/`). A fresh `git clone` of a repo that
  ships its harness surface as source. Doctor passes (rc=0); skips
  checks that depend on runtime files. **CI runs doctor on fresh
  clones** — `.github/workflows/release.yml` uses
  `espalier doctor . --mode source-checkout` to make the intent
  explicit.
- **`initialized_self_host`** — runtime artifacts present in the
  Espalier-Harness repo itself. Full check.
- **`initialized_consumer_repo`** — runtime artifacts present in a
  user repo that has run `espalier init`. Full check.

`--mode auto` (default) detects from disk state. `--mode
source-checkout` forces source-checkout semantics; `--mode
initialized` forces full checks (useful to expose missing runtime
artifacts as the failure they would be in that mode). The detected
mode is included in the report dict so log readers can confirm which
classification ran.

Local runtime files are generated state, not required source files —
this is the operating principle behind the mode split.

### Named-state policies are the project default

When a function's behavior splits along a small, finite set of
disjoint conditions, encode that split as a **named-state policy** —
a tuple of explicit string constants returned by a single classifier
function — rather than an ad-hoc cascade of booleans. Three classifiers
landed this shape independently, which is the signal that the
convention is real:

| Classifier | States |
|---|---|
| `init` ownership policy (3 states) | `created`, `updated_managed`, `skipped_user_files` |
| `doctor._detect_repo_mode` (4 states) | `uninitialized`, `source_checkout`, `initialized_self_host`, `initialized_consumer_repo` |
| `surface_contract.classify_release_path` (4 states) | `public`, `internal`, `transient`, `local_only` |

Why this beats booleans:

1. **Reporting.** The state name shows up in init's printed summary,
   doctor's report dict, and the release archive scanner's output.
   Boolean cascades produce "yes/no" diagnostics; named states produce
   "this file landed in bucket X" diagnostics.
2. **Test parametrization.** Tests assert `assert classify(p) ==
   "local_only"`, not `assert is_X(p) and not is_Y(p) and not is_Z(p)`.
   Adding a fourth state breaks the parametrize list explicitly rather
   than silently re-routing existing inputs through a stale boolean.
3. **Single source of truth.** All consumers route through the
   classifier, never through their own re-derived boolean — the
   parity tests (`test_release_archive_filtering.py`,
   `test_clean_checkout_semantics.py`,
   `test_managed_cleanup_parity.py`) enforce this.
4. **Priority order is explicit.** When state buckets can overlap
   (e.g., a file matching both `internal` and `transient`), the
   classifier's check order is the contract. `surface_contract.py`
   comments document the order; reordering requires re-running the
   release test slice.

When to reach for this: any time you find yourself writing more than
two `if-is-X / elif-is-Y / else` branches that downstream callers
need to inspect. When NOT to use it: simple binary distinctions
(`is_self_host_repo` is correctly a boolean — it has one threshold,
not a state machine).

### Derive from canonical SoT, not from a literal

Constants that track a filesystem count, a generated artifact, or any
other fact-on-disk must **derive from the canonical source at import or
test time** rather than be written as a literal integer or string the
test then re-asserts. The implementation reads SoT-X to produce
artifact-Y; the test reads SoT-X to assert artifact-Y. If both sides
read the same constant, drift is invisible — the test always passes
regardless of whether the constant matches reality.

Three cases reached this shape independently:

| Drift class | Fix shape |
|---|---|
| Archive-cleanliness test called `classify_release_path` on both sides of every assertion → classifier blind spots silently shipped junk | Independent regex denylist (`tests/test_release_archive_filtering.py::FORBIDDEN_SHAPES`) that does NOT consult the classifier; canon-independence pinned via AST walk |
| Manifest test re-rendered the manifest on both sides of every assertion → drift in the renderer was invisible | Byte-equality assertion against the committed `cc/PACK_MANIFEST.txt` file |
| `wheel_smoke.EXPECTED_COMMAND_COUNT = 13` literal stale (live count was 14); test synthesized fixtures sized to whatever the constant said | `_count_packaged_assets()` derives the constant at import time from `espalier/assets/`; canary tests in `TestExpectedCountsMatchPackagedAssets` independently glob the same tree |

Two principles fall out of these three instances:

1. **Don't restate the SoT — derive from it.** Any literal integer that
   counts a filesystem fact is a candidate for derivation. The
   `EXPECTED_COMMAND_COUNT = 13` shape is the recurring footgun.
2. **Pin canon-independence with a structural test, not a substring
   check.** `test_denylist_does_not_import_surface_contract`
   uses an AST walk (Import / ImportFrom / Name nodes) — substring would
   false-positive on error-message strings naming the function. The AST
   shape is the contract; copy it when you write the next one.

When to reach for this: any time you write a literal constant that you
expect to "track reality." When NOT to reach for this: facts that are
not on-disk derivable (e.g., a semantic version number, a release date
— those are written deliberately and SHOULD be literal).

### Sister-site compression

When the same logical concern lands in N call sites, each future fix
touches N, contract tests grow to pin "every site has property X,"
and the contract surface inflates linearly. The compression discipline:

1. **Upstream first.** Promote the shared body to a single helper in
   `tools/cc/hooks/_hook_utils.py` (for hooks) or the appropriate
   engine module (for `espalier/`). The stdlib-only constraint in
   `tools/cc/` is non-negotiable.
2. **Alias, don't delete (in the migration pack).** Per-file diff
   stays one line; rollback is per-file. The deletion of the alias is
   a separate later cleanup pack.
3. **Behavioral parity test.** Either AST (no inline def of canonical
   names) or behavioral (parametrized subprocess across all sites
   asserting the same observable).
4. **0-C compression probe in `/implement-pack`.** `python
   tools/cc/sister_site_probe.py` runs after 0-B scope-check and
   before pack execution; flags new compression debt before it lands.
   On an adopter tree (marked deployed hooks) the gating scope is their
   own source and the deployed hooks' debt is an advisory tail; here on
   the source tree it is hooks + top-level engine, every arm gating.
   DIVERGENT cliques (same name, different bodies — e.g. every hook's
   `main`) are advisory, and so are DELEGATING cliques (every site a
   `return <owner>(<pass-through args>)` forwarding to one IMPORTED
   owner — the logic already lives once, in that owner); IDENTICAL 3+
   cliques, canon-misses, and assignment- and import-alias misses block.
   The delegating carve-out is deliberately narrow: an argument that is
   not a bare name or literal, a target bound by a local `def` rather
   than an import, a target that is one of the function's own
   parameters, or a builtin target all keep the clique blocking —
   each of those was measured letting real duplication through.
   The probe scans four shapes:
   (a) **function bodies** (module-level FunctionDef);
   (b) **class methods** (`ClassDef.body`, qualified as
   `ClassName.method_name`; dunders skipped);
   (c) **alias shims** — a local name diverging (after stripping leading
   underscores from BOTH sides) from the thing it aliases, in any of three
   spellings: `LHS = Module.Attr` (assignment), `from Module import Attr as
   LHS`, or `import Module as LHS` — blocking: adopt the canonical name
   locally or opt out with a `# sister-site: ok <reason>` marker;
   (d) **module-level constants** (`Assign` / `AnnAssign`
   with collection-literal or long-string RHS; same severity rules
   as function cliques). Per-site `# sister-site: ok <reason>`
   markers and `--accept-compression-debt <reason>` are the documented
   escape valves.
5. **Docstring rationale on every contract test.** New test
   files carry a module docstring with ≥3 content lines and a
   rationale anchor from a fixed lexicon (`pins / prevents / guards /
   drift / catches / without / because / failure mode / ...`).
   The grandfathered set is frozen; new debt is blocked at
   pytest collection time.

When to reach for this: any time you find yourself writing more than
two near-identical function bodies. When NOT to use it: the bodies
DIVERGE deliberately (e.g., scanner `_classify` shapes per language)
— mark those with `# sister-site: ok <reason>` so the probe excludes
them.

The canonical worked example compressed 9 `_project_root` +
3 `_normalize_path` + 2 raw-stdin sites. A second worked example
covers the constant shape: `MUTATION_TOOLS` was
defined as a literal set at `write_guard.py`, `plan_guard.py`,
and `tests/test_hook_matcher_precision.py::_extract_script` — promoted to
`_hook_utils.MUTATION_TOOLS` so adding a new mutation tool updates one
place. Categorized memory:
[`memory/sister-site-compression.md`](../memory/sister-site-compression.md).

The registry of all duplication classes — Python function bodies,
cross-file string patterns, cross-language sister sites, categorical
fragmentation, and the out-of-reach classes that no mechanism can
solve — lives at `docs/REDEFINED_INFORMATION_REGISTRY.md`
(internal: kept in the maintainers' private archive and `export-ignore`d, so
it is in neither the public repository nor any shipped artifact — which is why
this is a path, not a link).
Adding a new "managed" category requires updating the
registry. Out-of-reach classes (past-tense facts in CHANGELOG /
MEMORY, semantic equivalence of paraphrases, absence-encoded events,
file-organization-as-fact) are catalogued there with explanation;
they rely on convention + reviewer attention rather than mechanical
enforcement.

**Contract-infrastructure pattern.** Cross-source parity
contracts use the dataclasses in [`tests/_contracts.py`](../tests/_contracts.py)
(`NumericContract`, `StringContract`, `StringListContract`) plus the
shared opt-out marker grammar `# contract: ok <rule-id> <reason>`.
Each rule declares its `rule_id` (kebab-case, e.g.,
`hook-event-banner`) and registers a row in
[`tests/_surface_expected.py::CONTRACT_CEILINGS`](../tests/_surface_expected.py).
Operators opting out a single site write `# contract: ok <rule-id>
<reason>` directly above the offending line; the ceiling chip-down
enforces that opt-outs don't become the steady-state. This replaces
per-pack `# tp-NNN: ok` marker variants and per-pack
`EXPECTED_*_OPT_OUT_CEILING` constants so consumers
keep adoption to a single rule-id + contract function + ceiling row.

### Closed-loop verification — producer/consumer parity

When a consumer function C reads runtime input produced by a
producer function P (via JSON file, fingerprint, blueprint,
managed surface), C's test suite must include a parity test that
drives C with REAL P output. Hand-fabricated fixture data that
"looks like what P would produce" is the closed-loop trap shape
(`docs/sharp-edges/closed-loop-verification-trap.md`); the producer's
real output may have changed since the fixture was authored, and
the consumer test passes against the fabricated shape while
silently no-op'ing against real production state.

Convention:
1. Each (producer, consumer-test) pair is registered in
   `tests/_closed_loop_registry.py`.
2. The consumer's test file includes a parity test named
   `test_<consumer>_with_real_producer_output` that drives the
   consumer via the `initialized_repo_root` fixture (or equivalent
   real-producer-output mechanism).
3. The contract test
   (`tests/test_closed_loop_contract.py`) AST-asserts the parity
   test exists for every registered pair AND that its body imports
   the producer module AND calls the producer function. A name-only
   stub (rename body to `pass`) fails both the import-check and the
   call-check.

The registry is hand-curated and chips UP as new producer/consumer
relationships are introduced. Adding a row forces a parity-test
addition at the same review; review-visible discipline.

The canonical precedent — BC-041 / BC-041b — Gate 1's
`_resolve_core_tests` was fabricated against
`[{"test_commands": [...]}]` shapes when
`espalier.analyze.detect_tests` writes shell strings; Gate 1
silently no-op'd for months until BC-041 surfaced it; the fix had
to be re-walked in BC-041b because the original parity-test scope
missed a sister site. The registry ships with this precedent as
the seed entry.

### Red-team repro contract (the re-execution gate's artifact)

When a red-team / convergence pass claims a `blocks_release` finding, the gate
that verifies it (`espalier/red_team_guard.py`) does not trust the claim — it
re-executes a repro. A red-team agent that emits blockers must therefore also
emit, for each blocker, a repro of this exact shape:

```json
{"id": "<unique finding id>", "argv": ["cmd", "arg", ...],
 "expect": "fail", "match": "<specific non-catch-all failure-signature regex>"}
```

Rules the guard enforces (a blocker verifies only when ALL hold): `argv` is a
**list**, never a shell string; `expect` is `"fail"` for a blocker (a repro that
`expect`s `pass` cannot stand in for one); `match` is a **specific** regex that
must actually appear in the run's `stdout+stderr` — empty / `.*` / `.+`-class
matches are rejected (a trivially-failing command emits no real signature); `id`
is unique and usable (a `<no-id>` or duplicate id can't bind). The artifacts are
written to `cc/red_team_findings.json` (the FINDING_SCHEMA list) +
`cc/red_team_repros.json` (the repros); both are tracked-able and committed with
the change (the gitignored `cc/finding_ledger.jsonl` is separate telemetry, not
the gate input). An honest null — zero blockers, no artifact — passes *at the guard
level*. The re-execution runs in an independent oracle (the driver / CI), never an
in-agent hook. (The unattended pack-chain **driver** adds a layer on top: it requires
a per-pack `cc/_pack_receipt.json` attesting the red-team RAN, so at the driver a
*missing receipt* halts — there, an honest null is a zero-blocker receipt, not no
artifact. The red-team repro files remain tracked-able for a manual convergence pass;
only that receipt is gitignored. See `docs/AUTONOMOUS_EXECUTION.md`.) See
FAILURE_MODES §11.12 / §13.10.

### State-machine transition coverage

JSON-serialized state fields in the harness
(`cc/execution_plan.json::status`, blueprint gate records,
`.claude/settings.json::disableAllHooks`, etc.) and their reading
predicates (`plan_guard._has_active_plan`, `gate_passed`,
`is_kill_switch_set`, `_maintenance_mode_active`) are declared as
data in `tests/_state_machines.py`. The contracts assert:

1. Every declared transition (from_state, to_state) has a
   unit-test function exercising it. Catches the class
   where a missing `else` branch leaves the plan-level status
   sticky.

2. Every predicate's truth table covers the full state-field
   domain. Catches the class where a predicate's
   `status in ("in_progress", "complete")` silently includes a
   closed state.

Adding a new state field, transition, or predicate to harness
JSON requires registering it in `_state_machines.STATE_FIELDS`
+ adding the corresponding unit tests in the location named by
`TRANSITION_TEST_LOCATIONS`. The contract tests fire at PR
review time when registration and implementation drift.

Sister-class to closed-loop verification: closed-loop catches
producer/consumer-shape drift; this contract catches state-transition
sticky/missing-branch drift. Together they cover ~30% of recent
regressions sister-sites alone don't catch.

Three thin bool predicate helpers back the truth tables:
`gate_passed(gate: dict)` in
`tools/cc/cognitive_blueprint.py`, `is_kill_switch_set(settings: dict)`
in `tools/cc/hooks/_integrity.py`, and `_maintenance_mode_active(env_value)`
in `tools/cc/hooks/_maintenance_mode.py` (distinct from the
side-effectful `is_active(hook_name, *, action)` — pure form for
testability + composition).

### Severity vocabulary

Single canonical scale across all review surfaces:

| Tier | Meaning | Used by |
|---|---|---|
| BLOCK | Ship-blocking; merge gate fails | code-reviewer, pack-artifact checklist |
| WARN | Advisory; important but not ship-blocking | code-reviewer, pack-artifact checklist |
| NIT | Polish; fix at leisure | code-reviewer |
| PASS | Affirmative per-item verification | pack-artifact checklist, `release_check.py` per-line output |

This single scale consolidated three older vocabularies, so older
findings map onto it: the former code-reviewer `MAJOR`-vs-`MINOR`
distinction collapses to WARN-vs-NIT (ranking preserved), and the
former pack-checklist `WRONG`-vs-`CONFLICTING` distinction
collapses to BLOCK (both equally block `/implement-pack` Gate 0-A);
the mechanical "fires the inline-fix loop" behavior is unchanged.
See `tests/test_severity_scales.py` for the parity contract and
`tests/_surface_expected.py::CANONICAL_SEVERITY_SCALE` for the SoT.
Per-rule opt-out via `# contract: ok severity-scale <reason>`
markers for transitional mentions during multi-step migrations;
steady-state ceiling is 0 (no live opt-outs).

### Scaffolding-quality canon

`espalier/scaffolding_canon.py` is the independent quality canon for
the scaffolding side of the harness — three falsifiable signals
computed from raw `cc/blueprints/*.json` artifacts.

The canon's load-bearing rule: it must NOT import any module that
participates in `/reflect`'s surface walker. Otherwise it measures
itself — the closed-loop trap of using `/reflect`'s `gap_count` as
the quality metric for scaffolding shaped toward `/reflect` itself.

**Three signals:**

| Signal | What it measures | Falsifiable when |
|---|---|---|
| 1 — continuity (1-hop) | Fraction of session S's `continuation_fragments` whose body (post `[tag] ` prefix) appears as substring in session S+1's `reasoning_entries` text. Mean across the chain. | Mean < 0.10 across 40+ pairs → S+1 isn't engaging with what S handed forward. **Empirical state:** Mean = 0.0 across 17 pairs / 0/85 across prefix sensitivity sweep. The threshold IS breached. Reconciliation chosen: see CLAUDE.md priority-3 line — claim updated to match measurement rather than measurement adjusted to pass claim. <!-- canon: tests/test_scaffolding_canon.py::TestSignalContinuity --> <!-- claim-id: scaffolding-signal-1-threshold --> |
| 2 — human reasoning density | Median count of `reasoning_entries` per session whose `description` does NOT start with `[subagent:` (the prefix `subagent_stop` autorecords use). | Median = 0 across 20 sessions → human recording protocol isn't being followed even when the slot exists. <!-- canon: tests/test_scaffolding_canon.py::TestSignalHumanDensity --> <!-- claim-id: scaffolding-signal-2-threshold --> |
| 3 — reflect coverage | Fraction of sessions with at least one `reflect_passes` entry. Coverage rate ONLY — never reads inside the entries. | Coverage stays < 20% steady state → `/reflect` is nominal, not real. **Empirical state:** historical coverage 21.7% — barely above the floor. The threshold sits at the noise baseline by construction, which means the canon cannot fail on near-historical data. Treat the 20% number as a noise reference, not a target; falsifiability requires a configurable threshold tied to operator intent (e.g., adopter-declared target). Tracked as a known weakness. <!-- canon: tests/test_scaffolding_canon.py::TestSignalReflectCoverage --> <!-- claim-id: scaffolding-signal-3-threshold --> |

**Interpretation guards (must travel with the signals):**

- Signal 1 measures whether S's *curated highlights* (last-3
  decisions, top-3 reflect findings, last-2 patterns — auto-derived
  at `cmd_finalize` with `[decision]/[pattern]/...` prefixes; the up
  to two `[subagent:<type>]` agent-report fragments `cmd_finalize`
  has carried after the patterns since 2026-09-11 are excluded from
  the measure by prefix, see the third bullet) get
  re-engaged in S+1's reasoning text. The `[tag] ` prefix is
  stripped before substring match because S+1's reasoning_entries
  don't carry the prefix. The direction matters: reversing it (S's
  reasoning into S+1's fragments) is structurally impossible to
  satisfy since S+1's fragments come from S+1's own reasoning at
  its own finalize, not from S's hand-off.
- Signal 1's fragments were themselves unfiltered until 2026-08-16b,
  so its nonzero readings were self-noise: a `[subagent:` marker
  fragment in S matched the same marker text among S+1's own
  entries. Measured on the 200-session corpus at the moment of the
  fix — 49 of 696 fragments (7.0%) were markers, and Signal 1 fell
  from **0.0407 to 0.0000** once `cmd_finalize` began filtering
  them. **100% of its nonzero value was marker-matching-marker.**
  Sessions finalized before and after that change are therefore not
  comparable for Signal 1, and no test reds on the shift because
  the "Empirical state" above already records 0.0. The filter is a
  Signal-1 concern too, not only the Signal-2 concern the next
  bullet describes.
- Third epoch, 2026-09-11: `cmd_finalize` again emits `[subagent:`
  fragments, by design — up to two REPORTS from agents (each the
  agent's final-message lead, with its transcript as the entry's evidence)
  after the patterns, so a fan-out's verdicts reach the next
  session. Signal 1 no longer relies on the builder never emitting
  one: `_signal_1_continuity` skips those fragments by prefix itself
  (`TestSignalContinuityIgnoresAgentReports` drives both directions —
  a recurring boilerplate lead would have re-armed the self-noise
  above, and an unrestated lead would have deflated the score for a
  session that engaged with everything the operator handed it). So
  the operator's own fragments are measured the same way in all
  three epochs, and a Signal 1 reading that moves off 0.0 after this
  date is continuity, not marker echo.
- Signal 2 is meaningless without the `[subagent:` filter — the
  repo-analyst survey found recent `latest.json` had 5 entries all
  of which were subagent autorecords. Unfiltered, the metric
  always looks healthy.
- Signal 3 reports coverage only; reading `gap_count`,
  `cross_ref_density`, or `findings[]` would be closed-loop with
  the surface walker.

**6-module forbidden-imports contract:**

`FORBIDDEN_IMPORTS = frozenset({ "espalier.reflect_protocol",
"espalier.reflection", "espalier.models",
"espalier.cognitive_blueprint", "espalier.cli", "espalier.doctor" })`.
Pinned by `tests/test_scaffolding_canon.py::TestIndependentImports`
via AST walk (not substring — substring false-fires on the
`FORBIDDEN_IMPORTS` frozenset literal naming the modules).
Negative-proof subtest (`test_negative_proof_check_fires`) protects
against silent test-rot where the walker passes for the wrong reason.

**Raw-JSON-load-only rule:** the canon reads `cc/blueprints/*.json`
via stdlib `json.load`, NOT through any
`espalier.cognitive_blueprint` loader or `CognitiveBlueprint`
dataclass. Pinned by `TestRawJSONLoading`.

**Producer-before-consumer principle:** the canon ships only signals
computable from data the harness already captures. Any protocol-on/off
A/B comparison waits for
canon-sensitivity validation — the canon must first prove it detects
known-bad scaffolding shapes before it's trusted to grade interventions.

**CLI:** `espalier scaffolding-bench [--out PATH] [--last N] [--json]`.

### Protected-path contract parity

Three layers carry the same protected-path inventory; parity tests
keep them in lockstep:

- **`espalier.surface_contract`** — public truth.
  `get_protected_integrity_paths`, `get_protected_ci_files`,
  `get_protected_ci_prefixes`, `get_protected_mutation_paths`.
  Authoritative; tests load this.
- **`tools/cc/hooks/_integrity.py::MANIFEST_FILES`** — hook-side
  inventory for the integrity manifest. Hard-coded to preserve the
  `tools/cc/` zero-espalier-import rule.
- **`tools/cc/ci_guard.py::PROTECTED_FILES` + `PROTECTED_PREFIXES`** —
  CI-side inventory enforced by the `harness-guard.yml` job. Same
  isolation rule as `_integrity.py`.

`tests/test_integrity_contract_parity.py` and
`tests/test_protected_path_contract_parity.py` load the hook modules
by file path (no espalier import) and assert set equality with the
surface contract. A future change that adds a protected path on one
side without the other fails immediately with a clear message naming
which side has the extra entry.

Workflow-protection policy is explicit: `.github/workflows/` is in
`get_protected_ci_prefixes` and `ci_guard.PROTECTED_PREFIXES` because
workflow mutation can change release / test / benchmark enforcement.
A `.github/workflows/*.yml` change requires `HARNESS-UPDATE-APPROVED` — with
two narrow, deliberate exemptions, both implemented in `ci_guard.py` and
pinned in `tests/test_ci_guard.py`:

- **Repo posture.** The marker is required for every pull-request-like event on
  any repo, and for a `push` on an *adopter* repo. It is **not** required for a
  `push` on the self-host repo: there the pusher already holds write access and
  could simply type the marker, so it bought ceremony rather than security while
  firing on the majority of commits — a gate satisfied that often stops
  discriminating. The self-host check requires all five fingerprint signals and
  fails closed (any mismatch ⇒ marker still required).
- **Dependabot action bumps.** A pull request is allowed without a marker only
  when the actor is `dependabot[bot]`, *every* changed path is workflow YAML,
  and every changed line is a `uses:` ref whose action **identity** is unchanged
  — only the ref after `@` may move. An action *swap* is denied.

The kill-switch and governance-completeness scans remain **unconditional**: the
marker never overrode them, and neither exemption reaches them (both run before
the protected-path branch).

Self-host vs consumer protection: `get_protected_mutation_prefixes`
returns `(".github/workflows/", "cc/", "espalier/", "tools/cc/")` — these
protect the Espalier-Harness repo itself when self-hosting. In consumer
repos, write_guard's runtime check overlays only the harness-relevant
subset via `tools/cc/hooks/_hook_utils.py::is_self_host_repo`.

### Managed inventory lives in `espalier/managed_inventory.py`

The unified ownership inventory used by `espalier init`,
`espalier clean-generated`, `espalier doctor`, and the `cc/PACK_MANIFEST.txt`
renderer. Three disjoint classifications, plus a fourth, deliberately
asymmetric one — four categories in total:

- **public managed files** — `get_managed_public_files(repo_root, plan=None)`
  returns the canonical surface deployed by init: package commands, skills,

- **local runtime files** — `get_local_runtime_files(repo_root)` returns

  `.espalier/integrity.json`, `reports/*.json`). Never in PACK_MANIFEST;
  cleanup never auto-deletes them.
- **local-only files** — `get_local_only_files()` returns gitignored
  per-session state (cognitive blueprints, execution plans, surface
  handoff drafts, `settings.local.json`). Never deployed; never in PACK_MANIFEST.
- **install-ci artifacts** — `get_install_ci_artifacts()` returns the paths
  `espalier install-ci` writes *outside* the public managed inventory
  (`tools/cc/ci_guard.py`, `.github/workflows/harness-guard.yml`, and the
  conditional `harness-guard.yml.new` parity twin). **This one is deliberately
  asymmetric**: unlike the three above it is consumed by `cleanup.py` **only**,
  so an uninstall accounts for each artifact (marked → deleted, unmarked →
  preserved as a user file) instead of silently orphaning it — and it is kept
  **out** of `PACK_MANIFEST`, `doctor`, and the surface gate on purpose, so
  install-ci's writes never leak into the public-surface counts. It is a
  hand-maintained *mirror* of `cmd_install_ci`'s write set, not a shared owner:
  `cmd_install_ci` hard-codes its own destinations and never reads this tuple.
  The sync is pinned mechanically by
  `tests/test_cleanup.py::TestInstallCiArtifactDriftPin`, which runs the real
  `cmd_install_ci` across both branches and asserts its observed CI writes equal
  the tuple — so a future install-ci write that is not added here reds rather
  than silently re-orphaning. `.espalier/integrity.json` is deliberately **not**
  in this bucket: install-ci re-seeds it, but it is already covered as a local
  runtime file (preserved, not orphaned).

Cleanup composes the inventory with the marker check from
`managed_markers.has_managed_marker`: any file lacking the marker is
preserved as a user file. Cleanup additionally scans
`get_managed_public_prefixes()` for orphan user files in managed dirs
so operators see the full preserved set in the report.

### Managed-marker constants live in `espalier/managed_markers.py`

`MANAGED_MARKER = "espalier:managed"` and the comment-form constants
(`MARKER_HTML_COMMENT_RICH`, `MARKER_HTML_COMMENT_SHORT`,
`MARKER_HASH_COMMENT`, `JSON_SENTINEL_KEY`) are declared once. Modules
that need them import — they don't redeclare. The recognition helper
`has_managed_marker(content)` is frontmatter-aware: for files opening
with `---\n` it scans past the closing `---` plus 200 chars of slack,
so a marker placed after a long YAML block (agents, skills) is still
detected without scanning the full body.

The insertion helpers preserve frontmatter validity:

- `apply_marker_to_md` — for `.md`. With YAML frontmatter, the marker
  comment is inserted **after** the closing `---` (frontmatter parsers
  see a valid block at the top). Without frontmatter, prepended at the
  top. Idempotent — re-applying never double-marks.
- `apply_marker_to_text` — for `.toml` / `.txt` / `.py`. Prepends `# espalier:managed`
  (or after a `#!` shebang). Idempotent.

`espalier init` (`deploy_harness` step 6b and `write_required_surface`)
applies the **4-state ownership policy** (`.md` and `.py` at parity):

| Target state | Action |
|---|---|
| Absent | Write with marker (`created`) |
| Exists, has marker, content drifted | Overwrite with managed copy (`updated_managed`) |
| Exists, content already matches packaged source | No write (`skipped_no_drift`) |
| Exists, no marker | Preserve, report (`skipped_user_files`) |

Init's printed summary line surfaces the tally: `created: N
updated_managed: N skipped_no_drift: N skipped_user_files: N`. The
contract gives users deterministic ownership: keep the marker →
harness regenerates on drift; remove the marker → harness preserves.
Reruns on an unchanged repo report `skipped_no_drift` for every
already-matching file.

**Line-anchored recognition (BC-026).** `has_managed_marker`
matches the marker as a *complete comment line* via the regex
`^[ \t]*(?:#|<!--|::)[ \t]*espalier:managed\b` (compiled with
`re.ASCII`; `::` is the batch-file comment head the `.cmd` statusline
asset carries). A YAML scalar (`description: espalier:managed text`),
a JSON string value, or a prose paragraph mentioning the marker as
text is **not** recognized. Pre-fix, recognition was a substring
scan; a hostile asset shipped via PR could plant the substring in a
YAML field and become overwritable by the next `espalier init`.
The deprecated `_legacy_substring_match` helper is retained only
for a single migration test that asserts the public API no longer
routes through the old code path.

A category-driven default-ignorable strip runs before the regex —
any leading run of Unicode categories Cf / Cc / Cs / Cn / Zl / Zp
(BOM, ZWSP, ZWJ, LRM, WORD JOINER, bidi controls, LINE SEPARATOR,
PARAGRAPH SEPARATOR, tag chars, etc.) is removed so an invisible
prefix cannot displace the `^` anchor and silently demote a
managed file to user-modified.

**Atomic deploy writes.** Every write site in the
deploy helpers (`_write_seed`, `_deploy_managed_py`,
`_deploy_asset_md`) and `deploy_harness` (CLAUDE.md, ESPALIER_MEMORY.md)
routes through `atomic_write_text` so a concurrent SessionStart
reading any of those files during an init rerun cannot observe a
torn write. The AST contract is enforced by
`tests/test_cli_deploy.py::TestDeployAtomicity::test_no_naked_write_text_in_deploy_helpers`,
the cli-specific floor under the tree-wide census in
`tests/test_atomic_io.py::TestEveryEngineWriteOfAdopterStateIsAtomic`
(see "Atomic whole-file writes" below).

**Packaged-source iteration invariant (BC-030/031).**
`deploy_harness` derives the asset set it (re)deploys from
import-time enumeration of packaged sources — `INIT_HOOK_SCRIPTS`
+ `INIT_TOOL_SCRIPTS` (module-level constants) for `.py` and a
glob over `espalier/assets/claude/` for `.md`. It **must not**
consult `cc/PACK_MANIFEST.txt` for the iteration set; the manifest
is the *report* of what was deployed (written post-deploy by
`write_required_surface`), not the *authority* for what to deploy.
Trusting the on-disk manifest would open BC-031: an attacker who
can write to it could silently shrink the deploy set and prevent
the regeneration of a hand-disabled hook. The contract is
documented in the `deploy_harness` docstring and mechanically
enforced by `tests/test_cli_deploy.py::TestDeployIterationInvariant`.

**Confusable-marker loud warning.**
`find_confusable_markers` returns `(matched-text, line-number)`
tuples for marker-shaped substrings that fail anchor-match — Cyrillic
look-alikes (`еspalier:managed` with U+0435), case variants
(`Espalier:Managed`), HTML-entity-encoded forms (`&#x65;spalier:managed`).
These are NOT treated as managed (the secure outcome) but are
surfaced so a maintainer reviewing a PR diff doesn't merge a
confusable thinking it's the canonical marker. The shipped-asset
contract test
`tests/test_managed_markers.py::TestConfusableDetection::test_assets_have_no_confusables_at_release`
fails CI if any file in `espalier/assets/` contains a confusable.

### Frozen+slots dataclasses are the default in `espalier/`

New dataclasses use `@dataclass(frozen=True, slots=True)` unless there's a compelling reason not to. Memory savings via `__slots__` (~20-30% per instance), faster attribute access, runtime catch of attribute-typo assignments, and hashability for any future `@cache` use. **Frozen blocks `__setattr__` (field reassignment) but does NOT block in-place mutation of mutable field values** — `bp.list_field.append(x)` works on a frozen dataclass; `bp.list_field = new_list` raises `FrozenInstanceError`. Use `dataclasses.replace(obj, field=value)` for the latter and rebind the result. The `CognitiveBlueprint` API deliberately mixes both styles — `add_reasoning` and `record_reflect_pass` append in-place; `set_continuation_fragments` returns a new instance. The split is documented in `espalier/cognitive_blueprint.py`.

Documented exceptions to the default: `espalier/pack_manifest.py::AffectedSymbol` is plain `@dataclass` because the caller mutates `.classification` post-construction (matrix lookup at `espalier/cli.py::cmd_scope_check`); making it frozen would force a `dataclasses.replace` call on every classification. `espalier/pack_manifest.py::PackManifest` keeps mutable list defaults during parsing for the same reason. New deviations should carry a one-line inline comment explaining why frozen+slots is impractical for the type.

### Structural coupling via NamedTuple records

When two or more pieces of data must be **paired** — pattern + message, key + validator, identifier + payload — use a `NamedTuple` record rather than parallel containers (`list[X]` + `dict[X, Y]`). The pairing becomes structural, not convention-based via object identity.

`tools/cc/hooks/write_guard.py::BashPatternRecord` is the canonical example: `DANGEROUS_BASH_PATTERNS` was previously a `list[re.Pattern]` paired with a `_BASH_PATTERN_MESSAGES: dict[re.Pattern, str]` for per-pattern custom deny messages. The dict-keyed-by-pattern-object only worked because `re.compile` returns the same `Pattern` instance for identical sources (Python's `re._cache`) — a frail coupling that broke silently if any consumer rebuilt the pattern object. The refactor to `tuple[BashPatternRecord, ...]` paired pattern + message in one record; reintroduction of `dict[re.Pattern, str]` is blocked at AST contract (`tests/test_write_guard_pattern_message_coupling.py`).

This convention applies in `tools/cc/` and `espalier/` alike. In `tools/cc/`, `NamedTuple` is the right shape (stdlib-only, zero dependencies). In `espalier/`, `@dataclass(frozen=True, slots=True)` is the default per the section above — `NamedTuple` is the natural fit when positional access is genuinely useful (e.g., iteration as a tuple). For ambiguous cases, prefer `@dataclass(frozen=True, slots=True)` in `espalier/` to match the surrounding code.

### Surface support matrix parser lives in `espalier/surface_matrix.py`

The matrix at `docs/SURFACE_SUPPORT_MATRIX.md` is normative. Tests and the `espalier scope-check` CLI both need to read it; both must consume the same parser. `espalier/surface_matrix.parse_matrix_rows` is the canonical extractor and `SurfaceMatrix.classify` is the canonical classifier. ### SoT-vs-witness contract

When a parity contract has the shape `assert len(other_view_of_X) ==
EXPECTED_X`, both sides must derive from independent sources. If
`EXPECTED_X` is itself `len(producer_of_X)` from the same SoT module,
the test is tautological — convergence theater.

Two independence shapes are legitimate:

1. **Committed-file vs live-rendered.** `TestCommittedManifestMatchesRenderer`
   compares a file on disk (`cc/PACK_MANIFEST.txt`, frozen
   at last commit) against `render_pack_manifest(REPO_ROOT)` (current
   producer output). The committed file IS the independent witness.

2. **AST-extracted pattern from two distinct producer modules.**
   `test_doctor_and_release_check_use_same_corpus_glob` walks the
   AST of `espalier/doctor.py` AND `scripts/release_check.py`, extracts
   each module's glob string, and compares. Two modules; each is its
   own SoT for the pattern string.

The forbidden shape is `assert len(producer.X) == EXPECTED_X` where
`EXPECTED_X = len(producer.X)`. `tests/test_surface_expected_witness_contract.py`
mechanically prevents this; constants in `tests/_surface_expected.py`
carry `# class: derived` (non-witness) or `# class: literal` (witness)
markers per the contract.

**Class-level detection.** The narrow witness contract pins
the EXPECTED_DERIVED sub-shape; the broader failure mode — *any*
assertion whose two sides share an import chain — is caught by the
`convergence_theater` scanner (`espalier scan .` writes
`reports/scan_convergence_theater.json`). The scanner detects seven
shape labels (literal-pair, same-call, same-attribute, assertEqual-self,
derived-constant, approx-self, assertEqual-same-call), filters to
`==` only (preserving `>=` floor and `<=` ceiling contracts), and
cross-references `# class: literal` / `# class: derived` markers so
literal witnesses are not false-flagged. Exemption via
`# theater: ok <reason ≥12 chars>` pragma; pragma count and
`EXEMPT_FILES` registry both capped. See
[`docs/SHARP_EDGES.md` "Convergence theater is a class, not a bug"](SHARP_EDGES.md#convergence-theater-is-a-class-not-a-bug).

**Stealth-contract trilogy.** Three sister scanners detect
coupling between modules expressed through channels OTHER than imports:

- `subprocess_contracts` — internal `subprocess.run/Popen/check_output`,
  `os.system/popen`, `Popen(...).communicate()`, and `shell=True` string
  calls whose CLI surface lacks a `SUBPROCESS_CONTRACTS` entry + sister
  test in `tests/test_subprocess_cli_contract.py`. OS-utility binaries
  (git, pytest, tar, ...) are skipped via `OS_BINARIES`. Dynamic argv
  patterns (`cmd = base + [literal]; subprocess.run(cmd)`) are resolved
  via function-scope Name binding tracking; irreducibly-dynamic
  generic runners use a `# subprocess-contract: ok <reason>` pragma.
  The registry carries a parity test
  (`test_subprocess_contracts_parity_with_pinned_tests`) — every value
  must point at a real test function.
- `filesystem_contracts` — cross-module structured-file writes
  (`.json/.toml/.yaml`) lacking a `FILESYSTEM_CONTRACTS` schema-parity
  test. Handles `Path.write_text/.write_bytes`, `json.dump` (incl.
  `with open(p, "w") as f: json.dump(obj, f)` alias resolution), and
  wrapper functions (`atomic_write_text`, `atomic_write_json`, etc.).
  Outputs under `reports/` (scan/fingerprint artifacts) are exempt —
  write-once-by-producer-read-by-humans, not coordination surfaces.
- `magic_depth` — `Path(...).parents[N>=2]` without a `MAGIC_DEPTH_SITES`
  registry entry or `# magic-depth: ok <reason>` pragma. Dynamic
  indices (`parents[<var>]`) always require a pragma.

All three scanners run in `cmd_scan` on the self-host repo (an adopter
repo gets an empty report from each), emit JSON
reports under `reports/`, and have INLINED registries
(`TestScannerSelfContainment` at `tests/test_scanners.py::TestScannerSelfContainment`).
`TestScannerExemptPrefixesParity` makes the
`tests/fixtures/` exemption mechanical across every scanner that
walks the test tree. See [`docs/SHARP_EDGES.md` "Stealth contracts are
five categories, not one bug"](SHARP_EDGES.md#stealth-contracts-are-five-categories-not-one-bug).

**Encoding contracts** (`encoding_contracts`, `DEF-792`) is the fourth
self-host-gated scanner but not a coupling scanner: it reads text-mode
I/O that follows the OS locale instead of UTF-8 — `open()` / `io.open` /
`os.fdopen` and a `Path`-style `.open()` in a text mode, `.read_text()` /
`.write_text()`, `subprocess.*(text=True)` (the module under any import
alias), `tempfile.*File` in a text mode and `io.TextIOWrapper` — with no
`encoding=` or one that is not UTF-8 (the value is judged, positional or
keyword; a UTF-8 fixture mis-decodes on a cp1252 Windows console). It is
the one scanner that walks the WHOLE tree, `tests/` included, pruning
tool directories by name and any virtualenv by its `pyvenv.cfg`, reading
through a byte-order mark, and reporting a file it could not parse under
a `skipped` key instead of passing over it. `# encoding-locale-ok:
<reason>` on the line above exempts a site; the pragmas are a capped
registry the scanner's own test keeps live (a pragma above a site that
no longer fires reds).

### Pack-artifact review

Every `/implement-pack` invocation runs pack-artifact review at step 0-A before any other gate (scope-check is now 0-B). The review dispatches the `code-reviewer` agent with the fixed checklist at `tools/cc/pack_artifact_checklist.md`. Findings come in four severities (per the canonical scale):

- **BLOCK** — block execution. Operator edits the pack file to address each finding, then re-invokes `/implement-pack`.
- **WARN** — advisory; important but not ship-blocking. Execution proceeds after acknowledgment.
- **NIT** — polish; fix at leisure.
- **PASS** — affirmative per-item verification; informational.

The checklist is versioned. A pack reviewed against checklist v1 carries that version label in its blueprint reasoning entry so historical reviews are reproducible.

This gate catches mechanical errors that scope-check (step 0-B) cannot see — line-number drift, missing symbols, factually wrong prose claims, stdlib-rule violations in code examples, cross-pack ordering omissions. Scope-check operates on the pack's structure; pack-artifact review operates on its content.

**Manual smoke procedure (false-negative regression).** The agent dispatch happens at Claude runtime and is not exercised by pytest. To verify the gate detects real errors, the operator:

1. Authors a fixture pack at `task-packs/Scrapped/TP-99-smoke-broken.md` containing a known BLOCK (e.g., `espalier/cli.py:9999 — _deploy_doesnotexist`). Under `Scrapped/`, not the root: since 2026-09-21 a pack at the root is tracked on sight and ships, so a broad `git add` between steps 1 and 5 would publish the broken fixture.
2. Invokes `/implement-pack "task-packs/Scrapped/TP-99-smoke-broken.md"`.
3. Confirms step 0-A surfaces the BLOCK finding with the bad line number named.
4. Confirms execution does not proceed to 0-B scope-check.
5. Deletes the fixture pack.

`tests/test_implement_pack_step_zero.py::TestFalseNegativeRegression` asserts this procedure is documented here; the dispatch behavior itself is verified by the manual smoke.

### Reasoning review

`/reflect --reasoning <pack-path>` audits the *generation process* of a pack — not the pack's artifact-level content (that is pack-artifact review's job). The skill body dispatches a reasoning-review agent with the versioned checklist at `tools/cc/reasoning_review_checklist.md` (currently `v1`). Findings come in four severities:

- **GAP** — a required review angle, scope-justification, or alternative framing is missing.
- **BIAS** — synthesis was pattern-matched rather than evidence-backed; or a single agent type dominated the reasoning chain.
- **UNCHECKED** — a premise was imported without independent verification, or a load-bearing choice has no counterfactual.
- **PASS** — informational.

Reasoning review is **advisory, not blocking**. For each non-PASS finding the operator picks one of three responses:

- **Address** — edit the pack to fix the reasoning gap.
- **Acknowledge** — add a `# reasoning-review: acknowledged <reason>` line in the pack so future readers see the conscious trade-off.
- **Defer** — note as a tracked follow-up.

**When to invoke:**

- Pack `Status:` includes "security", "critical", or "architectural".
- Net-new subsystem packs.
- Effort estimate > 4 hours.
- Stakes high but pack-artifact review clean.

The agent selected for reasoning review should ideally differ from any agent that participated in the pack's generation — diversity-of-context is the load-bearing property; same-agent self-review inherits blind spots. For packs that introduce hooks, gates, or governance contracts prefer `failure-mode-reviewer`.

**Anti-theater calibration.** The known failure mode is the agent returning plausible-sounding inert findings that operators never act on. Defense: track operator disposition per finding in `.espalier/reasoning_review_log.jsonl` (gitignored, one JSON line per session) with `acknowledge-rate = acknowledged / (addressed + acknowledged + deferred)`. Thresholds: `>70%` = theater (revise checklist to v2 or change agent selection); `<30%` = catching things operators rewrite for (sustain); `30-70%` = expected steady state. Re-evaluate after 10+ packs.

### Two independent witnesses on the same artifact

When a gate both builds AND validates the same artifact, a blind spot in the builder is also a blind spot in the gate. Break the closed loop with a second witness that shares no code with the first.

- First witness: `espalier/release_noise.py` consumed by `surface_contract.classify_release_path`.
- Second witness: `espalier/release_denylist.py` — imports nothing from `release_noise.py` or `surface_contract.py`.

`tests/test_release_denylist.py::TestNoSharedImports` walks the AST and asserts the boundary (not a substring grep — substring would false-fire on error-message strings naming the module). The check runs at pytest time, so a future refactor that would unify the two witnesses fails CI. Agreement between witnesses is expected; disagreement on a real archive member is an investigation signal, not a rubber-stamp.

When this shape applies: any classifier or validator that grades its own output (release archive cleanliness, doc-truth claims, generated config validity). The bench corpus is also a dual-witness pattern at a different layer.

### Release-check status semantics: PASS / FAIL / SKIP

`scripts/release_check.py` uses a three-value status alphabet for opt-in env-gated checks:

- `PASS` — check ran and returned a clean result.
- `FAIL` — check ran and rejected the artifact.
- `SKIP` — check did not run because its opt-in env var was not set (currently `ESPALIER_RELEASE_CHECK_WITH_TESTS=1`, `ESPALIER_RELEASE_CHECK_WITH_WHEEL_SMOKE=1`).

Exit code is 0 when no `FAIL` regardless of `SKIP` count — this is the "fast signal green" semantic. The summary line reads `N passed, M skipped` rather than `21/21 PASS` so a maintainer reading the output sees what was actually verified versus what was deferred to CI. The `release_check OK` trailer is part of the `docs/DEMO.md` contract (`tests/test_demo_end_to_end.py`).

### Robustness idioms

Three small idioms worth reaching for when code needs the same shape, rather than re-inventing.

**Pluralization stem-strip with length floor.** `espalier/surface_matrix._stem` strips a single trailing `s` (`agents` <-> `agent`) only on tokens of length > 2 and never on `-ss` suffixes. The length floor is what makes the rule safe: dropping it would collapse `is`, `as`, `os` and over-match short words. Anything more aggressive (e.g. `-ies` -> `-y`) needs an enumerated rule set; without one, false positives are worse than the gap.

**Deterministic peel for line-suffix stripping.** `espalier/pack_manifest._strip_line_suffix` peels trailing `:N` groups iteratively rather than via a regex with quantifier alternation. The iterative form is linear in the number of suffix groups (no super-linear backtracking on adversarial input) and short-circuits on URL schemes (`http://host:8080` is preserved verbatim). Pattern fits anywhere a token might carry `:N` location suffixes that need stripping without mangling colon-bearing identifiers (URLs, package specifiers).

**Name-safety pre-witness gate.** `scripts/release_check.py::_is_unsafe_member_name` runs BEFORE the classifier and denylist when validating ZIP archive members. It rejects absolute paths, Windows drive prefixes, and `..` traversal segments at the entry point so no later witness has to reason about them. Pre-witness gates work when the underlying witnesses share an input-shape assumption (here: members are relative repo-rooted paths) that's easy to validate in isolation but expensive to re-check at every consumer.

`ESPALIER_MEMORY.md` is capped at 120 lines (`tests/test_contracts.py::TestMemoryMdLineLimit`). ## Library / hook parity

`tools/cc/` scripts have zero `espalier` imports — they execute
standalone with only stdlib available. This means defensive constants
and helpers shared between the two layers must be **physically
duplicated** as mirror modules; the duplication is deliberate, and
parity is asserted mechanically by `tests/test_library_hook_parity.py`.

| Library side | Hook side | What is mirrored |
|---|---|---|
| `espalier/_blueprint_limits.py` | `tools/cc/_blueprint_limits.py` | `BLUEPRINT_MAX_SIZE` (128 KB cap on blueprint reads) |
| `espalier/_atomic_io.py` | `tools/cc/hooks/_hook_utils.py::atomic_write_text` (inlined — there is no `_atomic_io` module on the hook side) | `atomic_write_text` (tempfile + os.replace) |
| `espalier/surface_contract.is_self_host_repo` | `tools/cc/hooks/_hook_utils.is_self_host_repo` | 5-signal detector (espalier/ dir, tools/cc/ dir, bench/ dir, pyproject name, SHA pin on write_guard.py); hook side mirrors `WRITE_GUARD_PREFIX_SHA256` via `tools/cc/hooks/_self_host_fingerprint.py` |
| `espalier/reflect_protocol.LOCAL_ONLY_PREFIXES` | `tools/cc/reflect_protocol.LOCAL_ONLY_PREFIXES` (+ byte-mirrored to `espalier/_vendor/cc/reflect_protocol.py`) | reflect broken-link surface-exclusion prefixes — a **three-way** twin (the vendored copy is regenerated by `scripts/sync_vendor_cc.py`, not hand-edited). Unlike the rows above, its parity is locked by `tests/test_reflect_link_guards.py::test_local_only_prefixes_match_across_twins` (an `ast.literal_eval` of the tuple, multi-line-safe), **not** `test_library_hook_parity.py` |
| `espalier/cognitive_blueprint.py` | `tools/cc/cognitive_blueprint.py` | blueprint read/append/truncate behavior — **independent implementations, not a byte-mirror.** A library-side fix that does not reach the hook copy silently breaks the continuity chain (the `_truncate_to_cap` cap-defeat, since resolved; recorded in the findings corpus, now on the record branch) |

Shape rules:

1. **Constants live in named modules, not at use sites.** A magic
   number duplicated in two places drifts; a named constant in two
   mirror modules drifts visibly and the AST parity test fires.
2. **Both modules carry an identical docstring header** that names the
   sister module, so a reader looking at one immediately sees the
   other.
3. **Bug fixes that change defensive behavior must land in BOTH
   copies in the same commit.** A library-side hardening with no
   hook-side mirror leaves the hook layer (which fires earlier in
   the call chain) exposed.
4. **The parity test is an AST walk, not a string compare.** Module
   formatting can diverge (different import order, different comment
   placement) without breaking parity; only named defensive symbols
   are required to match.

## Runtime output is 7-bit ASCII

User-facing CLI output, hook stderr/stdout, and release-script logs use
ASCII tokens only.

| Concept | Token |
|---|---|
| Warning | `[WARN]` |
| Error | `ERROR:` or `FAIL:` |
| Success | `OK` or `PASS` |
| Skip | `SKIP` |
| Arrow | `->` |
| Em-dash | `--` |
| Bullet | `*` or `-` |
| Approximately | `~` |
| Ellipsis | `...` |
| Box-drawing rule | `-` |
| Emoji | delete it — the sentence must read correctly without one |

⚠ **Deleting a character is not the same edit as substituting one.** An emoji has
no ASCII equivalent, so it comes out — and a *deletion* can break a consumer that
a substitution would not. Measured 2026-09-03: removing a `🎉` broke
`tests/test_strengthen.py::test_zero_untested_still_celebrates`, and silently made
its twin (`assert "🎉" not in md`) **vacuous** — the character no longer existed
anywhere, so that assertion could never fail again. When you delete a glyph, grep
for it repo-wide first and repoint *every* assertion onto an ASCII marker, not just
the one that went red.

Reason: PowerShell on default Windows codepages renders non-ASCII
inconsistently; some CI log sinks fail on non-ASCII. The contract is
enforced by `tests/test_portability_contract.py::TestNoNonAsciiInRuntimePrints`.
It covers four sinks: (1) string literals passed directly to `print` /
`sys.stderr.write` / `sys.stdout.write`; (2) the `detail` field of a
`CheckResult(...)` result constructor, which reaches the operator via an
indirect print; (3) the indirect-operator-string collector's rules (a)–(g),
which reach module-level constants, returned report payloads, printed helpers'
return values, and accumulators returned through `sep.join(...)`; and (4)
leading-token `echo` / `printf` emit lines in shell scripts. Coverage is
allowlist-bounded — `argparse help=`, sibling result constructors and
non-leading shell `echo` are deliberately not scanned, so a green result is
still not "all runtime output is ASCII."

**Sink (3) was added 2026-09-03 (`DEF-677`).** Before that, this test called the
direct-print collector only, while every widening of the indirect collector fed
a *different* contract in the same file (`TestOperatorStringsArePortable`, the
interpreter-token rule). Two nets, one file, no shared collector — so
`build-a-list-then-"\n".join-then-print`, the dominant idiom for operator report
bodies, sat outside the ASCII contract entirely and shipped 18 crash-capable
characters across five report renderers under a green result. The scope-out that
covered it justified itself as "FP-prone dataflow with no cheap AST answer";
measurement falsified that — the shape resolves in ~15 lines of AST with zero
false positives.

Applies to: `.py` under `espalier/`, `tools/cc/`, `scripts/`; and `.sh` under
`scripts/` + `bench/baselines/` (echo/printf emit lines).
Does NOT apply to: docs, READMEs, CHANGELOGs, tests, comments, docstrings,
shell heredoc bodies.

## The interpreter a `python` string names depends on where it is written

There are **three** surfaces that spell an interpreter, and they do not share a
contract. Two resolve it to the host's actual interpreter; the third is pinned
to bare `python` **on purpose**. Getting the axis wrong is a coin flip, so pick
by surface, not by habit:

- **Runtime hints the engine PRINTS or RETURNS** — the `{py} -m espalier <verb>`
  strings in `cli`, `doctor` and `fuse` — spell the **remedy** interpreter from
  `cli._remedy_py()`: the resolver's answer when it clears the floor, else the
  interpreter running the command (`DEF-758`; `_detect_python_command()` is
  the WRITE answer, what settings.json carries, and on a host where nothing
  validated it is the literal `python` -- a command that cannot run). A hint
  is something an operator copy-pastes, and on stock macOS (`python3` only) a
  bare `python` hint is command-not-found at exactly the first-run moment.
  Detection is computed inside the emitting branch on frequently-run
  handlers, so a success path spawns no probe subprocess. The interpreter
  slot -- whatever precedes `-m espalier` in an f-string -- must be
  `_remedy_py()`, a local bound from it, or a parameter every call site
  passes one to; `tests/test_portability_contract.py::TestRemediesSpellTheRemedyInterpreter`
  follows the parameter (`DEF-805`).
- **`.claude/settings.json` hook wiring** — `cli._build_settings_json` threads
  the same detected interpreter. This is mechanical enforcement, and it has
  always resolved the host value.
- **Written surfaces stay bare `python`** — operator doc bodies, the generated
  `_build_claude_md` blockquote, and argparse `epilog=` / `help=` strings. This
  is the **opposite** contract and it is deliberate: Windows ships `python`, not
  `python3`, so a doc hard-coding `python3` re-introduces the Unix-only
  assumption the repo bans. Interpolating a detected value into argparse help
  would also run detection on every CLI invocation.

Both directions are mechanically enforced, and they pull opposite ways — check
which side you are on before editing an interpreter string:

- detected side — `tests/test_cli_commands.py::TestDetectPythonCommand::test_hint_tracks_detected_interpreter`
- bare-`python` side — `tests/test_portability_contract.py::TestOperatorDocsPortability::test_operator_docs_no_unix_only_default_workflows`

**A second, orthogonal axis rides along:** always `-m espalier <verb>`, never a
bare `espalier` console script, because the console script is not guaranteed to
be on PATH. That one is pinned by
`tests/test_no_bare_espalier_hints.py::test_no_bare_espalier_subcommand_in_engine_runtime_strings`
and is independent of which interpreter you name — converting `python -m espalier`
to `{py} -m espalier` keeps `-m espalier` intact and leaves that gate green.

## An OS error reaches an operator through `os_error_text`, and a path is never rendered through `repr`

`str(exc)` on an `OSError` renders `filename` through `repr`:
`[Errno 13] Permission denied: 'C:\\repo\\.claude'` -- the backslashes doubled
and the path quoted, so on Windows the shell says no such file when the
operator pastes the path the message names (`DEF-799`, driven on the Windows
walk; reproducible on POSIX with a backslash-carrying filename, because `repr`
doubles on every platform). Two rules, each with a pin:

- **An exception bound by a handler that can catch an `OSError` -- the
  OSError family, `Exception`, `BaseException` -- is rendered through
  `os_error_text(exc)`** -- `espalier._text.os_error_text` in the engine,
  `tools/cc/_json_safe.os_error_text` for the hooks and the `tools/cc`
  scripts (the dual-scope helper; the two bodies are parity-pinned by
  `tests/test_surface_contract.py`; a hook reads it through `_hook_utils`,
  which falls back to `str(exc)` when an adopter's `_json_safe.py` is stale
  rather than taking the hook layer down at import). It keeps Python's own
  shape (the `[Errno N]` / `[WinError N]` bracket, the strerror, the `->`
  between two paths) and spells the path plain, quoted only when spaced; an
  exception with no filename, or one that is not an `OSError` at all (the
  handler tuples also catch `subprocess.TimeoutExpired`), comes back as
  `str(exc)` unchanged, so every `except (...) as exc` site can route through
  it without a type check. In the hooks, `_hook_utils.warn_exc` is the one
  reporter an exception is handed to, and it renders through the seam. The
  scanners inline by contract (`TestScannerSelfContainment`) and carry the
  path as its own record key, so there the OS reason stands alone
  (`e.strerror or type(e).__name__`).
  Pin: `tests/test_portability_contract.py::TestOsErrorsRenderAsPaths`, keyed
  on the handler BINDING -- any load of the bound name that is not an
  attribute base, a `raise`, a type question or an argument to a renderer on
  its roster reds, whatever the sink and nested functions included -- so it
  is not blind to a `print` or `.format` a call-name list would omit. The
  population is types that can CATCH an `OSError`, not types that are one: a
  handler naming only non-OSError types is out by construction. The roster is
  held equal to the callees in use, and a `routes` entry must call the seam
  in its own body -- adding a line to the roster is not how a red goes away.
- **A path, a hook command or an interpreter token is never `!r`'d.** Render
  it plain inside backticks (`` `{cmd}` ``), the delimiter every remedy here
  already uses; a bare identifier that is not a path (`{event!r}`,
  `{profile!r}`) may keep its `repr`.
  Pin: `tests/test_portability_contract.py::TestPathsAreNotRenderedThroughRepr`
  -- `!r` on a name bound in scope from `shutil.which`, `Path`,
  `sys.executable`, `exc.filename` or a `Path`-typed parameter reds, and so
  does `!r` on the path vocabulary (`cmd`, `command`, `old_command`,
  `new_command`, `resolved`, `interp`, `script`, `a_script`, `b_script`,
  `path`, `root`), which is held live both ways so a name nobody interpolates
  plain any more cannot sit on the list.

## Atomic whole-file writes via tempfile + os.replace

Every whole-file write the engine makes into an adopter's tree goes through
`espalier/_atomic_io.atomic_write_text` (or `atomic_write_bytes` for a
verbatim copy of an existing file: a settings backup, the CI gate script):
the JSON state hook subprocesses read concurrently, and equally the cc/
docs, the seeds, the fused tree's stubs, the surface handoff, the scan
baseline and the settings unwire on uninstall. The hook side has its own
copy, `tools/cc/hooks/_hook_utils.atomic_write_text` (hooks cannot import
from `espalier/`), and `tools/cc/cognitive_blueprint.py` and
`tools/cc/execution_plan.py` carry inlined copies for the same reason; bug
fixes apply to every copy.

Algorithm: tempfile in target's parent directory (same FS), write,
close, `os.replace`. Concurrent readers see either the old or the
new contents, never a torn/truncated file.

**What the write does to the target's identity** -- its mode, a symlink
at its path, a second hardlinked name -- is part of the contract, stated
here because a rename-based write decides all three and used to decide
them silently (`tests/test_atomic_io.py::TestTargetMode` and
`::TestSymlinkedTarget` pin every copy):

- **Mode.** An existing regular file keeps the bits it had: the operator's
  `chmod +x` on a hook script or `chmod g+r` on a settings file survives
  the next init, upgrade or session. A fresh file gets the mode `open()`
  would give under the process umask. The helper imposes no mode of its
  own -- the tempfile used to hardcode 0600, so every file the harness
  wrote ended group-unreadable and every exec bit was silently dropped.
  Files an earlier release wrote at 0600 keep 0600 until the adopter
  changes them once; after that the change sticks. Windows keeps one
  read-only bit and has no `fchmod`, so the mode leg is a no-op there.
- **Symlink, decided per target.** By default every copy replaces a
  symlinked target with a regular file: harness state under `cc/`,
  `.espalier` and `reports/` is the harness's own, the readers of it that
  refuse a symlink (the plan file's `read_text_nofollow`, the freshness
  cache's and the statusline's `O_NOFOLLOW` opens) can read what the write
  leaves, and no adopter manages harness state by dotfiles. The engine's
  copy takes `follow_symlinks=True` for the adopter's *own* file -- a
  dotfiles-managed `.gitignore` or `settings.json` -- and rewrites the real
  file in place, its mode with it, keeping the link; the retire on
  uninstall, the settings merge, the hook-wiring repair, the interpreter
  rewire and the settings unwire pass it (a test pins that set), init's append follows the link by
  nature, and an emptied linked `.gitignore` is never deleted (init did not
  create the link). A dangling link into a directory that does not exist --
  a dotfiles checkout not cloned yet -- fails with the `OSError` init
  already reports as a one-line manual step; the directory is not created.
  The rule is per target, not per copy, because a writer that follows a
  link at a state path leaves the state's symlink-refusing reader empty
  forever (measured on `.espalier/freshness.json` while this was built).
- **Hardlink.** The new bytes are a new inode, so a second name for the
  old one keeps the old bytes. A property of rename-based atomicity, not a
  defect; the harness never hardlinks its own state.
- **Ownership** is the writer's; a file another user owned is owned by
  whoever ran the harness afterwards. Not preserved (that needs privilege),
  and not on the roster of things the helper promises.

The rule is enforced, not advised:
`tests/test_atomic_io.py::TestEveryEngineWriteOfAdopterStateIsAtomic`
censuses every raw write in `espalier/` by AST -- `write_text`,
`write_bytes`, a `json`/`pickle` dump, `open` in a writing mode, a `shutil`
copy -- and reds on any site outside its hand-written exemption rosters,
each entry carrying a count and a reason (append-only logs whose readers
skip a torn tail, lock files, the fused output tree, an `--out` that is not
a regular file). A one-shot write is not exempt because it is one-shot: add
the site to the roster with its reason, or use the helper. What the helper
does NOT buy is an atomic *update*: a load-modify-save site still needs a
lock against a concurrent writer (see "Atomic Write Is Not Atomic Update"
in `docs/SHARP_EDGES.md`).

The tempfile's visible name is capped at 64 chars for Windows MAX_PATH
(260) safety, so a long target filename cannot push the tempfile past the
limit on Windows runners.

## Symlink-safe recursive walks via `safe_rglob`

`Path.rglob(...)` and literal-recursive `Path.glob("**/...")` follow
directory symlinks on CPython < 3.13 (`recurse_symlinks` only became
default-`False` at 3.13), so on an adopter tree with a directory-symlink
**loop** they raise `OSError(ELOOP)` on the first-run fingerprint / scan
path — and the engine supports 3.10+. Never call a bare `rglob` /
recursive `glob` on a path that may be an adopter tree. Two copies of the
helper, same split as the atomic-write idiom above (scanners and hooks
cannot import from `espalier/`):

- `espalier/_safe_walk.safe_rglob` / `safe_glob` — engine-side canonical
  (`os.walk(followlinks=False)` + `fnmatch`). Imported by the tree-walking
  engine modules (`analyze`, `cli`, `cleanup`, `proofs`, `reflection`,
  `reflect_protocol`, `scope_walker`). `safe_glob` also covers the one
  shape the static guard cannot see — a `glob` whose pattern is a *runtime
  variable* that may contain `**` (e.g. `freshness.discover_fragments`).
- An INLINE `_safe_rglob` (the same `os.walk(followlinks=False)` symlink-safe
  core) in each `espalier/scanners/` module that walks a tree and in
  `tools/cc/reflect_protocol.py` — they are `inspect.getsource`-copied /
  zero-espalier-import, so they carry the core verbatim. The scanner copies
  additionally prune embedded repos via an inline `_skip_nested_repos` call
  (INV-28), stripped by the drift-pin below so only the shared core is compared.
  Bug fixes apply to every copy.

**Three obligations, not two.** A scanner-local walker carries the
`os.walk(followlinks=False)` core and the inline `_skip_nested_repos` prune
(both above) — **and** a per-file **read guard**. A walk must not abort
because one file is unreadable (dangling symlink, permission, a path that
vanished mid-walk), so the per-file read is wrapped in `except OSError` and
the walk continues. Every scanner that walks a tree carries the guard.
Four of them — `exceptions`, `perf_smells`, `prints`, `test_loosening` —
additionally collect the casualties under a `"skipped"` report key, which
`cli.cmd_scan` surfaces as `[WARN] N unreadable file(s) …`; that WARN is
what stops a silently-shrunk scan from reading as a clean one. `godfiles`
is the deliberate exception: it carries the guard but reports no `"skipped"`
key, because a size report omits an unreadable file rather than aborting
(its own inline comment states the rationale). **If you add the report key
to a scanner, wire the WARN with it** — a `"skipped"` list nothing surfaces
is the silently-shrunk scan wearing a receipt.

The inline copies are drift-pinned to the canonical by
`tests/test_safe_walk.py::test_inline_safe_rglob_copies_match_canonical_oswalk_loop`,
which AST-compares each `_safe_rglob` body against `safe_rglob`'s `os.walk`
loop and reds on any drift (a flipped `followlinks`, a dropped filter).

**Recurrence guard.** `espalier/scanners/filesystem_contracts.scan_recursive_walks`
(the `/scan filesystem_contracts` sub-mode, also run at `stop_gate`) flags
every UNannotated bare `rglob` / literal-recursive `glob("**/...")` /
`os.walk(followlinks=True)` under `espalier/` + `tools/` + the
fusion-overlaid `scripts/` subset (`RGLOB_SCAN_OVERLAID_SCRIPTS`, drift-pinned
to `fusion_manifest.HARNESS_INCLUDE`). A new bare walk earns the red there —
this is the structural lock that makes the class non-regressable: the
hand-list of sites is a floor, the guard is the ceiling.

**Pragma escape hatch.** A genuinely-safe bare walk — one that only ever
walks the harness's OWN tree, never an adopter's — carries a trailing
`# espalier:safe-walk-ok <reason>` comment (≥6 chars of reason) on the
call's own line or the line directly above. The marker is anchored to a
`#` so a string literal containing the text cannot suppress a finding.

See `docs/FAILURE_MODES.md` §9.7 (version-gated stdlib semantics) and
§2.8 (the narrow-lock class this swept).

## Cross-session counter atomicity via fcntl.flock

`tools/cc/hooks/reflect_trigger._locked_increment` is the model. The
counter `write_count` is read-modify-written by every PostToolUse
event; two CC sessions in the same repo race on the increment without
a lock. The lock is `fcntl.flock(LOCK_EX)` on POSIX; Windows
fall-through (documented as a known limit — `msvcrt.locking` has
different ergonomics). Tests exercise the contract via
multiprocessing pool in `test_reflect_trigger_concurrency.py`.

Use this shape for any cross-session state where strict monotonicity
matters. For non-monotonic state (e.g., flag files set/cleared) the
atomic-write helper above is sufficient.

**Generalisation.** Any load-modify-save sequence against a
shared JSON file needs the same flock — `atomic_write_text` only
guarantees that the final write isn't torn, NOT that two concurrent
load+mutate+save sequences both land their mutations. The second
consumer of this pattern is
`tools/cc/cognitive_blueprint._acquire_write_lock` (wraps `cmd_record`
/ `cmd_finalize` / `cmd_record_reflect`). With the
read+modify+write window unguarded, parallel subagent Stops
drop reasoning entries. The lock is taken on a sibling
`.write.lock` file in the same directory as the target JSON; POSIX
advisory semantics scope the lock to the file descriptor.

## Case-insensitive path-prefix comparison

Protected-zone prefix checks (`write_guard._is_protected`,
`write_guard._is_allowed`, `plan_guard._is_exempt`) normalize the
input path AND each prefix with `unicodedata.normalize("NFKC", s).casefold()`
before `startswith()`. On macOS APFS and Windows NTFS, case-varied
input paths (`tools/CC/hooks/x.py`) point to the same inode as the
canonical form — the normalization prevents case-variation from
bypassing protection. NFKC additionally collapses Unicode compatibility
variants (fullwidth Latin letters, Turkish dotted-I, German ß)
that `.lower()` misses but APFS case-folds via OS-level Unicode tables
(BC-025). Sister-site rule: all three sites must be updated together.

`os.path.normcase` does NOT help on macOS (Python doesn't know
whether HFS+ or APFS case-sensitive variant is in use). Documented in
`tests/test_write_guard.py::TestCaseInsensitiveBypassBlocked` and
`tests/test_hooks.py::TestUnicodeNormalization`.

## MCP tool-name write-intent detection

`tools/cc/hooks/plan_guard._MCP_WRITE_VERBS` is the narrow verb set
that triggers plan-required denial. Broad verbs
(`execute`, `send`, `commit`, `run_`, `post_`) that match non-FS-write
tool names are excluded. New entries must be unambiguous filesystem-write markers

## Hook matcher strings live in `harness_config.CANONICAL_HOOK_WIRING`

`CANONICAL_HOOK_WIRING` in `espalier/harness_config.py` is the single source
of truth for every hook's event name, matcher string, and timeout. Hardcoding
matcher literals in `espalier/cli.py::_build_settings_json` would require edits
in two places and drift silently.

The current contract:

- `cli._matcher_for(script_name)` reads `CANONICAL_HOOK_WIRING[script_name]["matcher"]`
  and is the only caller that emits matchers into `.claude/settings.json`.
- `harness_config._build_hooks(fp, repo_root=None)` reads the same dict and

- Tests that assert matcher values must import from `harness_config`, not

Adding or changing a hook matcher: update `CANONICAL_HOOK_WIRING` once;
`cli.py` and `deploy_harness` pick up the change automatically.

## `tomllib` import goes through `espalier._compat`

Python 3.11+ ships `tomllib` in the stdlib; pre-3.11 needs the
`tomli` backport. `espalier/_compat.py` exposes the resolved module
as `tomllib`, so callers write:

```python
from espalier._compat import tomllib
```

Direct `import tomllib` in `espalier/` raises `ModuleNotFoundError`
on older interpreters. Tests and runtime alike route through the
shim so dropping 3.10 support later is a one-line edit in
`_compat.py`, not a sweep across every TOML reader.

## `espalier.toml` adopter customization

Schema is flat top-level keys. `espalier/config.py::load_config`
filters a hardcoded `fields` set against `data.items()` — nested
TOML tables are NOT reached. Every `HarnessConfig` field
(`include_paths`, `protected_paths`, `default_profile`,
`plan_exempt_prefixes`, …) is a flat top-level key.

`plan_exempt_prefixes` lets adopters declare source roots that
plan_guard should treat as exempt from the plan-required check:

```toml
# espalier.toml
plan_exempt_prefixes = ["src/", "lib/"]
```

Each entry must end with `/`. Absolute paths (`/usr/...`) and `..`
traversal are rejected. Any invalid entry drops the whole list
(strict fallback) and emits a `[plan_guard]` advisory to stderr.

The hook-side reader at
`tools/cc/hooks/plan_guard.py::_load_adopter_exempt_prefixes`
duplicates the TOML parser because `tools/cc/` has a
zero-espalier-imports contract. The two readers stay in sync via
the contract test `tests/test_plan_guard_adopter_config.py`.

Adopter ergonomics knob, NOT a security control. The right relief
for plan_guard friction on conventional source layouts; do NOT use
`ESPALIER_MAINTENANCE_MODE=1` for that purpose — it also bypasses
write_guard protected-zone checks, stop_gate gates 2+3 and subagent_stop's
blueprint append. See
`docs/sharp-edges/plan-guard-adopter-source-roots.md`.

## Broad-except narrowing — precedent shape

When the `# noqa: BLE001` line above says the broad except is genuinely
needed, leave it. When the broad except can be narrowed to a concrete
type, the precedent is `(ValueError, OSError)`
for I/O-and-parse sites and `(OSError, UnicodeDecodeError,
json.JSONDecodeError)` for file-decode sites. Add the marker only
when those narrower forms cannot cover the legitimate failure modes
(e.g., third-party library raising untyped `Exception` subclasses).

**Scanner parity.** `scripts/check_exception_policy.py`
classifies handlers into three distinct constructs — `bare`
(`except:`), `exception` (`except Exception`), and `baseexception`
(`except BaseException`). All three are flagged by default; each
requires a per-site `# noqa: BLE001 — <reason>` annotation. The
comment is the discipline; the allowlist JSON is reserved for
pre-convention grandfathered sites only.

### Hook entrypoints: catch BaseException, deny on uncertainty

Hook scripts in `tools/cc/hooks/` AND `tools/cc/ci_guard.py` carry a
deny-on-uncertainty contract: any internal error MUST translate to a
structured `deny` response rather than propagating to `sys.exit(1)`.
Claude Code's hook protocol treats exit 1 as "hook bug — allow the
tool call" per `docs/external/cc-hook-protocol.md`, which is the
OPPOSITE of what a guard wants.

Therefore the top-level `main()` of each hook script catches
`BaseException` (not just `Exception`). This intentionally catches
`KeyboardInterrupt`, `SystemExit`, and `GeneratorExit` in addition to
the regular exception hierarchy: a Ctrl-C mid-write or a sub-process
signal that would normally produce graceful shutdown must still deny
the tool call.

The exception-policy scanner exempts BaseException catches at
hook-entrypoint sites via `_is_hook_entrypoint`. The exemption covers:

- Every file under `tools/cc/hooks/` (the `HOOK_ENTRYPOINT_DIRS`
  prefix).
- The enumerated CI / harness-internal helpers in
  `HOOK_ENTRYPOINT_FILES` — `tools/cc/ci_guard.py` plus the four
  helpers hook scripts dispatch into at the top-level entrypoint
  (`cognitive_blueprint.py`, `execution_plan.py`,
  `reflect_protocol.py`, `statusline.py`, `session_resume.py`).

`HOOK_ENTRYPOINT_FILES` cardinality is pinned by
`tests/test_exception_policy.py::test_hook_entrypoint_files_cardinality_pinned`.
Adding a new entrypoint helper without documenting its contract in
that test is the failure shape; widening the list silently would
mask future legitimate findings inside the file.

Non-hook code MUST NOT catch BaseException — silent-Ctrl-C is a worse
problem in normal code than the deny-on-uncertainty contract makes
of it in a guard.

## Concurrency

### Read-modify-write windows on POSIX use `fcntl.flock`

When a writer reads a file, mutates a field, and writes the result
back, two concurrent writers race-clobber by default. The harness's
contract for these windows on POSIX is `fcntl.flock` on a sibling
sentinel file. Reference implementations:

- `tools/cc/cognitive_blueprint._acquire_write_lock` —
  `cc/blueprints/.write.lock` flock around `cmd_record`,
  `finalize`, `record_reflect`.
- `tools/cc/hooks/_integrity.write_manifest` —
  `.espalier/.manifest.write.lock` flock around the
  read-current-hashes → write-manifest window.

Windows falls through without the lock (`fcntl` is POSIX-only); the
asymmetry is documented at each call site. The sentinel file is a
sibling rather than the operand because POSIX advisory locks scope
to the file descriptor — locking the operand directly would
serialize against concurrent *readers* too, which we don't want.

Note: `fcntl.flock` is host-local. If `cc/blueprints/` is symlinked
into a dotfiles repo shared between machines, two CC sessions on
different hosts both acquire local locks independently —
`cognitive_blueprint._maybe_warn_symlink` emits a one-shot stderr
WARN at first `_bp_dir()` call so the hazard is observable.

## Failure-mode review on the fix, not only the original gap

After any failure-mode-sensitive fix design — especially when an earlier
review produced a set of mitigations — run `failure-mode-reviewer` against
the FIX DESIGN before implementation, not only against the original gap.
Fix designs introduce their own blind spots: an allowlist that still admits
near-misses, a normalizer that misses a Unicode class, a defense framed as
"second layer" when it must be the primary, or a check at the scan site
that doesn't get mirrored at the write site (`pin_fragment` vs
`scan_repo` is the canonical example).

Concretely: the failure-mode-reviewer's prompt should be "how does the
proposed fix quietly fail when someone forgets a step, refactors
carelessly, or relies on a behavior the code doesn't enforce." It is a
different cognitive mode than the correctness lens a code-reviewer
applies — and a different mode again from external-threat modeling, which
is not in scope for this single-operator harness.

**Companion SHARP_EDGES entry:** "Adversarial Asymptote Is Smaller With
Fresh-Angle Discipline" documents the round-count pattern.

## Document freshness

Doc claims that bind to code paths can declare a fragment marker:

```
<!-- espalier:fragment id=<short-id>
     bound=<path>[::<symbol>][,<path>...]
     policy=<verify-on-touch|weekly|numeric-contract> -->
```

The manifest at `.espalier/freshness.json` records the SHA at which
each fragment was last asserted accurate by an operator. State is
computed from `git log` of bound paths since the pinned SHA.

Critical invariants:

- Manifest is **committed**, not gitignored. Pinning is a
  team-shared verification act, not per-machine state. (BC-039)
- A change to a fragment's `bound` field forces state to
  `unpinned` regardless of the manifest's SHA. Bound changes are
  changes to the claim itself and require explicit re-pinning.
  (BC-040)
- Policy vocabulary is **closed**: `verify-on-touch`, `weekly`,
  `numeric-contract`. Unknown policy → state `critical`. (BC-044)
- Markers inside YAML frontmatter or fenced code blocks are
  ignored. (BC-038)
- Pinning is the operator's explicit assertion; it does NOT verify
  mechanically. Pinning a stale fragment without reading the
  bound code is the documented anti-pattern. (See SHARP_EDGES.)

The scanner is canon: `espalier/scanners/freshness.py` owns
`Fragment`, `FragmentState`, the policy enum, and the regex.
`espalier/freshness.py` is a thin public-API wrapper that re-exports
those plus `pin_fragment` / `unpin_fragment` helpers; per the
established scanner convention (`espalier/scanners/{exceptions,
prints,godfiles,perf_smells,test_loosening}.py`), the public entry-point function
is named `scan_repo`.

Hook integration, statusline display, audit integration, and CI
gating layer on top of this foundation (see the cache-discipline
section below), not the scanner core.

     bound=tools/cc/_freshness_cache.py::_read_state_cache_safe,tools/cc/_freshness_cache.py::_is_state_cache_stale,espalier/freshness.py::update_state_cache,espalier/freshness.py::is_state_cache_stale
     policy=verify-on-touch -->
### Consumers read `state_cache`; only `freshness check` writes it

The committed `.espalier/freshness.json` manifest carries ONLY
the authoritative pin records (`fragments` key + `schema_version`).
The derived `state_cache` — counts + critical/stale lists + the
computed-at SHA — is written by `espalier freshness check` to a
SEPARATE gitignored per-install file,
`.espalier/.freshness_state_cache.json` (the whole file body IS the
cache object), so a `freshness check` never dirties the tracked
tree. Consumers — `session_start.py` banner, `statusline.py`
segment, `audit_accuracy.py` verdicts — read the cache; they
MUST NOT recompute it.

If the cache is absent (e.g. fresh clone before any local
`freshness check`) or stale (>24h old OR `computed_at_sha`
does not match `git rev-parse HEAD` and is not a recent
ancestor), consumers degrade silently — they do NOT trigger a
fresh scan, because the scan cost (~50-100ms) is too expensive
for every session_start / statusline cycle.

The fd-level safe-read pattern is inherited by
`espalier.freshness.read_state_cache_safe` and mirrored in
`tools/cc/_freshness_cache.py::_read_state_cache_safe`. The
two copies exist because `tools/cc/` must have zero espalier
imports per the architecture rule; a parity test
(`tests/test_freshness_cache_reader_parity.py`) asserts both
implementations return identical dicts on the same fixture
cache. New readers MUST use one of these helpers rather
than re-implementing the bounded read.

`.espalier/freshness.json` is in `write_guard`'s protected
files so the Write tool cannot corrupt the committed fragment
pins mid-session; only the out-of-process `espalier freshness
pin`/`unpin` subcommands write the committed manifest (a bare
`check` no longer touches it). The per-install
`.espalier/.freshness_state_cache.json` is deliberately NOT
protected — it is gitignored, regenerated on demand, and a
poisoned local cache only degrades the banner (consumers
already tolerate a bad cache).

The fragment-discovery surface is bounded by
`FRAGMENT_SURFACE_ALLOWLIST` + `FRAGMENT_SURFACE_DENYLIST` in
the scanner. `examples/`, `docs/external/`, `task-packs/`,
and `.espalier/` are explicitly denied; any new top-level
markdown file other than README / CHANGELOG / MEMORY / CLAUDE
is outside the surface by default and requires widening the
allowlist.

## Categorized memory + sharp-edges

`ESPALIER_MEMORY.md` is the *hot* surface — loaded into every session by
SessionStart, capped at 120 lines, autopruned. It carries the
load-bearing index of decisions, patterns, and recent session log.

`memory/` is the *cool* surface — categorized long-form entries that
don't need to be in the orientation prompt every session.

`docs/SHARP_EDGES.md` is the *footgun index* — its TOC is surfaced at
session start with recency annotations. `docs/sharp-edges/`
is the *cool* surface for long-form footgun docs.

The split has three consequences:

1. **Operators choose what's hot vs cool.** A pattern that's currently
   load-bearing lives in the index; one that's preserved for posterity
   lives in the folder. Either can move as load shifts.
2. **The index pays a cognitive cost; the folder doesn't.** Don't
   bloat the index with cold material. Don't hide hot material in
   the folder.
3. **The two folders have different temperatures from each other.**
   `memory/` is repo state; `docs/sharp-edges/` is failure-mode
   reference. Don't merge them.

### Renaming a heading in a recall-indexed catalog

A `## ` heading in `docs/SHARP_EDGES.md` (and a `### ` coinage in
`docs/FAILURE_MODES.md` §1) is three things at once: an anchor other text links
to, the title the pull-recall ranker scores a naming query against, and the
label the recall eval's hand-written arms quote. When the body reverses and the
heading must follow (DEF-779, 2026-09-12), rename the heading to what the code
does and keep the old text as the first body line in the form
`_(was: "<old heading>" — <when and why it changed>)_`. The old words stay
greppable and stay in the entry's body tokens, so a query phrased as the footgun
was filed still reaches the entry; the quoted labels in `tests/test_recall.py`
move with the title in the same commit (the corpus-source pin reds until they
do). Do not keep the old heading as a second `## ` line: two headings make two
corpus documents.

### Sub-doc convention

Every file in `memory/` or `docs/sharp-edges/`:

- Starts with an H1 matching the filename slug
- Declares `**Status:** active | historical | experimental | retired`
  in the first 10 lines
- Declares `**Linked from:**` pointing at the index row label (or
  `(unlinked)` for standalone notes)

The convention is enforced by
[`tests/test_categorized_memory_layout.py`](../tests/test_categorized_memory_layout.py).

## Folder CLAUDE.md routers

Claude Code's `CLAUDE.md` ladder injects subfolder `CLAUDE.md` files
when Claude touches files in those subtrees. Use this for
**path-keyed constraints** that any touch in the folder risks
tripping — constraints skills don't cover because they require a
trigger phrase the operator may not type.

### Template

Every router (≤20 lines, enforced by
`tests/test_folder_claude_md_routers.py`):

    # <folder>

    **Doing:** <one sentence — what code in this folder accomplishes>
    **Don't break:** <load-bearing invariant; the silent-violation risk>

    ## Before writing or editing in this folder:

    1. Read [`memory/<slug>.md`](memory/<slug>.md) — accumulated experience.
    2. <other procedural step — run a test, follow a parity rule>

    **Read first:** [`memory/<slug>.md`](memory/<slug>.md)

Template and example links carry the `<placeholder>` in the link
*target*, not only the display text. The reflect broken-link scan
skips a link only when its *target* is a placeholder
(`(memory/<slug>.md)`, a trailing-slash directory, or `...`); an
illustrative link whose target is a real-looking but non-existent path
is reported even if its display text contains `<…>`.

The `Before writing or editing` heading self-routes by mode:
reviewers reading files skim past mutation-only steps; mutators
follow them. `write_guard` and `plan_guard` remain the mechanical
gates (the router is instruction-layer, not hook-layer — see
SHARP_EDGES.md).

### Opt-in: `Depends on:`

A fifth field `**Depends on:**` is added per-folder when a task
genuinely warrants dependency disclosure (a godfile refactor,
multi-module surgery). Not in the default template — the discipline
is "narrow, load-bearing only."

### Stable router, fluid memory

The router rarely changes. The `memory/<slug>.md` it points to is
where accumulated experience lives and evolves. Upkeep cost stays
low because edits land at the fluid surface, not the injected
preamble.

### Discipline

- One router per folder where it's load-bearing — not every folder.
- ≤20 lines, enforced by test.
- No `TP-NN` pack identifiers in router bodies (visible to adopter
  Claude sessions that clone the harness).
- New routers are reviewer-eye work; the docs-maintainer agent
  does not author them autonomously.

## Canon annotations

Load-bearing claims in CLAUDE.md, docs/HOOK_ASSUMPTIONS.md,
docs/CONVENTIONS.md, and README.md carry two HTML comments
declaring where the claim is backed and by what slug. The
canon-vs-claim verifier
(`espalier/scanners/canon_verifier.py`) walks claims and asserts
the bidirectional slug match against tests carrying
`# pins: claim:<slug>` annotations.

**Shape:**

```markdown
<load-bearing claim line>
<!-- canon: <value> -->
<!-- claim-id: <slug> -->
```

**Allowed canon values:**

- `tests/<path>::<TestClass>` or `tests/<path>::<test_function>`
- `espalier/<module>.<symbol>`
- `docs/external/<file>`
- `convention` — explicit honest non-canon (use when the claim is
  a meta-statement about discipline, not a behavioral assertion)
- `dormant: <reason ≥12 chars>` — structurally prepared but unwired

**Where to place the annotation:**

- Standalone — two comment lines immediately following the claim
  text (HOOK_ASSUMPTIONS `**Backed by:**` blocks; CLAUDE.md
  numbered items).
- Inline — at the end of a table cell on the same line as the
  claim (CONVENTIONS scaffolding-canon table rows; markdown
  tables can't cleanly hold comments BETWEEN rows).

**Test side:**

```python
# pins: claim:<slug>
class TestX:
    ...
```

The verifier looks within ±10 lines of the class/function
declaration. Multi-pin caveat: one test can only be the canon for
one doc claim — when multiple claims need a witness, annotate the
strongest claim with the test and the others with `convention`.

**Surface registry:**

`CLAIM_SURFACES` is INLINED in the verifier (per
`TestScannerSelfContainment`). Adding a new claim surface
requires explicit registry update — the verifier flags
`UNREGISTERED_SURFACE` for any doc carrying canon syntax outside
the registry. Docs that mention the annotation syntax in PROSE
(typically inside fenced code blocks) without carrying real
annotations are exempted via `EXEMPT_PROSE_FILES` (cap 5).

**Enforcement gate:**

`tests/test_canon_verifier_contract.py`'s 7 enforcement tests run on
every pytest invocation; enforcement is default-ON. The
`enforcing_only` marker (`pytest.mark.skipif` keyed on
`ESPALIER_CANON_VERIFIER=enforce`) is retained as a debug escape-hatch
— re-add it to a single test to re-gate it. The legacy
`canon_verifier.is_enforcing()` helper that fed the old default-OFF gate
was removed in an earlier cleanup. The 2 unconditional tests
(smoke + stdlib-only) always run.

## Action-justification schema

The `CognitiveBlueprint.action_justifications: list[ActionJustification]`
field captures per-tool-call rationale as durable structured data.
This is the SoT for what fields the typed array carries and how
capture-time validation enforces shape.

### Fields

| Field             | Type   | Constraint                                     |
|-------------------|--------|------------------------------------------------|
| `goal`            | str    | non-empty, ≤500 chars after strip              |
| `step_rationale`  | str    | non-empty, ≤500 chars                          |
| `expected_outcome`| str    | non-empty, ≤500 chars                          |
| `not_doing`       | str    | non-empty, ≤500 chars                          |
| `tool`            | str    | in `MUTATION_TOOLS_TOKENS` OR `startswith("mcp__")` |
| `content_hash`    | str    | `^sha256:[a-f0-9]{64}$`                        |
| `timestamp`       | str    | ISO 8601; populated by recorder                |
| `session_id`      | str    | populated by recorder from the active blueprint |

### Where validation lives

- Library: `espalier.cognitive_blueprint._validate_action_justification`
  (imports `MUTATION_TOOLS_TOKENS` from `harness_config`).
- Hook-side: `tools/cc/cognitive_blueprint.py::_validate_action_justification`
  (zero espalier imports per the architecture rule; carries a
  duplicate `_AJ_MUTATION_TOOLS_TOKENS` tuple kept byte-equal to the
  library copy by `TestParity::test_hook_and_library_agree`).

Both reject the same inputs; both accept the same inputs. The parity
test walks a closed input matrix.

### No-new-hook policy

This schema does NOT add a hook script. The advisory surfaces
(planner trigger in `tools/cc/execution_plan.py::cmd_mark` and
post-write retroactive check in
`tools/cc/hooks/post_write_check.py::_check_action_justification_for_mutation`)
are non-blocking observational layers. `CANONICAL_HOOK_WIRING` stays
at 10 entries; pinned by
`tests/test_action_justifications.py::TestHookCountUnchanged`.

### Auto-compose from plan metadata

`execution_plan create` accepts `--goal STR` and `--not-doing STR`.
When both are populated, every subsequent `mark <i> running`
auto-composes the 6-field justification dict from plan-level
metadata + step description and records it via the existing
`cognitive_blueprint justify` subprocess. The composed `content_hash`
is `sha256:<sha256(task|index|description)>` — the `sha256:` prefix
is load-bearing (bare hex fails `_AJ_HASH_RE` and the validator
discards the record). The composed `tool` field defaults to `Bash`
(closed-set token; phase grain doesn't know the specific mutation
tool yet).

Both `--goal` AND `--not-doing` are required together: passing only
one short-circuits to None and the existing missing-justification
advisory fires. This prevents silently fabricating an audit-trail
field the author never wrote. Pinned by
`tests/test_execution_plan_auto_justification.py::TestComposeReturnsNoneWhenNotDoingAbsent`.

Precedence: explicit `--justification-fields` on `mark running`
always wins over auto-compose; a pre-populated
`step.action_justification` in the plan JSON also bypasses
auto-compose. Plans without `goal`/`not_doing`
keys fall through to advisory — backward compat is preserved.

### What this is NOT

- Not a fifth `--kind` enum value. Adding
  `kind="action_justification"` with a JSON-in-string
  payload would break `_sanitize_for_priming`'s `_MAX_FRAGMENT_LEN=200`
  truncation and skip typed validation. Pinned out by
  `TestNoJSONInDescription`.
- Not session-priming material. `auto_continuation_fragments`,
  `render_blueprint_md`, and `render_context_load` deliberately do
  NOT surface `action_justifications`. Tool-call grain is not
  session-priming grain.

## External-tool dependency contract

When the harness hard-requires a CLI tool (the lint gate, a security
scanner, etc.), the tool MUST be wired into three surfaces:

1. **`pyproject.toml [project.optional-dependencies].dev`** — so
   `pip install -e '.[dev]'` brings it in for local dev.
2. **`espalier/doctor.py::_LOAD_BEARING_EXTERNAL_TOOLS`** — so
   `espalier doctor` reports missing tools.
3. **`tools/cc/hooks/session_start.py::_SESSION_START_LOAD_BEARING_TOOLS`**
   — so an out-of-band install gap shows up at session boot rather
   than silently degrading the gate.

The triple is pinned by `tests/test_external_tool_contract.py`.
Adding a tool to `_LOAD_BEARING_EXTERNAL_TOOLS` without the dev-extras
+ SessionStart wiring fails the contract.

The two side lists (doctor / session_start) stay parallel-and-separate
because the SessionStart hook lives under `tools/cc/` and the harness's
zero-`espalier`-imports invariant forbids the hook from importing the
doctor registry directly. The contract enforces lock-step membership
in place of dynamic discovery.

Next-tool spike candidates:
`gitleaks`, `codespell`, `markdownlint`, `deptry`, `vulture`,
`interrogate`. Each follows the same triple.

Caveat: both banners (doctor + SessionStart) gate the *whole* tool loop
on self-host, because the sole current tool (ruff) is self-host-only. A
candidate adopters must be warned about (e.g. a secret scanner like
`gitleaks`) needs per-tool adopter-relevance gating added first — the
triple alone wires it into a loop that is silently suppressed for
adopters. The parity contract pins membership, not gating.


## Generative exemplar rail

The recall engine's generative face injects a canonical exemplar at
`UserPromptSubmit` (the `task_router` dispatch, on its existing plain-stdout
channel), BEFORE the model drafts a new artifact. Because an auto-injected
exemplar is only useful while it matches the *current* canonical shape, a
`ReinjectRule(face="generative")` may be `push_eligible=True` (auto-inject) ONLY
if a red-on-violation parity test re-derives it from its canonical source.

- **The rail is mechanical AND test-enforced.** `_reinject.check()` skips any
  `face=="generative"` rule with `push_eligible=False` (a pull-only row never
  fires even if mis-placed in `REINJECTS`). `tests/test_exemplar_parity.py`
  asserts `{pushed generative ids} ⊆ {parity-tested ids}` and proves the gate
  bites with an earn-the-gate red proof (a synthetic unpinned push rule must be
  flagged — so the live pass is non-vacuous).
- **Pull-only is the honest default.** Most canonical shapes (scanner contract,
  hook posture, pack skeleton) are cross-file abstractions with no single
  byte-source, so they cannot be parity-pinned. They live in
  `_reinject.EXEMPLAR_MAP` as `push_eligible=False` catalog entries, served by
  `/recall`, never auto-injected. Template-file sourcing was rejected
  (a template is a second copy that itself drifts).
- **A future push exemplar must** (a) ship a parity test, (b) intent-anchor its
  prompt predicate + a negative test (UserPromptSubmit fires on EVERY prompt — a
  bare keyword false-fires on meta-prompts that merely quote the trigger and
  trains the model to ignore the channel), and (c) account for the shared
  `REINJECT_SESSION_CAP` (a non-exempt generative fire consumes a session slot
  shared with the sync witnesses).


## A "decompose godfile" refactor into in-file helpers doesn't move the godfile metric

When a pack titles itself "decompose <godfile>" or "godfile de-dup", verify the
godfile scanner count actually moved before claiming a code-health win.
Extracting nested branch bodies into module-level helpers *within* the same file
improves per-function readability and nesting but does NOT reduce the file's LOC
— it often grows it (one `cli.py` "decompose" netted +104 LOC; `cli.py`
stayed the #1 godfile at 4514). To actually move the metric, extract into a NEW
module. Grade the campaign on the scanner that defines the metric, measured at
the base commit vs HEAD — see memory `measure-efficacy-not-just-correctness`.

## `surface_contract` protected-hook lists derive from `managed_inventory`

`surface_contract`'s `_PROTECTED_MUTATION_*` /
`_PROTECTED_INTEGRITY_*` lists hold only the NON-hook literals and append
`_hook_protected_files()`, which lazy-imports
`managed_inventory.get_hook_entry_files()` + `get_hook_helper_files()`. So the
hook portion of the protected/integrity sets is DERIVED, not hand-listed:
registering a new hook helper in `managed_inventory._HOOK_HELPERS` flows into
both protected lists automatically — no `surface_contract` edit. (`_integrity.py`
`MANIFEST_FILES` is still a hand-mirror — the zero-espalier-import rule forbids
it from calling `managed_inventory`; `test_integrity_contract_parity` pins it
equal to `get_protected_integrity_paths()`.) The deployed-helper count is still
a multi-surface SoT (~12 witnesses) — see SHARP_EDGES "A new pattern-detector
trips the harness's own defenses."

## Comment text must not pattern-match a tooling directive

A prose comment whose leading token is `noqa`, `type:`, `pragma:`, etc. is
parsed by the tool as a real directive — a `# noqa-text drift` note gets
treated by ruff as a `# noqa`. Phrase such comments so the directive
token is not at the front (`# (note on noqa drift)` rather than `# noqa-text
drift`).


## Architecture rules

### File-path loaders are not package imports

`espalier/_integrity_bridge.py` and `espalier/recovery.py` use
`importlib.util.spec_from_file_location(...)` to load standalone helper
scripts from `tools/cc/` (e.g., `_integrity.py`, `session_resume.py`) by
absolute path. These are NOT package imports — the script files are read
from disk and given a synthetic module spec. When the source sibling is
absent (a wheel install), the load falls back to the byte-mirrored
`espalier/_vendor/cc/` copy, then raises `FileNotFoundError` if neither
resolves.

The espalier → tools/cc isolation rule (Rule 1 in CLAUDE.md) means
`tools/cc/` scripts have zero `from espalier import ...` lines. The
inverse — espalier loading a tools/cc script by file path — is fine
and intended: it lets the harness's engine consume its own
standalone tooling without recursive imports.

Pinned at:

- `espalier/_integrity_bridge.py::load_integrity_module` — file-path load of
  `tools/cc/hooks/_integrity.py` via `importlib.util.spec_from_file_location`,
  falling back to the `espalier/_vendor/cc/` wheel copy when the source
  sibling is absent (`candidate.exists()` check); raises `FileNotFoundError`
  if neither resolves.
- `espalier/recovery.py::_load_session_resume` — the same pattern for
  `tools/cc/session_resume.py`: a `spec_from_file_location` load with a
  `_vendor/cc/` wheel fallback and a `FileNotFoundError` guard.

**A file-path-loaded module can be OLDER than the engine that loads it.** The
bytes come off the adopter's disk, and an engine upgrade moves the package
without redeploying those scripts — only the deploy verbs do — so any **new**
attribute the engine reads off one of these modules needs a backfill in the
same commit. `_integrity_bridge` backfills the canonical-text helper and the
protocol-mismatch predicate onto a pre-canon module for exactly this reason,
and both review passes drove the crash that arrives without it (an older
checkout of `tools/` raising `AttributeError` mid-deploy). Where a constant read
across that seam is a value the two copies must agree on, the writer follows
the reader: read the deployed copy's constant statically and write what it can
read, and send the remedy to the redeploy rather than to a refresh that
rewrites the same file.

Both call sites self-document this exception in a header comment.
Future architectural reviewers should treat any
`importlib.util.spec_from_file_location` call inside an
`espalier/*.py` module as compliant with Rule 1, not a violation.
