### Fixed

- **A process table or checkout list that could not be read says so,
  instead of reading as empty.** On a loaded box a `ps` killed at its time
  cap read as a host with no processes. The kill speed bump then let a
  `pkill -P` and a kill of a pid it could not climb to its owner through
  with no word, which is the case where another checkout's test run gets
  ended, and the session-placement notes (the catch-up, the reaper, the
  board's seats read, the own-clear) said the session registry does not
  list this session when the real cause was the table. The speed bump now
  asks once when it cannot tell whose run a live pid is, a reading that
  places the pid in another checkout still names that checkout, and the
  notes say the process table could not be read. A killed `git worktree
  list` no longer makes the occupancy check ask it twice or skip the main
  checkout's session markers.
