### Changed

- **`upgrade`, `init`, `install-ci` and `fingerprint` exit 2 where they used
  to write.** Automation that runs them sees a non-zero exit in two states
  that exited 0 before: `upgrade --execute` on a tree with no saved plan, and
  any of the four over a deployment stamped by a newer release (the
  `upgrade` and `init` dry runs included). The reasons are under Fixed.

### Fixed

- **`upgrade` and `init` no longer roll back, break or hide what they
  overwrite on an adopter tree.**
  - **A clone:** `upgrade --execute` refuses (exit 2) when the saved plan
    (`reports/harness_config.json`, gitignored, so absent on every clone) is
    missing or unreadable, and names the command that rebuilds it: `init .`,
    or `init . --wire-hooks` where a `.claude/settings.json` is already
    present, so the new hook events are merged as `--execute` would. It used
    to re-render `cc/COMMANDS.md` and `cc/LIVE_SURFACE.md` from an empty
    action table and leave `doctor` failing. The dry run reports what
    differs and what that command would replace, sets the two plan-reading
    docs aside as not compared, and previews no stage the execute refuses.
  - **A newer deployment:** when `cc/PACK_MANIFEST.txt` stamps a later release
    than the running engine, `upgrade`, `init`, `install-ci` and `fingerprint`
    refuse before any write and name the files they would roll back. A stamp
    that does not parse as `X.Y.Z[aN|bN|rcN]` never refuses, and deleting the
    stamp line is the way past for a rollback chosen on purpose. Two builds of
    one pre-release string still compare equal.
  - **Every overwritten file is named:** the version-current preview, the
    version-bump preview (which printed one generic sentence), the
    `--execute` report and `init --dry-run` list every file they replace,
    where they stopped at ten or listed none, and the same line says that a
    marked file you edited is replaced and that dropping its managed marker
    line keeps it. The five agent bodies with an `Adapting me` section say so
    too.
  - **An older saved fingerprint:** a key a later release retired no longer
    makes `upgrade` call `reports/repo_fingerprint.json` absent or
    unreadable; the fields it declares are compared, the retired keys are
    named, and `--execute` re-baselines the file once.
- **`refresh-externals --help`** describes `--apply` and `--interactive` as
  they behave since the quote check: candidates and prompts only for pins
  whose quoted passages moved.
